# 页面设计和复审记录

每页在 `docs/design/ui-reviews/` 建立小型记录，文件命名 `<page>-v<version>.md`。尚未画图时不创建虚假评审记录。可用下列字段，内容随实际证据填写。

## 设计卡

- 页面／状态／用户任务／对应模块规则。
- 已确认结构：实际参考文件及版本；缺失图和文字更新。
- 本页视觉观点：一句话说明希望用户首先注意什么。
- 字体：实际家族及fallback、中文覆盖、标题／正文／元信息字号与行高。
- 色彩：背景、表面、主文字、次文字、强调、语义状态；本页候选或已确认，不能假写全局定稿。
- 间距／对齐／圆角角色；键盘和安全区策略。
- 参考借鉴点、弃用的技能建议及原因，最多写影响决策的几条。

## 画面检查

记录具体位置和用户影响，不给虚构的“审美95分”。

| 维度 | 检查问题 |
|---|---|
| 内容 | 真实中文长标题、长昵称、短文／长文能否成立？有没有图外说明混入App文案？ |
| 层级 | 第一眼看到的是内容或下一动作？作者身份有没有抢正文？所有卡片是否无区别？ |
| 排版 | 左右对齐线、行距、孤行、数字与中文基线、图标光学重心是否一致？ |
| 色彩 | 强调是否只服务动作／选中／状态？灰字是否难读？是否仅小图标换色却宣称整套试色？ |
| 操作 | 完整产品图稿与代码启用范围是否分别登记？有没有把图中按钮冒称为已实现，或因代码切片删去用户要求的设计？有无重复确认、无意义标签？操作与文案结果是否一致？ |
| 匿名 | 公共身份是否独立？是否出现本体／共同编号？删除／关闭是否沿用旧昵称？ |
| 状态 | 加载／空／错误／未知／失败区别明确？取消是否冒称成功？保存失败能否保留内容？ |
| 适配 | 402×874基准外，小屏、大字、键盘时哪些结构需要换行或滚动？ |
| 风格 | 有无无理由渐变、发光、纹理、玻璃、每行卡片、夸张标题或营销语？删一处装饰后是否更清楚？ |

## 证据与定稿

- PNG路径、尺寸、实际已查看版本、已修复问题、仍待验项。
- 对比度如有记录，写实际前景／合成背景及测量值；未测写NOT_RUN，不凭肉眼填PASS。
- 用户确认原话和日期；仅确认页面／颜色／业务分别记录。
- Flutter映射：使用的token／组件、行为测试入口。图稿与实现分别登记。
- 真机：48dp触控、键盘、大字、读屏、位置恢复等实际结果；没有证据仍NOT_RUN。

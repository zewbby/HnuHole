# HnuHole 手机 UI 设计

项目根由当前工作树定位，不写死机器路径。先读根目录 `AGENTS.md`、`docs/design/HANDOFF.md`、当次计划与对应 `docs/design/modules/`。读取并查看实际图像；缺图不能说已查看，历史图与正式图分别记录。

完整流程在根目录 [docs/design/ui-quality-workflow.md](../../../docs/design/ui-quality-workflow.md)。页面决策／状态／视觉检查使用 [review-sheet.md](references/review-sheet.md)。遵守本次用户授权，既有产品规则优先于第三方技能；不为画面增加功能、改变身份绑定或把未知结果画成失败。

## 设计与交付

1. 定义本页用户任务、必须保留的内容、当前状态和返回路径。沿用已定需求，不重复访谈；业务歧义才询问。
2. 查看参考：页面结构优先已确认图；记录成熟产品的借鉴点，按用户指定参考执行，保留本项目通道与功能语义。2026-10-08用户明确要求贴近其小红书页面；不能用技能风格偏好拒绝这一方向。无需每页泛搜趋势。
3. 内部形成短设计卡：一个视觉重点；4–6个命名色；中文字体／字重／行高；间距与圆角角色；布局草图。用户不需要先审批prompt或文字方案。
4. 自主生成当前页面／当前状态PNG，默认逐张；用户明确要求一组多状态一起出图时按指定批次执行。生成或编辑位图时读取并使用可用imagegen技能与工具；精确几何校准／Flutter实现验证用真实渲染截图，不能拿生成图证明实现。保留版本，未经确认不覆盖正式稿。
5. 查看实际输出，批量检查并修复：读屏顺序、对齐、中文换行、信息噪声、触控入口、身份语义、错误／未知状态。一次集中修正后复看，不无期限微调；证据不足时标待验。
6. 展示图，简述最关键设计和未验边界；让用户针对画面反馈。2026-10-09用户明确“我没给意见就是定稿了”：在后续回复中推进下一批时，对已展示且未被提修改意见的页面按此授权定稿；被指出问题的页面继续修正。不因等待时间或刚生成就直接定稿。登记具体版本、范围及决定，并直接推进用户指定下一张／下一类。颜色仅本页确认，不自动变成全局主题。

## HnuHole 的质感

配色按用户最新页面指令，不把历史黑底或浅色参考锁成全局主题。2026-10-08用户明确“定稿这三个”，通道正常／空／首次失败的v9三图为正式稿，保存在`UI产品图/`；白色框架及本组暗灰蓝配色已确认，v7林绿／炭黑和v8整页暗蓝废弃。不要擅自改动这组；下一页可沿用为连贯候选，但不把本组确认推定为最终全局主题。用可辨的表面层级与协调状态色表达，避免多块彩色争抢；“栖息感”不能推导为未经要求的森林画面或全局暗色主题。中文字体用实际可用且覆盖中文的家族，优先清晰的系统中文无衬线；不机械套英文展示字体，不为“区别AI”牺牲阅读。

用字重、行距、列表节奏和有限分隔建立层级，不把每行都放进同尺寸圆角卡片。圆角、阴影、描边按控件职责确定；质感不要求颗粒、玻璃、霓虹、星空或装饰树枝。每个装饰必须能说明用户收益，否则移除。允许一处有辨识度的细节，周围保持安静。

真实状态优先美观：处理中／结果未知／明确失败分开；草稿与已受理任务不混称；公开作者不带本体、账号编号或其他身份关系。完整产品图稿与当前代码切片分别登记：用户要求图稿展示图片、点赞数、通道名、搜索、筛选和底栏，不能因为代码仅做文字片就删掉这些区域。未实现功能不冒称已可用，代码启用范围按当次任务单处理。布局已确认时只修改用户要求的颜色，不重新排版或自动转入下一类。

2026-10-09用户调整：确认发布直接回原通道，发布中／失败放在我的卡片中，明确失败用草稿标签与亮红叹号保留内容。随后用户附四图明确“定稿这几张”，见项目四图定稿记录：成功提示选暗蓝通道款，本人发布中与失败选附件中的错落双列混排，失败编辑同样定稿。具体文件选择优先于此前通用对齐或黑色提示候选，按附件原字节归档，不能自行改为未选中的网格版本。正常网格F1-11仍单列候选，不因此重画通道feed或批准全局主题；独立状态整页仍被替代。失败草稿保留原身份、通道和失败尝试，未知结果不画成可重发普通草稿。用户定稿后同轮同步记录并继续下一张，新生成图先展示。

PNG只能证明静态画面。真实触控48dp／44pt、键盘、大字、读屏、安全区、返回位置、原生持久化与授权须在实现和设备验收中单列。不能靠一张漂亮图宣布通过。

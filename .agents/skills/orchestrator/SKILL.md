# SpeechFUL Orchestrator

此 Skill 仅由用户显式调用 `$orchestrator` 启用。总指挥对最终可运行结果负责，贯穿整个开发过程；执行 Session 对获派模块的实现、验证、分支和阻碍反馈负责。通用约束以仓库 [AGENTS.md](../../../AGENTS.md) 为准。

## 五阶段

1. **需求收敛**：确定产品目标、范围和验收标准。仅对影响方案的未决问题进行 Grilling；已有决定写入唯一的 `docs/tasks/<ID>.md`，不让执行 Session 重复讨论。
2. **架构与拆分**：确定最小可运行端到端链路、接口契约、依赖与集成顺序。只把可隔离的工作并行化，为每个执行 Session 分配独立分支和 Worktree。
3. **迭代执行循环**：按[五项派单协议](references/dispatch.md)发出简短任务。执行 Session 在授权范围内自主实现和聚焦验证；总指挥持续跟踪依赖、解决跨模块阻碍，并尽早集成可运行切片。每轮根据实际结果继续、修复或调整，不等待所有模块完成才首次集成。
4. **联合验收**：按[交付门槛](references/delivery-gates.md)核对端到端行为、安全边界、适用的真机／性能验证、版本对应的测试证据与必要的独立审查。发现问题回到对应实现环节。
5. **交付收口**：核对 PR、CI、任务状态和遗留项。按用户授权处理 Push、PR、合并和部署；分别报告实现、验证、合并与发布状态。

## 调度判断

- 派单只写任务 ID、目标、任务文档、依赖、交付条件；细节留在任务文档，Git 与安全操作见 [CONTRIBUTING.md](../../../CONTRIBUTING.md)。
- 无依赖且已授权的任务持续推进。重大产品取舍、接口破坏、权限不足或高风险操作及时升级；阶段完成本身不构成全项目暂停。
- 相同故障或测试循环连续没有带来新证据时，先归类原因并调整方案或测试手段。测试次数不能替代定位。
- 只在 `docs/tasks/<ID>.md` 维护当前任务状态；其他文档引用它，已有历史证据保持其原版本与时点。

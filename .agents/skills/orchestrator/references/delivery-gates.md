# 指挥模式交付门槛

总指挥按风险和改动范围使用这些检查点；具体 Git、安全和测试规则仍以 [AGENTS.md](../../../../AGENTS.md) 与 [CONTRIBUTING.md](../../../../CONTRIBUTING.md) 为准。

| 检查点 | 要核对的证据 | 未满足时 |
| --- | --- | --- |
| 最小链路 | 真实入口、跨模块接口和可运行结果已连通 | 优先补齐链路，再扩展旁支 |
| 增量集成 | 上游契约、依赖顺序、隔离分支与合入差异清楚 | 回到对应模块修复或调整顺序 |
| 联合验收 | 对当前提交的端到端测试、必要的安全／设备／性能检查及独立审查 | 记录 `FAIL`／`BLOCKED`／`NOT_RUN`，修复并聚焦复验 |
| PR 与 CI | PR head、适用产品 CI、审查和遗留项对应当前版本 | 保持待验或 draft；不拼接旧版本结果 |
| 合并与发布 | 明确授权、主线状态、发布环境与资源依赖已核实 | 保留真实状态，等待所需决策或条件 |

任务文档区分实现完成、验证通过、PR 合并和正式发布。AI 独立审查仅是审查证据，GitHub 成员批准按仓库规则另行满足。清理测试资源前核对后续执行 Session 的依赖。

## 1. 目标与明确边界

交付一条实际手机 App 可操作、服务端权威、可以核对未知结果的文字闭环：登录后进入通道 → 编辑标题和正文 → 发布确认及选择有效身份 → 服务端原子受理、固定帖内身份 → 后台公开 → 最新列表 → 正文详情。中途退出、丢响应或进程重启后，原账号能恢复草稿或核对原发布任务，不重复发表、不换身份。

用户于本轮明确选择文字闭环范围，包含同机草稿、发布任务核对及“我的／自己的帖子”必要入口。图片、自定义标签交互、评论、点赞收藏、搜索、私信、推送、热榜、完整治理后台和作者编辑留后续；本片完成不等于完整 B03/B05/B06/B10 或首版产品完成。可选标签字段暂为空，后续不能借此更改一帖单通道规则。

必要生命周期属于本片：身份改名后的当前资料投影、身份删除／正式注销后的独立占位、未公开任务停止、普通草稿与已提交任务的分隔，以及作者删除自己文字帖的最小能力。作者删除用于落实 MASK-ARCHIVE-01 的“旧帖从我的移除，但从其他入口仍可删”；不开展编辑、审核或举报工作台。

## 5. 产品流程与状态约束

### 5.1 通道、编辑和草稿

- 点击通道真正进入所属通道的“最新”列表；没有跨分类广场。标题卡片不显示正文摘要；评论模块未实现时不放可点击的假评论控件或伪造计数。
- 固定加号始终新建，不覆盖旧草稿；编辑页标题在上、正文在下，下一步进入确认页。正文在文字片必须含非空白内容，不能只发标题；文字保留及计数按 Q1 固定。
- 无身份仍能读帖；在需要公开发送时引导现有身份设置。取消设置不发送；成功后回原步骤，保留输入，不自动发表。默认身份遵循 MASK-DEFAULT-01，不拿消息收件身份替代。
- 内容存在时退出正常自动保存；保存失败留编辑页，提供重试、复制文字、明确放弃。空白新稿不新增草稿；空白的定义在 T1 与内容校验口径一并固定。
- “我的／自己的帖子”包含本片正式帖、草稿、处理中和失败项，不新建独立草稿箱。发布成功由同一逻辑项目转正式帖，不残留重复草稿。草稿可恢复／经确认删除；原身份失效时保留文字、要求重选。

### 5.2 受理、公开、未知结果和取消

- 点击确认立即返回通道；先持久保存原操作上下文，再发送请求。草稿、操作标识、候选身份及提交内容在存储失败时不能被伪装成已持久。
- 受理最终事务必须原子产生固定帖子身份、不可修改的受理内容、发布任务和命令结果。内容／权限校验拒绝且未形成任务时不绑定。
- `UNKNOWN` 是客户端不知道原操作结果，不是服务端发布失败。核对原命令，不因超时新建帖子、不换身份，不重放不可重复证明。
- 服务端状态与客户端展示状态分开：任务 `ACCEPTED → PUBLISHED / FAILED / CANCELLED`；未受理的终态拒绝另记命令结果。原命令查无为 `UNKNOWN_NOT_OBSERVED`，封印为 `NOT_ACCEPTED`；具体响应以post-api为准。
- 受理与公开分为独立权威步骤，即使文字没有图片也保留可验证的取消／权限竞争边界。worker 在公开最终事务复核 Gate、账号限制、关闭状态和发送身份；失败不能绕过限制。
- 已受理任务不因主动退出、接替或密码重设自动取消；重登录原账号才能恢复本人查询。申请注销、禁言／封禁及身份删除停止尚未公开任务。竞争按服务端最终提交顺序裁决，迟到响应不能推翻终态。
- 用户取消需核对服务端结果：取消先完成则不公开且不生成失败卡；公开先完成则保留成功事实。客户端点了取消不等于已取消。
- 明确失败后可编辑文字重试，但原身份与通道固定。重试建立新的不可变尝试和新命令标识，关联原任务及既有帖内绑定；不以同一命令换 payload、不把失败任务改成可换身份的草稿。详情规则和失败项目位置在 T1 固定。
- 结果查询的不存在／未知／终态必须能安全区分；可查原结果的保留策略、命令标识摘要和清理时点在 T1 固定，不能在版本重启后因查无记录就擅自另发。

### 5.3 阅读、资料变化与清理

- 只有已公开且对当前会话可见的内容进入列表和详情；本人未公开内容只通过本人任务接口读取。列表最新排序用发布时间和稳定 tie-break，游标禁止跨通道／作用域误用。
- 后续翻页不能插入新帖挤动当前浏览位置；成功发帖进入列表顶部但不强拉用户回顶部；详情返回保留列表锚点。分页一致性及失效锚点策略在 T1 明确。
- 对外资料读当前权威身份生命周期，改名后更新，不缓存原昵称冒充删除投影。删除／正式关闭调用既有独立投影，不返回内部账号或共同关闭时间。
- 删除身份后的旧帖继续公开，但从“我的”移除；原作者从通道打开仍有最小删除权限，没有编辑权限。正式关闭前不提前显示注销；关闭后旧内容按规格保留及独立占位。
- 删除作者自己的帖子停止其公开可见性，读旧详情或旧游标不能泄露删除正文；不新增回收站、编辑历史或恢复接口。举报证据、评论等未来消费者另外实现。
- 正式关闭获权威终态后清理本片旧账号本地数据；401／临时冻结／普通退出不能等同于注销而删除草稿。新账号不得继承旧草稿、任务或帖内身份。

## 6. 领域模型、接口与源码落点（T1契约／T2服务端）

| 模型 | 权威边界／要求 |
|---|---|
| 帖子 | 独立不透明 postId，单通道，内容版本、公开状态与发布时间；owner 仅内部 |
| 帖内身份绑定 | 内部账号＋帖子唯一；受理时建立；成功／失败／删身份均不解除绑定 |
| 发布任务／尝试 | 私有归属、固定身份和通道，不可变尝试内容、状态和原结果；可核对且无重复公开 |
| 命令回执 | 命令标识绑定请求摘要和归属；同标识不同 payload 拒绝；终态和重试权限不能混用 |
| 本机草稿 | 按环境＋账号隔离；持久文字和编辑上下文；与已受理任务区别清楚 |
| 公共身份投影 | 活动资料或身份级独立占位；与本人管理 DTO 完全分开 |

T1产出OpenAPI和事务／状态表，共14个操作：创建发布命令、原结果核对及封印、本人任务列表／详情／取消／失败重试／隐藏、通道feed、帖子详情、本人帖子列表、本人删除权能、作者删除与权威默认身份context。T2已实现handler／最终Gate事务／worker、迁移0013及精确受限权限，实际范围见T2报告；T3本会话已实现Flutter客户端路径，精确分层证据见T3报告，实际C/V到完整App待T4。

本地沿用Drift/SQLite业务持久化，不把正文、所有草稿和发送队列塞进认证AuthStore单一文档。SQLite不存Bearer／密码／恢复码；任务环境与账号归属必须准确。T3固定Drift2.35.2／sqlite3 Dart3.7.0／characters1.4.1，实现独立原生vault namespace、认证加密payload和noBackup路径；Linux实盘结果不代证手机原生备份。共享auth workflow codec新增可选的私有originalAccountId，正式闭号原账号清理有持久重试标识；native认证read/write原语义保持，当前设备共享回归重新打开。

服务端已新增 `services/api/internal/posts/`、posts HTTP／authprivacy业务边界、SQL迁移0013及对应测试，更新runtime／worker／入口／权限；完整源码与测试落点见T2报告。T3实际源码为 `apps/mobile/lib/src/posts/`、`src/storage/`、`main.dart`及`packages/auth_vault/`业务边界，对应 `apps/mobile/test/post_*_test.dart`；实现、实际测试和平台NOT_RUN分别登记，不据此冒称完整App或生产通过。

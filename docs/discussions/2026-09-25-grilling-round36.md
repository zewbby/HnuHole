# 第三十六轮：匿名凭证生命周期与强隐私边界（已回答）

状态：2026-09-25。继续认证隐私 grilling。本轮在回读账号、管理、ADR 与既往讨论档案后记录用户答复；后续提问必须先按当前模块规则排重。

## 用户答复

1. 稳定匿名凭证生命周期按推荐：每次完成邮箱验证后，通过隐私协议重新取得同一稳定匿名标识；账号恢复不依赖旧设备长期保存凭证。
2. 用户纠正重复问题：既有设计已经明确“封禁期间不可注销”。后续 grilling 必须先读取当前分支对应模块设计与历史讨论并排重，不得把已确认规则重新提问。
3. 强隐私边界选择 A：生产继续要求邮箱验证方与社区服务方由不同组织或法律主体控制；不能用同一组织内权限隔离替代这一承诺。

## 已确认并澄清

- 换机、卸载或清除本地数据后，用户仍以校园邮箱验证码作为唯一登录凭证；重新验证同一邮箱后，隐私协议应重新取得同一稳定匿名标识并恢复原有效账号。
- 客户端可以持有一次认证所需的临时协议状态，但长期账号恢复不能依赖设备中保存另一份“恢复秘密”。
- 封禁仍生效时禁止申请注销；七天注销缓冲期内新受到封禁会取消本次注销申请。不得再把“封禁后注销再注册”作为正常业务场景。
- 生产隐私目标保持“任何单一主体不能取得具体邮箱与具体社区账号的对应关系”；两个独立主体主动串通仍不在保证范围内。

## Grilling 约束

后续提出认证、账号、处罚或注销问题前，必须先读取当前分支的对应模块文档、ADR 和既往 grilling 档案。模块文档中的已确认规则优先于历史档案里的旧“待确认”文字；历史档案只作为来源和决策过程，不得仅凭旧待办重新发问。

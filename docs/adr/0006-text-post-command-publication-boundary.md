# ADR 0006：文字发布的命令回执、公开事务与停止代次

原决策日期：2026-10-08；维护说明更新：2026-10-18。状态：已由后续主线实现沿用。
[原始 ADR](../archive/community-text-posting-20261008/original/docs/adr/0006-text-post-command-publication-boundary.md)
按原始字节归档；其中“实施与动态验收未运行”仅描述当时设计阶段。

## 决策理由

CREATE 超时后的查无不能证明没提交，迟到请求仍可能公开。仅检查当前账号状态会使撤销注销或处罚到期后的旧任务复活；
只依赖会话代次又会让正常退出和换机错误取消已受理任务。

采用账号域的不可变命令回执、独立任务尝试和两次最终 C 事务：受理时固定身份／任务／原结果，
公开时由 worker 重新检查 Gate、权限和停止代次后提交公开事实。seal 只封印尚未受理的原命令；
已受理任务另行 cancel。合法 retry 创建新尝试，保持身份和通道。

发布停止代次与会话代次分离：注销申请、处罚等停止事件使旧尝试永久停止，正常退出、换机和重设凭据不取消已受理任务。

## 代价与后续演进

需要命令／任务／尝试表、封印操作、worker、生命周期 hooks 和防重执行墓碑。
主线后续接入图片清单和受保护字节上传，保留文字摘要兼容、固定归属和全部验证后公开的要求。
不采用“查无就另发”“旧会话失效就取消”或“只检查当前处罚”的简化方式。

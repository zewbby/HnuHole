## 功能要求

1. 在帖子信息流／详情提供转帖与取消转帖操作。普通转帖引用原帖，保留原作者、正文和图片，不复制生成一篇冒充本人创作的新帖；本次不增加引用评论式转帖。
2. 转帖成功后，“我的 → 转帖”应能读取当前所选身份实际转发过的帖子，默认按转帖时间倒序，支持分页、刷新、进入原帖详情和取消转帖。
3. 复制链接或系统分享不要自动算作转帖；不要将收藏冒充转帖。连续点击、重试、响应丢失、并发取消不能重复计数或恢复已取消状态。
4. 实现服务端持久化、读取与取消接口，不能仅使用前端数组或本机缓存。接口风格和授权方式沿用项目已有帖子互动契约，优先独立文件，尽量减小与页面分支的共享改动。
5. 延续现有匿名身份和权限边界：私人归档只对本人开放，公共返回不泄露账号ID、跨身份关联或私人历史；已删／隐藏／无权访问的原帖按项目已有规则处理。
6. 首页、详情和个人转帖列表状态一致；身份切换、账号切换、退出、会话失效后，旧请求和旧页面不得影响新身份或新账号。显示真实结果，保存失败或结果未确认时不能伪装成功。
7. 转帖归属已明确：按发言身份区分（帖子、回复同样如此）；喜欢和收藏是同一账号多身份共享。列表查询必须校验身份属于当前账号，游标与缓存绑定身份，切换时防止旧请求串入。仅“转帖是否公开进入别人信息流”仍需结合既有规则确认；不要自行扩大为公开个人主页。

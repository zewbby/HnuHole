# 通知收件箱、全局身份与五项导航

任务 `NOTIFICATION-INBOX-01`；分支 `feat/notification-inbox`，基线 `origin/main@c17a667`。用户于 2026-10-27 明确授权完成后 commit／push／PR／merge，并构建最新主线产品。当前实现范围以本节为准，早期五分类／真实提及方案已撤回。

- 通知页为“全部／回复／收到的赞／系统通知”四等宽分类，每项25%，字号14、未选缩放0.94、选中1.08，点击和内容／分类栏横滑平滑切换。字体和深浅色来自现有 App。
- 真实 `@` 选择、结构化提交字段、提及目标接口及提及事件生产均不进入正式代码。原评论编辑器、协议、加密 journal 与 V1 金样保持主线原样；前期草稿仅在外部本机目录归档。普通正文可以包含字符 `@`，不会生成提及通知。
- 私信、通知、个人页及新发帖选择共用当前账号的一份身份状态。任一入口切换，其余已打开页面立即同步并丢弃旧身份迟到响应；身份删除回退有效身份，会话／账号变化清空，管理页暂时关闭不丢选择。已受理任务、已有帖内绑定与现有会话的归属保持原事实。
- 四个主模块始终保留统一五项底栏：首页／通知／＋发帖／私信／我的。只有首页下滑进入沉浸阅读时隐藏，反向阅读／离开首页恢复；其他模块的＋调用同一真实发帖流程。
- 回复与匿名点赞按收件身份，系统通知在本人账号各身份下共享。保留取消赞重算、按所见版本已读、目标删除后无旧正文、最终 C Gate 和资源归属校验。

后端新增三个接口：`GET /api/v1/notifications`、`GET /api/v1/notifications/unread-counts`、`POST /api/v1/notifications/{id}/read`。迁移 `0028_notification_inbox.sql` 只新增私有收件事实与生产触发器，不修改评论尝试内容，不回填历史互动；旧系统通知与受限治理入口兼容。

状态与最终命令见[测试交接](../design/notification-inbox-test-handoff.md)、[机器记录](../design/notification-inbox-verification-20261026.json)。旧模块整体裁决不因本任务局部通过而提升。正式发布身份／公开域名另行配置；现有手机联调仍使用原签名与既有同机开发服务，不把 Profile 构建称为生产上线。

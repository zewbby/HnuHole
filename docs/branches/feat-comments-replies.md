## 目标与本次包含

交付 Android 帖子内实际可用的评论／楼中楼链路，复用现有 C 授权、固定帖内身份和图片能力。
所属模块 B07，关联 B02／B06／B08／B11；不以本任务完成代替这些整模块通过。

1. 评论领域、迁移、最小权限、API、Go实现和 Flutter 页面，包含主评论、回复具体内容、列表与目标定位、本人删除。
2. 同账号同帖固定身份，楼主标识按实际发言身份；首次公开发送前的身份设置／选择保留原输入。
   不把不同面具关联公开，也不允许重试更换身份、通道或回复对象。
3. 沿用已确认展示规则：主评论前十按赞、其余按时间；楼中楼前五按赞、其余按时间，手动展开／收起；
   同赞按既定时间规则，阅读期间不自动重排。为这些规则实现评论自身必要的幂等点赞与计数，不扩展为帖子赞藏模块。
4. 主评论／回复最多一张图，可纯图发送；复用图片原格式／受保护读取的能力，按评论生命周期增加资源适配，
   不能直接套用“帖子最多九图”或绕过资源归属。图片失败保留文字和原目标。
5. 接受任务、结果未知核对、明确失败后重试、App重开恢复及临时输入清理遵守评论模块。
   评论没有独立长期草稿列表；不复用帖子草稿产品行为。成功发送定位本人内容；目标删除时按既定规则处理。
6. 本人删除主评论移除整楼，删除楼中楼仅移除本条且保留别人的回复关系；帖子删除关闭讨论。
   申请注销／处罚／删身份及清理继续通过最终 C 事务，覆盖并发和迟到结果。
7. 配套产品CI、真实SQL、HTTP、Flutter和受影响原生／Android构建；设备窗口可用后补真机，不把替身测试记成实测。

## 系统通知依赖与交付顺序

任务2 `codex/feat/report-moderation` 负责系统通知最小列表／详情／已读／路由，以及举报和处罚结果通知。
本任务拥有评论发送任务的权威状态、原身份／原目标／保留内容及重试／放弃动作；任务2拥有统一失败入口展示。
先对齐已提交的接口契约：任务ID、身份归属、目标引用、当前状态、允许动作和解决后移除条件。
公开内容DTO不携带内部账号关联；账号级与身份级通知由任务2隔离。
可先用清楚标识的测试适配器验证边界；未实际接入系统通知前不得将 COMMENT-FAIL-ENTRY-01／B07 整体标为PASS。
对方契约尚未可用时继续完成自身后端／页面／测试，并在PR列出具体依赖，不重复开发另一套通知中心。

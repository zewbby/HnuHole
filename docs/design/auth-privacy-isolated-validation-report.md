## 2. 本轮实现

| 边界 | 实际交付 |
| --- | --- |
| 协议 | 固定消息与规范编码、用途／环境／撤销钥配置、公钥散列槽位、bootstrap PoP、资格时间窗、严格 Pure Ed25519 包装器 |
| C 原子开户 | 锁后验资格、挑战与恢复码确认；账号、恢复摘要、初始会话和无秘密结果同事务创建；原键重试不返回会话秘密 |
| C 槽位生命周期 | 开户和退役共用槽位锁；永久终态、账号脱钩、待签 outbox 和单调 ACK 约束 |
| V 配额 | 精确字节邮箱唯一占用、未开户退役待办、收据和清旧配额同事务处理；重复旧收据不清新配额 |
| 提交后签名／ACK | HSM 调用在 SQL 事务外；签名回调比较原消息及版本；V 持久处理后才 ACK，C 本地持久确认后才开始清理 |
| 实验环境 | 新建 PostgreSQL 集群，只用私有 Unix socket；两个非超级用户角色和数据库，停止后自动删除本次集群 |

实现位于 `services/api/internal/authprivacy`；实验 SQL 在 `services/api/authlab/migrations`。现有 `0001_sessions.sql`、`0002_channels.sql`、目录路由及演示会话验证器没有改变。

## 3. 实际运行结果

工具：**Go 1.27.1 / darwin arm64、PostgreSQL 18.6**。项目模块最低版本保持 Go 1.22；本轮没有在 Go 1.22 或 PostgreSQL 16 重跑。Edwards 点运算锁定 `filippo.io/edwards25519 v1.1.0`，数据库客户端为已有 `pgx v5.7.4`。

从 `services/api` 实际执行：

```sh
sh authlab/run-isolated.sh
```

脚本从零建立临时集群，执行 `go test -race -count=1 ./...` 和 `go vet ./...`，两者成功退出。数据库集成测试不是 mock；测试前检查实验数据库、非超级用户、私有 socket 与 application_name，并显式启用实验 schema 重建。本轮仅使用合成数据，没有提交真实邮箱、生产私钥或临时数据库密码。

11 个数据库案例通过，其中注册／退役竞争运行四组双事务：

1. 原子开户、恢复码确认、秘密仅首次返回及无权限重放。
2. 用户名冲突消费已验证挑战，但不消费槽位；可新建意图继续。
3. 原位收缩过期结果锚点后，迟到 POST 不重执行。
4. 同槽位开户／退役竞争只提交一个终态。
5. 唯一索引等待跨越截止时间后，全部临时写入回滚。
6. 同键并发提交只有一份会话，另一响应为无秘密结果。
7. 槽位锁等待之后重新采样数据库时间，过期意图不能开户。
8. HSM 失败、V 已提交但 ACK 丢失、C ACK 事务写入失败、迟到 ACK、密钥版本轮换、清理和迟到 signer；旧收据不清后来的新槽位。
9. 同一精确邮箱并发只保留一个资格；大小写不同地址不被折叠。
10. 未知映射、错误签名和相反用途收据不能释放或 ACK。
11. C 没有邮箱列，V 没有社区账号凭据列；会话存摘要而非原令牌。

协议测试消费原公开签名、弱点及编码向量，并通过 race 检查。Go 原生验签接受原向量中的四个弱点反例，项目严格包装器全部拒绝；不以裸 `Verify` 替代该准入配置。**时钟回退／时间高水位案例仍明确跳过**，不算协议算术或数据库事务测试已经解决灾备。

最终截止检查另做一次负向验证：仅临时移除注册在唯一索引等待后的 `checkSignupDeadline`，对应测试确实发现过期开户；立即恢复原字节后，聚焦测试通过。记录注明负向退出 1、恢复后退出 0，验证的是可观察的未授权提交，而非测试与实现互相复述。

## 4. 评审中已修正的问题

- 协议用途 `RETIRED/V1` 与数据库状态 `RETIRED` 显式转换，避免签名帧用途与 SQL 枚举混用。
- PostgreSQL 时间参数显式转为 `timestamptz`，避免同参数在列和 interval 运算中类型推断冲突。
- 用户名冲突及终态槽位拒绝均持久清除已处理挑战；开户业务回滚不误耗槽位。
- 同键等待者锁后重读提交结果，避免把已经成功的重复提交当成失效意图。
- 过期锚点的 NULL 结果字段正确处理；不同操作共用原键明确拒绝。
- C ACK 与 ledger 标记同事务，签名轮换时同终态的迟到 ACK 仍可确认；已清理任务无法被旧 signer 重建。

协议 agent 对父任务事务源码做只读复核，剩余两个测试备注（持锁事务清理、唯一索引等待截止检查）已落实。这是内部 AI 代码检查；不是人类第三方审计或生产放行。

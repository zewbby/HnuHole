# Authorization Safety Gate：第 0 步隔离实现与验证

日期：2026-09-30。基线分支：`codex/auth-privacy-handoff`，起点 `0409609`。范围仅为第 0 步；本轮没有实现用户名密码登录、完整会话管理或生产路由接入。

## 实现边界

- C 实验迁移 `0002_authorization_gate.sql` 默认 FROZEN，持久保存可信时间高水位、证据版本、授权代次、冻结原因与审计。注册意图及初始 Session 保存不可变的 authorization_generation；旧代次不能在恢复后获得新权限。
- 所有现有注册入口先做 Gate Snapshot；HTTP 在 Argon2 前取得代次，再把代次固定在注册意图中。`CommitSignup` 的开户、恢复码和初始 Session 与最终 Gate 复核属于同一事务；幂等重放也先过当前 Gate。资格过期和时间证据在锁等待结束后复核。
- `CommitAuthorized` 持有数据库门禁行锁直到提交。它先做最终可信时间／代次／证据复核及业务期限检查，再先持久推进库外锚点、提交数据库事务。事务异常回滚时若锚点领先，下一次请求冻结；这是有意的 fail closed 可用性取舍。`Abort` 在业务回滚后用独立事务持久同步冻结。
- 实验签名证据与独立签名锚点存在 PostgreSQL 快照之外的私有文件，由文件锁序列化多实例访问。证据 TTL 上限 5 分钟，时钟回退容忍上限 5 秒，高水位不倒退。FROZEN 不随重启、证据刷新或原幂等请求自动解除。
- 正常恢复要求独立在线证据、受限恢复角色的签名动作、显式操作 ID 和审计，并将代次推进一。离线 break-glass 使用独立签名恢复材料；在线证据不可用时只在离线证据有效期内开放，过期再次冻结。原 Session 的隔离认证读入口 `AuthorizeExistingSession` 复用 Gate，冻结期间不能凭旧 Bearer 读受保护账号。
- 门禁错误在隔离 C HTTP 注册端映射为 `503 SERVICE_UNAVAILABLE`；不是 `401/403`。现有 V 资格链路、退役收据和生产演示认证器未改为新门禁消费者。

## 实际验证

在 `services/api` 下执行 `sh authlab/run-isolated.sh`：新建两个非超级用户的临时 PostgreSQL 数据库与私有 Unix socket，运行 race 全模块测试与 vet。运行结果、工具版本及源码 SHA-256 见[机器验证记录](../../services/api/authlab/authorization-safety-gate-verification.json)。测试确实执行 SQL；原 28 个数据库集成案例仍运行，其中真实 HTTPS/mTLS 两例未跳过。

新增隔离数据库故障测试覆盖：5 秒边界与超限回退、5 分钟边界与证据过期、缺失／错误签名／旧版本／未来证据、数据库或锚点失联、重启与跨连接实例冻结、旧库门禁行回退对比库外锚点、受限恢复角色与签名校验、显式恢复审计与代次推进、在线证据刷新不自动解冻、离线 break-glass 及其 TTL、注册请求在槽位锁等待中冻结、账号／恢复码／Session 不落库、旧 Bearer 读失败、恢复后旧意图和旧 Bearer 失效、旧幂等键无权限重放、冻结前已提交事实保留、以及模拟后续登录命令与 Session 续期的最终事务栅栏。原 `TIME_RESTORE_CLOCK_ROLLBACK` 固定向量已在真实 Gate 测试中执行；纯票据时间算术测试保留其职责，不再把该向量标成跳过。

故障演练用受控时钟和签名文件模拟独立证据；旧快照案例由实验库所有者模拟旧门禁行并保留新的库外锚点，证明快照中的 OPEN 不足以放行。登录／续期向量只通过统一 Gate API 和真实事务模拟未来消费者；用户名密码登录、续期接口尚未实现，不能把模拟称为端到端登录验收。

## 进入下一切片与生产边界

第 0 步隔离验收后，可以开始“用户名密码登录＋完整会话管理”的实现切片。新登录、接替、恢复、续期、注销和所有认证读写必须逐个接入同一最终事务门禁，并各自补真实边界测试；不得从本轮模拟推断那些未实现路径已安全。

真实独立可信授时、生产外部证据／锚点部署、整库灾备演练、多地域失效分析、运营恢复角色分权、密钥托管与人类独立安全审计仍是生产上线门槛。隔离文件锁和每次授权检查的同步持久化尚未经生产负载评估；本机签名文件与内部测试不证明这些外部条件。

# AC01：V 独立 Safety Gate 实施与验收

日期：2026-10-04（Asia/Shanghai）。分支：`codex/auth-privacy-handoff`，实施基线：`faf557db4d74ecb2c202fd1349f1bf8fa64e6133`。本任务只处理 AC01；AC02、AC03 和完整业务开发不在本次实现范围。实际完成状态与执行结果以本轮验证报告和机器记录为准。

## 依据与安全不变量

依据[匿名收口清单](auth-privacy-closure-checklist.md)的 AC01、[已确认的 Gate 设计](auth-authorization-safety-gate.md)和[第39轮最终答复](../discussions/2026-09-29-grilling-round39.md)。沿用已确认的 5 秒回退容忍、最多 5 分钟签名证据、持久冻结、单个受限恢复角色、显式代次推进及审计；正常恢复与受控 break-glass 分别验证证据。工程复用同一状态机，V 具有自己的数据库状态、域、信任材料和库外锚点。

V 无法确认当前时间、数据库状态或恢复代次可信时，资格操作及受保护结果核对 fail closed。C 正常运行、C Gate OPEN、重启、时间重新向前或取得新证据，都不能直接解除 V FROZEN。数据库中的 OPEN 必须与 V 的独立库外锚点匹配。

## 独立状态与受限恢复

- V 使用 `v_auth.authorization_gate` 和 `v_auth.authorization_gate_audit`，不读写 `c_auth` 的 Gate。schema 参数只接受固定白名单；默认 C 行为保留。
- V 正式迁移由版本 3 推进到版本 4，首次部署为 FROZEN。证据、anchor、高水位和授权代次一致后，由受限角色显式建立初始可信状态。
- V 的证据、恢复、break-glass、anchor 及协议签名密钥保持用途分离；C/V 的 Gate 材料、域和状态文件分开。API 只持恢复公钥，不能持恢复签名私钥或取得恢复角色成员资格。
- `hnuhole_v_runtime` 只有业务与 Gate 检查／冻结所需权限；`hnuhole_v_recovery` 才能推进代次及开放 Gate。迁移 owner、runtime 和 recovery 的边界在真实角色下验证。
- 旧数据库快照与当前独立锚点不一致时冻结。若数据库和库外锚点一起回退，本地文件无法独立证明新鲜性；生产独立存储、授时、备份与灾备运行证据继续属于 P02/P03。

## 最终授权点清单

| 路径 | 授权与可信时间要求 |
| --- | --- |
| OTP 发码、预算、设备锁、等待与原结果 | 前置取得 V 代次，数据库事务最终复核；预算、有效期、等待和留存裁决使用 `TrustedAt`。 |
| OTP 验证与确认资格 | 消费 OTP、配额占用、确认记录和待签名作业在同一最终授权事务内落库。 |
| 提交后资格／退役授权签名 | 签名器在业务锁／事务外运行；调用前授权，返回后按持久作业代次、当前 Gate 与原记录再次核对，不落库跨代迟到结果。 |
| 原确认退役与续办 | mTLS 外部调用不持业务事务；原确认／作业代次不可随恢复重绑定，最终事务复核槽位与可信资格窗口。 |
| 收据与配额释放 | C 的已提交签名事实可在当前 V Gate 下核对；不得借此续办失效的旧确认或发出新资格。 |
| 邮件派发与回调 | 持久 claim 绑定 V 代次，SMTP 在事务外；回调须核对原 claim 与当前授权，保留 UNKNOWN 的不自动重复派发语义。 |
| OTP／确认及其他有界清理 | 候选扫描不能构成删除授权，最终事务使用可信时间并复核 Gate；冻结时停止改变资格材料。 |
| 健康与就绪 | live 表示进程存活，ready 核对本侧 Gate；V FROZEN 时 ready 不可用。 |

事务的前置快照不能替代最终复核。业务锁等待后、签名返回后及同意图重试均须再次检查；无效最终提交回滚业务副作用，同时保留冻结事实。外部 I/O 一旦按授权启动，其已发生的邮件或对端效果无法撤回；此边界不应包装为跨服务原子事务，迟到回调不能进一步产生资格或复活本地旧作业。

V 的短事务 Gate 快照使用独立有界连接池，最终授权仍提交原业务事务。业务事务内的时间刷新不能再从已耗尽的业务池索取连接；前置刷新不跨业务锁等待保留 Gate 行锁。

## 恢复代次与已有数据

OTP flow、confirmation、sign job、mail outbox 和 retire pending 持久记录各自授权代次。升级前记录默认代次 0，不能直接成为新代次的授权作业；恢复前 pending authorization 也不能重新绑定新代次。调用方需重新验证校园资格。永久槽位和已提交收据事实保持其原协议约束，不能通过清空表来解除邮箱占用。

已完成的无秘密结果在当前 Gate 下按原结果能力核对；历史结果不变成新的资格授权。未完成的旧确认、签名、派发或退役作业不得通过重启、worker 重扫或原键重试重新开放。

## 必须保留的测试证据

1. 正常状态下 V 资格链仍可完成，C/V 冻结相互独立。
2. 5 秒阈值边界、高水位不倒退、超阈值回退、证据过期及缺失，均有真实数据库断言。
3. 恢复完整旧 Gate 数据与业务快照时，独立锚点阻止自动开放；冻结在重启和另一个副本中保持。
4. 新鲜证据不自动解冻；无效、跨域、重放和无权限恢复不能推进代次；有效受限恢复带审计并推进代次。
5. 等锁期间冻结／恢复、签名前后冻结、SMTP／退役迟到回调，不能越过最终授权或复活旧作业。
6. 原键结果核对、永久槽位、收据释放与 UNKNOWN 邮件状态继续遵守原协议。
7. 正式迁移 3→4、初始 FROZEN、受限 runtime 与独立 recovery、实际 C/V 进程冻结／恢复／重启分别记录。
8. 共享 Gate 核心改动重新验证现有 C SQL／race／vet 与相关 HTTP 链路；旧版本记录保留原证明范围。

# 匿名业务接入契约（AC03）

日期：2026-10-04。本契约固定已确认的 [账号规则](modules/accounts.md)、[身份规则](modules/identity.md)、[私信规则](modules/messaging.md) 与 [AC01–AC06 清单](auth-privacy-closure-checklist.md)。它约束以后 B05–B11 等模块的实现；当前分支不因此扩展帖子、评论、聊天或管理后台。

## 公开资料与本人管理

公共资源只返回已授权内容所需的该身份资料：活动身份的昵称、头像及确有业务需要的身份级不透明标识；正式删除／账号关闭后使用独立的注销投影。不得返回内部 accountId、slot、私有用户名、验证邮箱或摘要、安装／设备标识、会话／恢复材料、累计创建数、isOriginal／内部序号、其他身份列表、共同账号关系标记。公共 DTO 与本人管理 DTO 分开定义并使用字段 allowlist；不得将数据库行、本人列表、请求回执或管理对象直接序列化到公共资源。

`/api/v1/identities` 及变更／结果查询仅供同一有效会话的本人管理，允许本人需要的原始身份标记和创建限制信息。内部账号从最终授权事务中的会话取得，不接受客户端 accountId、ownerId 或类似选择器。跨账号的身份变更与回执核对必须拒绝；公开身份标识本身不授予本人管理或查阅其他身份的权限。不得增加公开个人主页、全部历史发言查询或按昵称枚举身份历史的接口。当前只实现本人管理 API，公共帖子／评论／消息资料消费者未集成。

## 生命周期与独立占位

七天缓冲期不提前显示注销状态，也不清除原公开资料。正式关闭与现有身份资料擦除在同一 C 最终 Gate 事务内完成；单独删除和正式关闭均保留必要墓碑、累计约束及永久回执。公开旧内容保留与单独内容删除仍服从各业务的可见性和权限规则。

后续业务读取先在最终 Gate／会话／资源归属检查内得到该内容身份的权威生命周期，再调用 `ProjectInactiveIdentityLifecycle`。该纯函数只生成身份级 placeholderToken、统一 avatar 与 state，不提供查询或授权。同一身份的独立占位在删除后又正式关号时保持稳定；不同身份不得按 accountId、共同关闭时间或统一账号编号合并。不得继续显示已擦除昵称／头像；对外不得加本体或其他面具关系。2026-10-08用户确认统一显示“注销身份 · 短编号”和统一头像，点击时分别提示“身份已删除”或“账户已注销”；具体编号长度、字符集、碰撞处理与头像资源随实现固定，现有 token 不直接决定界面文案。

正式注销后，本人设备获知权威终态才清理该旧账号本地聊天、私人备注和搜索历史；缓冲期不提前清理。对方本地已有记录保留，按原身份独立占位并停止发送，不开放云端历史恢复。新账号不继承旧身份、内容归属、私信或私人历史。当前公开内容、聊天本地数据及清理消费者尚未实现；AC02 的数据库关闭和纯投影不能代证这些调用链。

## 账号＋帖子固定身份

服务端最终业务事务按内部账号＋帖子建立唯一绑定。首次公开发送发帖／主评论／楼中楼回复，或从来源帖首次发送私信，被服务端完成权限、内容和身份校验并接受发送任务时才固定身份；绑定、发送任务及结果回执原子提交。仅打开设置、选择身份、草稿输入或取消不产生绑定。校验拒绝且未形成任务时不绑定；任务受理后即使异步发布失败，也保留绑定，重试继续使用原身份。并发首次发送只能确立一个绑定；后续该帖回复及从该帖发起互动必须复用已有身份，其他候选身份即使属于本人也不能替换。失败任务和未知提交结果继续核对原意图／原身份，不能静默换身份重发。被删身份停止未成功任务；选择有效默认身份只用于尚未绑定的操作。

该绑定表及内容消费者当前未实现。B05/B06/B07 必须补并发、请求重放、未知结果、身份删除／关闭与发送竞态及授权代次测试，不能以本契约或 B02 CRUD 通过代替。

## 按身份对隔离私信

会话键由参与双方身份组成，并由服务器处理方向规范化；不按共同账号合并。相同身份对可跨帖延续；任意一方换成另一身份即成为独立会话。创建或发送先遵守来源帖的固定身份及收件身份权限。尚无该帖绑定时，首次私信接受发送任务也原子建立同一账号＋帖子绑定，后续公开发言或联系其他人沿用；只确认发送身份或关闭选择面板不绑定。用户切换消息收件身份不改变已有帖内绑定。后台可以按账号执行接收限制／处罚，但响应、错误文案、数量、合并列表和关系标记不能揭示其他身份。

B08/B09 会话／消息模块当前未集成。后续必须验证身份对唯一性、双方对称隔离、非本人收件身份、删号停止发送、拉黑不泄露关系、离线及未知结果恢复，不把账号级治理键输出给客户端。

## 管理、恢复与数据边界

C 不保存完整验证邮箱或可连接邮箱的摘要；V 只接收资格与槽位协议需要的数据，不接收社区账号、用户名、密码、恢复码、身份资料或社区会话。共享 slot 是既定协议字段；真实串通、共同泄漏或可同时读取两侧的运维仍可连接邮箱与账号。本契约不声称抵抗该关联。V 的必要校邮处理权限不应成为任何社区管理角色读取邮箱的能力；普通审核员不得查询其他身份，所有社区管理端不得展示或恢复完整验证邮箱。

邮箱 OTP 仅证明新账号准入，禁止客服／管理后台按邮箱查回旧账号、返回旧用户名、重设密码、强行释放活动资格或离线建立邮箱—账号映射。旧账号控制仅走既有密码、预登记高熵恢复码或 Passkey；全部独立凭据丢失时旧号不能找回。处罚、申诉和审计 DTO 各自按所需权限定义最小字段，不能复用完整账号或资格行。管理消费者当前未实现；B10/B11 接入时需补角色和负向字段检查。

C/V 端点、请求编号、安装 ID、幂等键、密钥、普通日志与备份域分离。应用诊断采用固定事件与有界类别，不记录请求体、响应体、邮箱、OTP、密码、Bearer、恢复码、完整票据、能力头、原幂等键或意图 ID、私钥、底层数据库错误／panic 值。生产数据库、代理、邮件商、崩溃收集与遥测的配置／留存需要独立证据；开发源码检查不是实际生产运维批准。

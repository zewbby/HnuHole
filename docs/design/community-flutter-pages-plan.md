## 3. 需求决策树

前提已定：文字切片 → 两步发布和后台任务 → 草稿／任务隔离 → 服务端权威结果 → 独立身份投影。

Q1（已决）：本片未实现入口如何呈现？用户答复“隐藏了后面会麻烦吗？怎么方便怎么来”，授权按实现便利决定。选择隐藏详情评论／赞藏、列表搜索／筛选，暂不提供收藏页签，保留阅读结构、作者、返回和本人删除。通过独立正文／元信息／操作区域、列表查询与筛选职责分离，为以后接入保留位置，不预写未来业务。隐藏控件可逆，不删除完整产品规则，也不将参考图中删去的功能登记为已实现。

Q1后续限定：以上只描述文字切片的代码启用范围。用户随后明确要求完整页面图稿展示图片、点赞数、通道名、搜索与底栏；F1须保留完整设计，不继续用Q1删除用户要求的视觉内容。图片上传／搜索／互动等实现仍须独立任务和契约。用户已将含“最新发布＋筛选”紧凑工具栏、白色框架的v9三图正式定稿；不放只有一个选项的排序下拉。底栏“首页”回导航树，不设置全通道广场；中央加号仍新建当前通道帖子。热榜维持既定搜索入口。v9局部偏暗偏灰蓝色确认仅适用于本组三状态，不代表全局主题；v7／v8整页暗色已废弃。

不重复询问已定字数、两步发布、默认身份、同机恢复、取消或失败规则。分页失效策略、后端错误码、任务字段等属于工程事实与契约对齐，由实现者查明，出现真实产品分歧才新增问题。`grill-with-docs` 配套方法用于记录决策，本轮不借访谈扩大范围。

| 发布确认 | 标题和身份按已定顺序；本片无标签交互；固定底部确认发布，无预览和额外确认；返回保留输入；连点抑制；持久提交上下文失败留页 |

| 我的／自己的帖子 | 正常态F1-11沿用已定稿列表版式；发布中／失败以选中的双列混排正式PNG为准；普通草稿、后台状态、失败重试草稿、正式帖同列表；明确失败为草稿＋亮红叹号；草稿按编辑时间，正式帖按发布时间；原置顶保留，不新增失败栏或草稿箱 |

客户端状态名称为暂定语义，不冒充尚不存在的API枚举：普通草稿、提交上下文已持久化、原结果未知、已受理处理中、取消核对中、明确失败、已公开、已取消。权威状态只能来自服务端；未知结果与服务端发布任务终态分开。发送前先原子保存命令标识、不可变尝试payload及归属；发送后即使响应丢失或进程被杀仍能核对原命令。

点击确认后后台发送并直接返回原通道，不显示发布状态整页。本地写入上下文只证明有可恢复操作，不证明服务端受理或公开；确认公开后才上方短暂提示发布成功。明确失败保存为失败重试草稿并标叹号，保留原尝试及固定身份／通道；重试按契约建立尝试，不变成普通草稿换身份。取消已公开任务不能撤销成功，作者删除是另一操作；明确失败删除只隐藏本人入口，不销毁服务端回执。

## 5. 账号授权、隔离与持久化

使用现有 `AuthSessionController` 的当前令牌和授权代次检查，401走既有失效入口，503／超时保持可恢复状态并暂停受保护读取；迟到响应不写入新账号或新通道。客户端判断不替代C最终业务事务、会话代次和资源归属授权。

业务持久化采用ADR已定Drift/SQLite。现有pubspec无Drift／SQLite，需增加明确依赖、迁移与跨进程测试；不将正文、草稿和队列塞进认证AuthStore。按可信环境域和内部账号隔离本机数据；内部归属键不得进入公共DTO、界面或日志。普通退出／401／暂时冻结保留隔离草稿；正式关闭获权威终态才执行对应账号清理，新号不能继承旧数据。

F2和后端T1共同固定：业务敏感payload保护、独立原生vault namespace托管密钥的接口、SQLite迁移和备份排除、提交上下文原子写入与损坏处理。不得修改认证已验存储schema来省事。密钥不可用／库损坏时停写并明确恢复状态，不用内存替身或明文回退宣称持久成功；真实方案未固定前不得称安全存储完成。

会话变化先封闭界面及进行中的敏感回调；是否可重新显示本地内容要经同账号恢复授权。身份改名读权威投影；删除身份保留普通草稿文字但清除失效选择，已受理任务不换身份。申请注销停止未公开任务由服务端执行，客户端不能等七天后才反映；正式关闭和暂时无权访问分别处理。

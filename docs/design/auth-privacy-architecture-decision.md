# Hnuhole 认证与匿名隐私架构决策

日期：2026-09-26。基于 `codex/auth-privacy-handoff` @ `680f863` 及本轮用户最终确定的入口：**每次创建账号都验证学校邮箱验证码；日常只用私有用户名和密码登录；同一精确邮箱地址同时最多一个有效账号。**

状态：**架构决策＋实施前协议规格；尚未实施或经过独立安全审计。** 注册、取消未消费资格与释放的固定字段及状态机见[协议 v1](auth-privacy-registration-protocol.md)；[独立恢复策略](auth-privacy-recovery-decision.md)与[数据/API 契约](auth-privacy-data-api-contract.md)已补齐实施前规格。旧 ADR 0005 和账号模块中的“邮箱验证码唯一登录”已被本决策替代。

## 1. 结论和必须承认的取舍

采用独立校邮验证方 V 与社区方 C。每次注册，客户端新生一次性 Ed25519 密钥，按固定作用域对公钥做 SHA-256 得到**本次资格槽位** `slot_id`。用户在 V 验证当前学校邮箱控制权，V 只签该槽位与公钥；C 验签、验证槽位散列等式及客户端对 C 一次性挑战的持钥证明，才原子消费槽位并创建私有用户名和密码账号。日常登录、换机、缓冲期内主动撤销注销都只用用户名和密码。邮箱验证码不能找回、重设或接管已有账号；忘记密码只能用事先保存的独立恢复码或预先登记的备用 Passkey。

V 以精确邮箱地址为键保存当前槽位，并保证当前槽位在 V 全局唯一、已退役／释放槽位不再签发；C 在账号存活期间保存槽位与账号的对应。正式注销时，C 在关闭旧号的同一事务中写入释放意图；事务提交后才签发只含旧槽位的收据并幂等送达 V，用户也可在注销状态页取得同一收据并在重新收码时提交。V 只在核对该槽位已关闭后才允许此邮箱领到**全新公钥导出的槽位**并注册全新账号。V 知道“邮箱→当前槽位”，不知社区账号；C 知道“当前槽位→账号”，不知邮箱。旧槽位完成释放和确认后从两侧在线账号映射删除；C 另保留与账号脱钩的最小终态记录以拒绝旧资格重放。新槽位与旧槽位在 C 看来没有密码学上的共同标记。

**这是一项有意识的隐私让步。** 同一个在两方共享的公钥导出槽位是可直接连接两份数据库的键；两方串通、同时泄漏或同一运维主体能读取两侧时，可得到邮箱—账号映射。仅靠 RFC 9578 的盲券可隐藏签发与兑付关系，却不能单独证明“注销的账号与此次重新验证的是同一个邮箱”并维持精确地址的一号配额。为满足用户新确定的“每次收码＋同邮箱一号＋注销后可再注册”，首版选择可审计的跨方槽位，不声称具有盲券方案的串通下不可关联性。这是对 [Privacy Pass 的发行／兑付边界](https://www.rfc-editor.org/rfc/rfc9576.html) 的架构推论，不是匿名配额不可能性的数学证明。若未来引入经过独立审计的匿名凭证与同邮箱等值证明，可重新评估替换槽位。

“一个邮箱只能注册一个账号”限定为**一个精确邮箱地址同时最多对应一个有效账号**，不是一个自然人或同一个实际收件箱一号。现行邮箱前缀允许别名且大小写严格区分，多个可收码地址可能归属同一收件箱；任何算法都不能仅凭字符串安全猜出学校的别名等价关系。恶意 V 可以违背配额签发新资格，这是用户已接受的“可造新号、不可接管旧号”边界。

## 2. 威胁模型

| 主体／事件 | 可见或可做 | 当前保证及限制 |
| --- | --- | --- |
| 校邮系统或 V 主动恶意 | 看邮箱、伪造／拦截 OTP、拒签或额外签发新槽位；可用退役授权试探槽位是否已开户 | 可制造新资格或阻止注册，也可推断某邮箱是否完成开户；不能用另一公钥抢用户的**同一槽位**，仍得不到账号 ID／用户名；没有旧号密码／独立恢复凭据，不能只靠校邮接管旧号 |
| C 主动恶意或定向篡改客户端 | 可读取账号、密码输入、面具和内容，或让客户端泄露校邮 | 不承诺对恶意社区端点的绝对匿名；发布客户端和权限必须受控 |
| 只泄漏 V 数据库 | 精确邮箱、当前公钥导出槽位、验证码短期状态 | 单独没有 C 的账号对应表；可知道某邮箱曾申请资格 |
| 只泄漏 C 数据库 | 私有用户名、密码验证值、账号、面具、当前槽位 | 单独不含邮箱；弱密码可能被离线猜中并造成账号与隐私损失 |
| V 与 C 串通，或两边数据库／备份同时泄漏 | 可按当前共同槽位准确连接邮箱与账号 | 不在当前匿名保证内；历史槽位、日志与备份还可能连接已注销旧号 |
| 单一运维人员／共同云控制面 | 若可同时读两侧数据库、签名密钥或完整日志，就能跨方查询 | 必须是真实不同组织与权限域；名义拆服务无效 |
| 邮件提供商 | 邮箱与收码时间，可影响实际控制权 | 不应收到用户名、密码、账号 ID；不能宣称对邮件系统匿名 |
| 设备被盗、密码复用、恢复码被盗 | 已登录会话、弱密码或恢复权可能丢失 | 安全存储、限速、再次认证和恢复码轮换；不保证失控设备安全 |
| 网络观察者与小流量时序分析 | IP、访问时刻、注册／注销时间 | 最小日志及必要的批量诊断；即时释放仍有时序线索，不保证全网匿名或串通下不可关联 |

对外可说：在实际分权并且双方不串通时，任何**单一一侧**没有“邮箱↔社区账号”的完整映射；V 可能获知某邮箱是否完成开户，不等于知道具体账号。不可说：“即使两方串通也无法识别”“学校绝不可能知道用户身份”“V 连是否完成开户都无法得知”“一个自然人只能拥有一个账号”。

## 3. 候选架构的八项比较

以下比较均要求“校邮资格”与“既有账号控制权”分开讨论。学校 SSO 和 ZK 邮件证明只是资格来源，仍须另设用户名密码或 Passkey 控制旧号。

| 维度 | 邮箱 OTP 唯一登录 | 盲资格＋注销续券（上一稿） | 本决策：公钥导出槽位＋用户名密码 | 槽位＋Passkey 主登录 | 学校 SSO／ZK Email＋独立账号凭据 |
| --- | --- | --- | --- | --- | --- |
| 1. 恶意 V 接管旧号 | 可通过伪造验证进入或重置 | 不可，前提是独立恢复 | 不可，前提是独立恢复 | 不可，前提是独立恢复 | 若旧号控制退回 SSO／邮件则可；独立恢复时不可 |
| 2. 邮箱—账号映射 | 重复验证与稳定索引易形成关联 | 盲券无共同直查键，仍有时序关联 | V/C 各一半；共享槽位令串通可直接映射 | 同本决策 | 取决于匿名层；普通 SSO 的稳定 subject 易映射 |
| 3. 库／日志泄漏 | 稳定索引、邮件日志或联合记录风险大 | 单侧券账本不含邮箱；联合时序仍危险 | 单侧无完整映射；两侧泄漏可按槽位直接连接；C 弱密码可猜 | 槽位风险相同，C 侧无密码哈希 | IdP 邮件／实名日志、证明元数据、联合日志依实现而定 |
| 4. 串通 | 可关联 | 主要靠网络与时序关联 | 可用槽位准确关联当前账号 | 同本决策 | 普通 SSO 可直接或近乎直接关联；ZK 仍有元数据 |
| 5. 首次／日常／换机／全凭据遗失 | 每次登录收码；换机易；失校邮即困难 | 首次收码；日常需另设控制；旧资格券遗失影响再注册 | 每次注册收码；日常和换机用密码；全凭据遗失不能救回旧号 | 每次注册收码；日常生物识别／同步；全凭据遗失不能救回旧号 | 首次依学校或证明钱包；日常、换机和失权取决于独立账号凭据 |
| 6. 恢复是否回退单邮箱接管 | 是 | 若邮箱单独重置则回退 | 仅独立恢复码／备用 Passkey；邮箱单独重置会破坏边界 | 同左 | 若 IdP／邮件直接重绑账号凭据则破坏边界 |
| 7. 成熟度与审计 | OTP 成熟，但不满足攻击边界 | Blind RSA 已标准化；同邮箱续券与新 OTP 等值证明未有本项目可直接套用的标准 | Ed25519、Argon2id 成熟；跨方配额状态机仍需审计 | WebAuthn 成熟；跨方配额和找回另需审计 | OIDC／SAML 成熟但学校授权未知；ZK 实例需专项密码学审计 |
| 8. 实施与运营 | 低，但隐私与旧号控制不达标 | 高：盲券、续发、客户端备份、等值证明 | 中高：两组织隔离、原子槽位、释放收据、备份与日志 | 中高，另加认证器及同步恢复支持 | 高：学校合作或证明系统、可信签名来源与审计 |

盲资格上一稿可以做到**首次验证后注销续券免重新收码**，但用户明确要求每次注册重新收码，因此不能再把它作为当前决策。学校官方 SSO 可提供更权威的资格来源，尚无学校合法接口；ZK Email 无法让 Hnuhole 自己发出的邮件变成独立可信事实。当前不发明密码学原语。

## 4. 推荐协议与端到端时序

固定编码、签名用途、原子状态和异常处理以[注册与释放协议 v1](auth-privacy-registration-protocol.md)为准。客户端每次申请**新的资格槽位**时生成全新 `sk_boot/pk_boot`，用固定作用域的 SHA-256 公钥散列得到槽位；同一槽位的开户意图重试继续使用原密钥。V 验严格 `hainanu.edu.cn` 地址和 OTP，原子保留“邮箱→槽位／公钥”，签固定格式的 `register(slot_id, pk_boot)`。客户端核对返回值；C 同时验 V 签名、槽位散列等式和客户端对**真实 C 的一次性挑战及不可修改开户意图**的持钥证明。

单纯把公钥附加到 V 签名资格并要求 PoP，无法阻止主动恶意 V 对用户同一槽位再签自己的公钥并抢先开户；散列绑定堵住的是这一具体换绑路径。V 仍能用自己的新公钥和新槽位伪造资格、占用邮箱配额或拒绝服务。C 在同一事务中验槽位未被开户／退役，创建唯一私有用户名、密码验证值和账号，消费槽位与挑战。用户名冲突不能消耗槽位；C 提交成功而响应丢失时，用户改用用户名密码登录，**不能凭旧资格或持钥证明重发会话**。V 不接收社区用户名、密码、账号 ID 或内容。

~~~mermaid
sequenceDiagram
    actor U as 用户
    participant A as 客户端
    participant V as 独立校邮验证方
    participant C as 社区认证服务
    U->>A: 每次注册填写学校邮箱
    A->>A: 新生 sk_boot 和 pk_boot，由公钥导出 slot_id
    A->>V: 邮箱、OTP 请求
    V-->>U: 一封验证码邮件
    U->>A: 输入 OTP
    A->>V: OTP、slot_id 与 pk_boot
    V->>V: 验证邮箱且原子保留本地址的槽位
    V-->>A: 固定签名资格 register(slot_id, pk_boot)
    U->>A: 设置私有用户名、独立密码并保存恢复码
    A->>C: 签名资格与开户材料
    C-->>A: 一次性挑战与待开户意图 ID
    A->>C: sk_boot 对真实 C 挑战及意图的证明
    C->>C: 验签、核对公钥散列、验 PoP、原子建号
    C-->>A: 单设备会话
    Note over A,C: 日常与换机只用用户名和密码
    A->>C: 用户名和密码登录
    C-->>A: 接替旧移动会话
    Note over C,V: 正式注销事务写关闭状态与释放意图
    C->>C: 事务提交后签发 release(slot_id)
    C-->>V: 幂等释放凭据
    V->>V: 仅当前槽位匹配才释放该邮箱配额
    Note over U,V: 再注册时再次收 OTP，并由全新公钥导出全新槽位
~~~

这不是 Blind RSA／Privacy Pass 发行协议；本方案**不宣称资格签发和开户在两方串通下不可连接**。SHA-256、Ed25519、Argon2id 是成熟原语，跨方状态机、持钥证明与故障恢复的**组合安全性仍需单独审计**。

## 5. 用户流程及恢复

| 场景 | 用户操作 | 服务端结果 |
| --- | --- | --- |
| 首次注册 | 校邮收一次验证码；设私有用户名和密码；保存并完整重输确认 C 一次性展示的高熵恢复码，Passkey 可选 | V 占用该精确地址；C 建号但不自动创建公开面具 |
| 日常登录或换机 | 输入私有用户名和密码 | 不联系 V；新设备接替旧设备唯一移动会话；会话三十天、近到期且活跃时续期 |
| 忘记密码但有备用凭据 | 用预设恢复码或备用 Passkey | 重设密码，撤销旧会话、旧恢复码与**全部旧 Passkey**；登录后可重新登记 Passkey，保留原账号内容和处罚 |
| 忘记用户名 | 用恢复码或可发现 Passkey 先证明旧号控制权 | 证明后才显示私有用户名；无“输入邮箱查回用户名”的接口 |
| 密码、恢复码及备用凭据全失 | 无法证明旧号控制权 | 邮箱 OTP 不救回旧号；原精确邮箱槽位仍占用，不能直接注册第二号 |
| 申请注销 | 用旧密码再次认证，进入七天缓冲 | 禁言允许；封禁禁止，缓冲期新封禁取消申请；主动成功登录可取消 |
| 正式注销 | 不需用户长期保管旧资格券 | C 永久关闭旧号并生成槽位释放凭据；投递失败会自动重试，状态页可取得同一凭据 |
| 注销后重新注册 | **再次**输入同一精确学校邮箱并收 OTP；创建全新用户名和密码 | V 核对旧槽位释放后发新槽位；用户可提交状态页凭据加快处理。C 建全新账号，旧内容按注销占位保留，不继承旧身份、私信、收藏或禁言 |

旧号密码与邮箱 OTP 是不同用途：OTP 只能证明当前校邮控制权与新账号准入；密码或独立恢复凭据才证明旧账号归属。普通 App 允许邮箱单独重置密码，是另一种可接受的产品取舍；本项目为了防校邮方冒充用户而不开放这种路径。[OWASP 找回指南](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)

注册时由 C 生成并一次性展示 128 位恢复码，用户在资格正式消费前完整重输确认；C 只持久保存验证摘要，用后轮换并限制尝试。备用 Passkey 是可选独立恢复凭据，不改变日常用户名＋密码入口。若全凭据遗失且仍有有效会话，敏感修改也须新鲜独立认证，不能以会话代替找回。具体流程、全失后同邮箱也无法再注册的后果见[恢复决策](auth-privacy-recovery-decision.md)。

## 6. 注销、配额释放与重复请求

C 的七天注销事务必须先检查当前封禁、用户主动登录取消和版本号；仅当旧号不可逆关闭时，才在**同一持久事务**写入 `CLOSED(slot_id)` 终态及唯一待签／待投递释放事件。外部 HSM 签名不与 SQL 事务天然原子；只可在关闭事务提交后，对已提交状态签发 `RELEASED(slot_id)` 收据。收据只含固定作用域、旧槽位、C 的全局签名版本，不含账号 ID、用户名、邮箱、面具、处罚或精确时间。后台幂等投递给 V；用户也可凭注销申请时取得的受限状态访问权，从状态页领取已签发收据并在重新收码时提交。V 仅在验签且槽位等于该邮箱当前占用槽位时原子释放；重复释放对新槽位无效。**释放消息不能在旧号仍可登录时发出。**即时送达增加时序线索，不能宣称已消除此侧信道。

如果 C→V 投递失败，旧号仍按时正式注销；用户持状态页凭据可在校邮验证时自助释放，若两路均未完成则该邮箱暂时无法重新注册。后台按原槽位幂等重试，界面显示“资格释放处理中”。不能由管理员手工输入邮箱找账号放行。V 可保留当前槽位和释放处理结果直到确认安全；C 的关闭事务即可清除在线**槽位→账号**直连，出站队列和受限状态页只以槽位交付收据，长期保留与账号脱钩的 `CLOSED` 拒重放记录。V 清除在线邮箱→旧槽位映射，同时保留不含邮箱的已处理收据／已用槽位标记；备份与日志按明确保留期限过期。不宣传“立刻从所有历史介质消失”。新注册总用新密钥导出的槽位，不能复用旧槽位。

V 在精确邮箱唯一占用及槽位全局唯一的同一事务中持久保存槽位、公钥和签名结果再向客户端返回；同一确认请求的短期幂等窗口内，客户端仍持有本次 `sk_boot` 时可直接取回原资格，**无需再次收码**。窗口已过或重新进入流程则再次收码，仍得到同一槽位／公钥的有效资格，例行换钥可重签但不另开槽位。C 原子建号后响应丢失，用户用已设置的用户名和密码登录，不以同一资格再建新号或取回旧会话令牌。申请邮箱校验、签发、建号、退役与释放都要审计并发、崩溃和灾备回滚。没有可靠跨方释放确认时，选择**暂时不允许再注册**，不能先开放配额导致两个有效账号。

若用户在 V 领到资格后放弃开户，V 保留该地址的槽位；后续收码且仍持有 `sk_boot` 可继续原资格。若私钥丢失或决定重开注册，V 须在新 OTP 后签发**旧槽位退役授权**，C 原子将从未开户的槽位记为 `RETIRED` 并签收据，V 只在该收据匹配当前旧槽位时才清除配额、签发新公钥导出的资格。若旧槽位已开户，退役失败，不得影响已有账号；只能走登录或独立恢复。不能凭超时自行重置，也不能删除 C 的终态拒重放记录。细节见[注册与释放协议 v1](auth-privacy-registration-protocol.md)。

## 7. 谁知道什么、存什么

| 位置 | 必需数据 | 禁止数据及访问 |
| --- | --- | --- |
| V | 精确学校邮箱、短期 OTP 状态、当前公钥导出槽位与注册公钥、原签名响应、签名私钥、必要配额与已处理收据状态 | 账号 ID、私有用户名、密码、面具、帖子；V 管理员不可查询 C 的槽位→账号记录 |
| C 受限认证库 | 槽位→当前内部账号、与旧账号脱钩的终态拒重放槽位、私有用户名、加盐 Argon2id 密码验证值、恢复码验证摘要、可选备用 Passkey 公钥、短期待开户意图、会话和释放出站记录 | 邮箱原文、可解密邮箱副本、邮箱哈希、V 内部邮件状态；普通运营与管理后台不可按槽位查询 |
| C 社区业务库／管理端 | 内部账号、内容与面具归属、必要处罚状态、受限平台编号 | 邮箱、槽位、密码验证值、恢复秘密、跨代账号直查表 |
| 用户客户端 | 本次注册邮箱、一次性 bootstrap 私钥／公钥和槽位、登录用户名密码、恢复码 | 不把邮箱与账号资料一起上传到分析 SDK、崩溃报告或普通诊断日志；bootstrap 私钥不在注册后继续用于登录 |
| 邮件服务商 | 邮箱和本次 OTP 邮件 | 私有用户名、社区账号和密码 |

V 保存“邮箱→槽位”，C 保存“槽位→账号”，因此同时得到两边数据的人可以准确连接。槽位虽由随机一次性公钥导出、外观不可预测，**不是匿名凭证**，不能写成“不可关联标识”。C 业务库和管理端不存槽位；认证库也不存可由自身解密的邮箱。与账号脱钩的长期拒重放槽位、历史备份、共同日志和共享人员权限都须计入隐私与保存期限评审。

六位平台编号仅本人和授权管理可见，不能作为登录或找回凭据；若继续递增，会泄露大致注册顺序，建议在实现前改为随机不重复编号。旧公开内容按各面具独立占位，不显示旧号与新号关系。

## 8. 密码学、密钥轮换与作用域

- 客户端一次性公钥经固定作用域 SHA-256 导出槽位；注册资格、退役授权、退役与释放收据及客户端持钥证明的固定消息格式见[协议 v1](auth-privacy-registration-protocol.md)。签名采用 [Ed25519 / RFC 8032](https://www.rfc-editor.org/rfc/rfc8032.html)；V、C 和客户端分别持有不同用途的私钥，公钥通过受信配置发布，密钥版本不可按邮箱单独选择。客户端和 C 拒绝意外字段，避免签名消息藏入邮箱派生标签。
- 密码经认证 TLS 传输，只在 C 认证边界短暂处理，存每账号独立盐和校准成本的 [Argon2id / RFC 9106](https://www.rfc-editor.org/rfc/rfc9106.html)。按 [OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html) 评估长度、撞库和限速；弱密码仍可能在库泄漏后被猜出。普通未验证调用的用户名登录错误不能泄露账号是否存在；恶意 V 可自签资格试探全局用户名，不能宣称完全不可枚举。
- 全部签名消息包含 Hnuhole 专用作用域；槽位不能被其他应用接受。例行 V 签名轮换保留受控验签窗口内未消费资格的旧公钥与槽位状态，或要求重新收码为同一槽位／公钥换签；C 收据签名轮换可基于已提交终态重签待确认收据。轮换不重置邮箱占用或 C 终态。疑似私钥泄漏时须先停用对应验签钥并冻结相关操作，不能为了可用性继续收旧签名。
- V 签名私钥泄漏可伪造新资格；C 收据私钥泄漏可伪造退役／释放，从而错误开放邮箱配额。必须暂停受影响操作、审计影响并轮换；已经错误释放的配额不能单靠换钥修复。已有用户名密码账号不因此自动交出控制权。V 主动恶意仍可伪造新资格，这是已接受的边界。
- Privacy Pass 的 Blind RSA [RFC 9578](https://www.rfc-editor.org/rfc/rfc9578.html) 可用于未来**放宽严格同邮箱配额**或引入已审计等值证明的方案。当前槽位方案不应混用“盲签”字眼制造超出实际的匿名承诺。OPAQUE [RFC 9807](https://www.rfc-editor.org/rfc/rfc9807.html) 可后续评估以减少服务端密码接触，但不解决邮箱配额或失权恢复。

## 9. 日志、侧信道及两组织隔离

- V 与 C 必须是实质独立组织控制数据库、备份、云管理、签名私钥和诊断权限；同一人跨两边有读权限即违反单方隔离前提。
- 两边不共用请求 ID、幂等键、安装 ID、cookie、分析 SDK、错误监控账号或含正文的队列。除当前槽位及必要释放凭据外，不建立可 join 的业务字段。
- OTP、邮箱、密码、恢复码、完整资格、会话令牌不进普通日志、崩溃报告和客服系统；槽位仅在受限认证／配额存储及短期必要审计中存在，不能进入业务事件流。
- C→V 释放投递是必要的状态协调，不能宣传成完全独立、无跨方通信。为了保留正式注销后正常情况下立即再注册的体验，释放默认尽快送达；即使未来增加批量处理，也不能抵消共同槽位在串通下的直接映射。
- 注册与注销频率较低的小校园里，即使删除共同槽位，IP、时间、设备指纹、内容和备份仍可能推断旧新号关系。[Privacy Pass 架构](https://www.rfc-editor.org/rfc/rfc9576.html) 也明确讨论部署模型、串通及侧信道；本决策不作绝对匿名宣传。

## 10. 对现有规则的替换与迁移

| 来源 | 处理 |
| --- | --- |
| [ADR 0005](../adr/0005-privacy-preserving-email-authentication.md) | 原“邮箱唯一登录／稳定匿名凭证”不再是认证主链；沿用两组织隔离和社区不存邮箱目标，并明确当前槽位的串通边界 |
| [账号模块](modules/accounts.md) AUTH-01／AUTH-API／AUTH-LOOKUP | 登录改私有用户名密码；**每次注册**需校邮 OTP；仅独立恢复凭据能重置旧号；现行产品规则已同步，精确协议见本文所链规格 |
| 账号模块 AUTH-INPUT／DELIVERY／ABUSE | 严格后缀、验证码五分钟、获取间隔六十秒、三错锁五分钟保留在每次注册的 V 侧 |
| 账号模块 AUTH-DEVICE／RENEW／DRAFT／INTENT | 单设备、三十天及活跃静默续期、草稿隔离、认证后回原意图保留；“邮箱重验”字样改用户名密码 |
| 账号模块 ACCOUNT-CLOSE／WAIT／RETURN | 七天缓冲、禁言／封禁与旧公开内容占位保留；正式注销释放槽位后，同邮箱**重新收码**建全新号 |
| [审核模块](modules/moderation.md) | 禁言允许申请注销，封禁阻止；注销后不自动把旧号处罚挂到无旧新映射的新号 |

若生产已经有旧账号，必须先用旧号的既有合法控制凭据证明归属，再绑定私有用户名和密码；不能凭新邮箱 OTP 自动认领旧号。没有证据表明当前已有必须迁移的真实生产账号。

## 11. 实施前安全评审与验收

- [ ] 验证 V 同一精确邮箱并发签发只得到一个槽位、不同邮箱不得共用一个槽位，已释放槽位不可重签，原响应可重试；别名、大小写和学校邮件转发规则按产品文案如实呈现。
- [ ] 审核每次注册的新生 bootstrap 公钥、固定作用域 SHA-256 槽位等式、签名消息固定且全用户共用密钥、无可用来泄露邮箱的附加字段；验收 C 业务库与管理端无槽位接口。
- [ ] 用恶意 V 测试同槽位换公钥攻击被 C 拒绝；同时承认其自造新槽位仍可注册。审核真实 C 挑战、不可修改开户意图、持钥证明及不在证明中公开密码快速散列。
- [ ] 审核 C 原子建号、唯一槽位／用户名、响应丢失不重发会话、取消未消费资格与开户竞态，以及 `RETIRED/CLOSED` 终态拒绝旧资格重放。
- [ ] 演练七天注销、主动登录取消、新封禁竞争、关闭事务后签名、释放 outbox 重试、V 收据验签与当前槽位原子释放；确保旧号有效时配额绝不开放。
- [ ] 在 V、C、单侧备份、双侧备份、日志和普通管理权限下实际尝试邮箱—账号连接；单侧不应获得完整映射，双侧可连接应被清楚记录为限制。
- [ ] 核实两组织的法律主体、人员、云账户、监控及签名密钥分隔；对共同控制面与数据泄漏做事故演练。
- [ ] 校准 Argon2id、密码长度与限速，验证普通调用的用户名枚举防护、恶意 V 的探测边界、恢复码盗用和旧会话撤销；用户测试全凭据遗失与同邮箱锁定说明。
- [ ] 演练每次注册 OTP 投递未知、重复收码、拒绝资格和同邮箱注销后立即重注册；释放未确认时显示明确待处理状态。
- [ ] 验证例行签名密钥轮换不改变已建账号、未消费资格或地址占用；疑似泄漏时停验旧钥；灾备恢复后 `RETIRED/CLOSED` 不能倒退，旧释放凭据不能释放新槽位。
- [ ] 对外隐私承诺用第 2、7、9 节边界复核；不要把公钥导出槽位或两个服务部署包装成密码学意义的串通下匿名。

## 12. 最终决定

注册界面每次都验证当前学校邮箱，再以客户端一次性密钥绑定的资格建**全新私有用户名＋密码账号**；登录界面只验证用户名和密码。同一精确邮箱地址同时最多一个有效账号的配额依赖诚实 V，正式注销后由受控释放流程允许再次收码注册。邮箱系统或 V 可造新资格但不能只凭邮箱接管已有账号；公钥散列绑定另防它抢用户的同一槽位。V 与 C 任一单侧没有完整邮箱—账号映射；两侧串通或共同泄漏能凭槽位连接，这是当前取舍。上线前必须把[注册协议](auth-privacy-registration-protocol.md)、[恢复策略](auth-privacy-recovery-decision.md)与[逻辑数据/API 契约](auth-privacy-data-api-contract.md)转成可执行 OpenAPI／迁移，落实独立 V/C，并完成第 11 节及独立安全评审。

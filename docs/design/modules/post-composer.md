# 新建帖子

更新：2026-10-08。当前规则只在本模块维护。

## 范围

本文件是新建帖子内容编辑、发布与草稿规则的当前维护处。适用于首版手机 App；F1-04文字编辑正常态、F1-05键盘状态与F1-06发布确认v1均已正式定稿。F1-07保存失败及F1-08／09／10身份三状态已出图／DRAFT，见[本批评审](../ui-reviews/post-identity-and-save-states-v1.md)，尚未定稿。图稿定稿不等于代码实现或平台验收通过，当次Flutter文字切片未实现、业务验收NOT_RUN。通道入口见[导航与通道](navigation.md)，标签见[分类与标签](tags.md)，昵称和头像见[预设身份](identity.md)，已发布内容的编辑、删除见[内容管理](moderation.md)。

## 已确认规则

### POST-01：标题与正文

- 标题必填，最多十五字；正文最多三千字，接近上限时显示字数提示。正文和图片至少提供一种，允许“标题加图片”且正文为空，不能只发标题。
- 标题全部由用户手写；纯图片且无正文时也必须手写标题。

### POST-FLOW-01：分步发布，标题与正文顺序自由

- 用户接受内容编辑与发布确认两步，同时明确可以自行选择先定标题还是先写正文。
- 内容编辑阶段允许先写标题，也允许先写正文并配图，不强制按“正文 → 标题”的顺序填写。
- 发布确认页从上到下依次呈现标题、标签、发言身份，底部固定“确认发布”按钮，不展示帖子预览。点击该按钮直接提交帖子，不追加发布确认步骤；标题仍为发布必填。
- 确认页的身份区域显示当前身份头像和昵称，点击打开附件式底部身份列表；选中后收起并回到确认页，选择身份本身不发布。
- 标签区域点击后打开[标签模块 TAG-SELECT-01](tags.md)规定的底部选择面板，完成选择后返回确认页。
- 通道归属必选，自定义 `#标签` 选填、最多三个；不增加中间分类或主题屏蔽，规则见[标签模块](tags.md)。旧标签面板与 `#tag` 输入的具体交互衔接留给 UI 设计。
- 编辑页标题在上、正文在下，图片接在正文后；标题可暂时留空，用户自由选择先写标题还是正文。右上角“下一步”进入发布确认页。
- 不增加“先标题／先正文”的选择弹框；标题在实际发布前仍须填写。
- 从发布确认页返回编辑页时，保留标题、正文、图片及顺序、已选标签和身份。
- 点击“确认发布”后立即回到当前通道，发送在后台继续；成功后按[导航模块 FEED-01](navigation.md)在“最新”列表顶部显示帖子，失败时提供重试。用户已滚动到其他位置时不强制拉回顶部。

编辑已发布帖子时，字段权限、原身份与互动保留、“已编辑”标记由[内容管理 EDIT-POST-01](moderation.md)维护，不将编辑另作新帖发布。

### POST-MASK-MANAGE-01：从发布身份列表进入管理后保留内容

- 发布确认页的身份列表提供“管理身份”，进入现有身份管理页；返回后保留标题、正文、图片与顺序、标签和通道。
- 原选择仍有效就保留；用户可选择新建的有效身份后再发布，不因创建身份自动选择并发表。身份数量与创建间隔继续执行，原选择失效按既有规则重选。

### POST-PENDING-01：后台发送中的本人卡片

- 确认发布后立即在“我的／自己的帖子”出现仅本人可见的转圈卡片，可查看本次提交内容；退出 App 后任务入口仍保留。
- 可以检查任务状态，也可以取消本次上传／发布。结果未知时核对原任务，不重复提交、不编辑或直接删除处理中卡片；不能仅凭客户端点击取消宣称服务端已经取消。
- 服务端确认成功后转正式帖；确认失败后转 POST-FAIL-01 失败卡片。成功后的帖子仍可按内容管理规则编辑。
- 用户主动取消成功不生成失败卡片；清理本次未公开任务的临时上传文件，保留草稿原始图片。已由服务端确认成功的结果以服务端最终状态为准，不将成功帖子当临时任务清理。
- 登录失效后，服务端**已完成授权并持久提交**的任务继续处理；重新登录原账号后在“我的”核对状态，不能换账号或身份重发。接受事务须固定不可修改的标题、正文、身份、通道与图片顺序／大小／内容散列清单；后到的上传只能用绑定该任务和清单项的短期受限权限补齐**原定字节**，worker 公布前逐项核验，不能靠旧会话或上传入口改写已授权内容。退出、换机或密码重设不取消既有任务；申请注销或被禁言／封禁时仍未公开的任务按当前权限取消或转失败并清理临时上传，不等待七天截止；只有此前已经公开的帖子按注销占位与治理规则处理。未完成上传的重试与清理细节待实现设计。
- 明确失败后可修改内容重试或删除失败卡片；删除后本人失败入口不可恢复，不改变服务端失败任务记录。成功公开与通道展示按 POST-FLOW-01。

### POST-FAIL-01：失败帖子在“我的”中继续处理

- 发帖失败后，在“我的／自己的帖子”保留内容卡片，标记“发布失败”；点开可查看内容并重试，不增加独立失败栏目。
- 明确发布失败后，可修改标题、正文、图片和标签再重试；原发送身份及通道固定，不能借失败修改换身份或转投其他通道。结果未确定时不直接当作失败另发。
- 重试沿用原发送身份和内容归属；原身份已删除则遵循[身份模块 MASK-TASK-01](identity.md)，停止重试，并按 MASK-FAILED-POST-CLEAR-01 清除本人列表中的明确失败帖。
- 此卡片是本人处理失败任务的入口，不视为帖子已公开；也不作为可随意更换身份的普通草稿。具体卡片位置、排序和失败提示样式待设计。

### MEDIA-01：帖子图片

- 首版帖子支持文字与图片，每篇帖子最多九张图片。
- 一篇帖子的全部配图准备好后才公开完整帖子，不先展示缺图版本；例如九张中两张上传失败，仅重传失败的两张，保留已成功图片及其顺序。后台发送和失败入口仍按 POST-FLOW-01、POST-FAIL-01 执行。
- 编辑页采用三列图片缩略图，每张右上角提供移除入口；长按拖动调整顺序。未满九张时，末尾显示“＋”入口继续添加。
- 发布后的多图查看规则见[帖子详情 DETAIL-MEDIA-01](post-detail.md)，评论和回复的图片上限与界面由[评论与回复](comments.md)独立维护。
- 首版不支持视频和投票。

### MEDIA-SELECT-FAIL-01：选图读取失败不丢其他内容

- 只标记无法读取的那张图片，允许移除或重选；其他已选图片及顺序、已写文字继续保留。
- 此规则处理选图读取失败，不把整篇内容清空；点击发布后的上传失败和后台发送仍按 POST-FLOW-01 处理。

### SCOPE-01：发布信息与草稿

- 发布流程包含标题、正文、通道、自定义标签和本次发言所选身份；具体必填性以对应规则为准，不将所有字段推定为必填。
- 自动保存帖子草稿；退出交互按 POST-DRAFT-01 执行，展示位置、排序与发布成功后的列表更新由[个人内容与设置 PERSONAL-DRAFT-01](personal.md)维护。
- 从通道内发帖默认归入当前树洞；入口位置与通道约束由[FEED-01](navigation.md)维护。
- 创建新帖时，如果账号已有身份，从设置中已有的预设身份里选择；如果账号还没有身份，先完成基础身份设置。身份在实际点击确认发布时绑定为该帖身份，遵守[身份模块 MASK-01、MASK-02](identity.md)。该身份同时作为自己后续参与此帖的固定身份；具体选择控件待设计，默认值由身份模块维护，不再采用每帖临时取名流程。

### POST-IDENTITY-GATE-01：首次发帖前设置身份并返回原操作

- 无身份账号可以浏览导航树、通道和帖子；点击新建帖子后，只有在继续到需要公开发送的步骤时才进入基础身份设置，不在登录后强制创建身份。
- 进入身份设置前保留标题、正文、图片、通道和标签等当前输入；完成身份设置后回到原来的发布确认或编辑步骤，输入和发布意图不丢失。取消设置则返回原操作，不创建身份、不发送帖子。
- 已经在该帖绑定身份的账号不能在发帖确认页改用另一身份；服务端按“账号 + 帖子”唯一绑定拒绝换身份请求。发帖身份与后续主评论、楼中楼回复的帖内身份一致。

### POST-DRAFT-01：有内容时退出自动保存

- 写了内容后退出发帖，正常保存成功时自动保存草稿并直接返回，不再弹出是否保存的询问；明确保存失败时按 POST-DRAFT-SAVE-FAIL-01 处理。
- 自动保存用于保护中途退出或登录失效时已写内容；重新登录原账号返回编辑、换账号不带入草稿按[账号模块 AUTH-RECOVER-01](accounts.md)执行。草稿列表和排序由[个人内容与设置](personal.md)维护。
- 发布成功后原草稿转为正式帖；确认发布后立即返回通道、后台发送和失败可重试的规则继续按 POST-FLOW-01 执行。
- 点击“我的”中的草稿恢复文字、图片顺序、标签及仍有效身份；原身份删除时按 POST-DRAFT-IDENTITY-01 重选后发布。
- 退出 App 或重启手机后，在同一手机仍能恢复草稿文字、已选图片及编辑顺序；首版先保证同机持久保存。
- 同机持久保存必须保留可再次使用的已选图片，不能仅依赖重启后失效的临时选择结果；图片尚未上传不取消此保存要求。
- 空白编辑页和未完成图片读取等异常处理待设计；保存失败按 POST-DRAFT-SAVE-FAIL-01，本次不承诺草稿跨设备同步或卸载后的恢复。

### POST-NEW-ENTRY-01：通道加号始终新建

- 点击通道“＋”始终打开一篇新的帖子，不自动恢复该通道已有草稿，不覆盖旧草稿。
- 续写已有草稿从“我的”对应草稿进入；新建稿的通道仍为当前通道。

### POST-DRAFT-SAVE-FAIL-01：草稿保存失败时留在编辑页

- 用户退出编辑时，若因存储已满等原因明确无法保存草稿，留在编辑页，提示保存失败并保留当前内容，不直接退出造成未保存修改丢失。
- 提供重试、复制文字和放弃退出；说明放弃退出可能丢失本次未保存内容，由用户明确选择是否放弃。
- 此为明确保存失败时的例外；正常退出仍按 POST-DRAFT-01 自动保存并返回，具体反馈样式待设计。

### POST-DRAFT-IDENTITY-01：草稿所选身份被删除

- 未发布草稿的文字和图片保留，原身份失效；再次发布前重新选择一个仍存在的身份，不自动换身份发布，不清空草稿。
- 图片顺序、标签等已编辑内容继续保留；草稿仍从“我的”进入。
- 本规则仅处理尚未实际提交的草稿；已发送、结果未确认或失败待重试内容不能作为普通草稿换身份重发。原身份删除后的任务处理遵循[身份模块 MASK-TASK-01](identity.md)。

- **页面布局**：编辑页标题、正文、图片顺序及右上角“下一步”，确认页标题、标签、身份顺序及底部固定发布按钮均已确认；F1-04编辑正常态与F1-05键盘状态v1已正式定稿，F1-06发布确认已出图／待评审，保存失败图尚未生成。选图、拖动反馈、实际控件尺寸和平台避让仍在后续设计／实现时校准；图片三列排布及返回编辑保留内容已确认。
- **标题填写**：标题由用户手写，最多十五字；不依赖自动生成或外部建议。
- **图片与草稿**：最多九张、三列缩略图、右上移除、长按排序和末尾添加已确认；同机持久保存图片及保存失败留在编辑页按 POST-DRAFT-SAVE-FAIL-01 已确认。尺寸、格式、选图细节和失败视觉待设计；草稿删除按个人模块 PERSONAL-DRAFT-DELETE-01 执行。点击草稿进入编辑页并恢复内容，按[个人模块 PERSONAL-DRAFT-01](personal.md)执行。
- **发布行为**：立即回通道、后台发送、图片齐全后公开、发送中卡片按 POST-PENDING-01、成功转换、失败卡片与原身份重试已确认；成功插入“最新”列表顶部但不强制回滚。明确失败后允许修改文字、图片和标签，身份与通道固定；失败视觉、排序及结果未知继续核对真实状态；处理中卡片按 POST-PENDING-01。

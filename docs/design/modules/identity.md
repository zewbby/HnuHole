# 预设身份与匿名边界

更新：2026-09-23。当前模型为最多三个预设身份、同一账号在每帖固定使用一个身份；私信仍按身份对隔离并可跨帖延续。旧讨论与旧图仅用于追溯，不作为现行规则。

> 2026-10-08图稿接续：用户明确将身份三态定稿，F1-08身份选择v1／F1-09首次尚无身份v1／F1-10草稿原选择失效v2均FINAL／USER_APPROVED，见[身份状态定稿](../ui-reviews/post-identity-and-save-states-v1.md)及UI产品图正式文件。选择与重新选择发生在实际受理之前，不表示已绑定，也不能为已受理任务更换身份。此处仅登记图稿，不修改身份数量／创建／删除规则或既有验收证明范围，Flutter社区业务与平台验收NOT_RUN。

## 范围

负责预设身份的数量、昵称与头像、发言身份选择，以及 behindMask 的身份隔离。身份管理入口见[个人内容与设置](personal.md)，发帖和评论分别见[新建帖子](post-composer.md)、[评论](comments.md)，私信会话见[私信与会话](messaging.md)，切换收件身份见[消息中心](messages.md)。

## 已确认规则

### MASK-01：至少保留一个，最多三个预设身份

- 每个有效登录账号至少保留一个身份，最多设置三个身份，原始身份占一个名额，另可设置两个身份。不能删除最后一个身份；注销整个账号与删除身份仍为不同动作。
- 身份预先在自己的设置中管理，包含昵称和头像；首次参与一篇帖子时从已设置的身份中选择，后续遵循 MASK-02 固定沿用。
- 每个身份是可持续使用的独立面具，可以用于不同帖子；不再为每个帖子临时建立一个新的身份。
- 三个身份属于同一个内部登录账号，并不要求用户分别注册或登录三个账号。账号访问规则见[账号与访问](accounts.md)。
- 初次只设置一个基础身份，其余两个名额按需在设置中创建，不要求一次填满三个。自己的设置中可以区分原始身份和其他身份；对外只显示昵称与头像，不标注本体。创建页面的具体控件待设计。

### MASK-INITIAL-01：首次公开发言前完成基础身份设置

- 新用户首次完成校邮验证、账号注册并建立会话后，可以先进入导航树和通道浏览，不强制立即创建身份；首次进行需要公开身份的发言时，再设置原始身份。昵称必填，遵守 MASK-NAME-01，头像可使用默认值，不强制上传。
- 完成身份设置后继续原本要进行的公开发言操作；已有基础身份的用户再次登录不重复设置。没有身份时不影响导航和阅读，但不能把账号会话当作公开发言身份。
- 首次只建立一个基础身份，其余身份按需创建；中途退出后，登录仍有效则恢复基础身份设置及同机已填内容，失效则先用原账号的用户名密码重新登录；完成前不重复建账号。默认头像样式待设计。

### MASK-CREATE-01：第三个身份创建后，新增身份间隔六个月

- 初始原始身份计入创建次数；首次成功创建第 3 个身份后开始等待六个月，满六个月才可以再次创建。这里按累计成功创建次数判断，删除不减计数，不能在凑满前反复删建绕过限制。
- 进入限制后，每次成功创建新身份重新计算六个月；等待期满也只能在当前身份少于三个时创建，不增加同时最多三个的上限。
- 删除只释放名额，不重置或提前结束等待时间；创建失败不消耗创建机会。至少保留一个身份的删除下限继续生效。
- 以六个月为间隔，不按上半年／下半年固定重置。设置页保留“添加身份”入口，等待期间显示“可于某年某月某日创建”；月份边界与服务端时间判断另行实现。
- 示例：2026-09-13 创建第 3 个身份，最早 2027-03-13 可再创建；若实际到 2027-04-01 才成功创建，则下次最早为 2027-10-01。期间仍须先有空余名额。
- 昵称每三十天修改一次、头像随时更换仍按 MASK-EDIT-01 执行；修改资料不创建新身份，也不重置创建间隔。
- 整账号按[账号模块 ACCOUNT-CLOSE-WAIT-01](accounts.md)经历七天缓冲期并正式注销后，同邮箱可立即重新注册，新账号的身份创建次数及等待期重新开始。此例外不改变旧账号存续期间的限制，也不重置尚未失效的管理处罚。

### MASK-NAME-01：本人身份不重名，不限制其他用户

- 同一账号下的各个身份不能使用相同昵称，便于本人选择和切换。
- 不同用户之间允许昵称相同，不因名字被其他用户使用而要求改名；同帖也不再执行旧的临时改名限制。
- 重名不代表同一个身份；内容归属、回复对象和私信对象均不能仅凭昵称判断。
- 昵称长度为二至十二个用户可见字符；允许中文、英文字母、日语、韩语、数字及 Unicode 标点类别，英文字母区分大小写。拒绝所有位置的空格、控制字符、表情及不可见特殊字符；同账号各身份按有效输入判重，不限制其他账号同名。
- 非法字符在输入框附近即时提示，只拒绝非法字符本身并保留合法输入，合法字符可继续输入；存在未处理的非法输入时不能完成。达到十二字后忽略后续字符并提示已达上限，输入法组合中的具体计数实现待细化。

### MASK-EDIT-01：昵称与头像修改

- 允许修改已有身份的昵称和头像；同一身份的帖子、评论及私信统一展示修改后的资料。
- 每个身份的昵称在任意连续三十天内最多修改一次；成功改名后需满三十天才可再次改名，不按自然月重置。违规昵称被审核员强制重置后的合规修改为例外，按[管理 MOD-PROFILE-01](moderation.md)执行。
- 头像可以随时更换，不受昵称修改间隔限制；仍须遵守正常的头像素材与上传规则。
- 修改资料不创建新身份、不切断已有联系；原有会话和消息归属继续保留，身份之间不因此合并。
- 本人各个身份的昵称仍须遵守 MASK-NAME-01，不能通过改名形成同账号下的同名身份。

- 违规昵称或头像可由审核员重置为中性占位并通知本人；该处置不删除身份，也不改变帖内身份和会话归属。举报、修改例外与处罚规则统一由[管理 MOD-PROFILE-01](moderation.md)维护。

### MASK-02：同一账号在每帖固定一个身份

- 每个账号在同一篇帖子内只能使用一个预设身份。发帖时确定楼主身份；参与他人帖子时首次确定自己的身份，此后该帖内所有主评论、楼中楼回复及从该帖发起的私信联系均沿用这一身份。
- “首次确定”发生在该账号第一次实际公开发送该帖的内容时：如果账号尚无身份，先创建基础身份；如果已有身份，从现有身份中选择。仅打开身份设置、选择身份或填写评论不会绑定帖子身份。
- 一旦该账号已经在该帖成功发过主评论或楼中楼回复，后续在该帖的主评论、任意楼中楼回复以及从该帖继续发起的互动都直接复用已绑定身份，不再重复弹出身份设置，也不能因为更换回复对象、重新进入帖子或切换消息收件身份而更换。
- 服务端按“账号 + 帖子”强制唯一身份绑定；客户端隐藏已绑定帖子的身份切换入口，服务端拒绝任何试图用另一身份发送的请求。
- 在不同帖子里可以选择不同身份，也可以继续使用同一身份；同帖固定不意味着每帖都创建新身份。
- 尚未确定该帖身份时，新帖或首次评论默认显示最近一次公开发言使用的身份；还没有公开发言记录时默认选中原始身份，并清楚展示头像与昵称，用户可在首次提交前更换。选择本身不发布；已有该帖身份后不再提供换身份入口。
- 应作为默认值的身份已删除时（包括首次公开发言前删除原始身份），按 MASK-DEFAULT-01 处理，不得选择或恢复已删除身份。首次私信仍按 DM-IDENTITY-02 执行。
- 输入区显示该帖固定身份的昵称与头像；后续发言直接沿用，不要求重复选择。资料修改仍遵循 MASK-EDIT-01，不因改名或换头像视为另一身份。
- 从提醒返回继续回复、从帖子昵称进入私信、从其他页面再次进入帖子，都不能改变已确定的该帖身份。消息页切换收件身份也不改变该帖身份或首次公开发言的默认值。
- 从帖子首次私信时的身份选择由[私信模块 DM-IDENTITY-02](messaging.md)维护；从提醒继续回复见[消息中心 MESSAGE-IDENTITY-01](messages.md)。
- 点赞按[帖子详情 LIKE-ACCOUNT-01](post-detail.md)记录，不要求先选身份，也不单凭点赞确定该帖发言身份。
- 仅选择身份、尚未发送就退出时，不固定该帖身份；服务端完成权限、内容和身份校验并接受发送任务时，与发送任务原子地写入帖内身份绑定。
- 服务端在接受任务后即使异步发布失败，也保留该帖身份，重试必须继续使用原身份；如果请求在校验阶段被拒绝、没有形成发送任务，则不产生绑定。不能通过重试、删除评论或取消点赞重新选择身份。
- 并发请求只能提交一个“账号 + 帖子”绑定；客户端回执延迟、网络重试或离线恢复都不得形成同账号在同帖使用多个身份的结果。

### MASK-DEFAULT-01：默认发言身份失效后重新选择

- 新帖或首次参与另一篇帖子时，若原本应使用的默认身份已删除，仍有多个身份就要求用户重新选择；只剩一个身份时直接展示该身份的头像与昵称。
- 不将消息页当前收件身份当作发言后备值，也不直接套用“我的”顶部展示身份的替换规则；用户确认发送前应能看清本次身份。
- 本规则仅补充尚未固定帖内身份时的默认选择；已有该帖身份和已经提交的失败任务仍按 MASK-02、MASK-TASK-01 执行，不能因此换身份重试。普通草稿原身份失效按发帖模块 POST-DRAFT-IDENTITY-01 处理。

### MASK-DELETE-01：使用过的身份也可以删除

- 已经发表帖子、评论或发送私信的身份同样允许删除，但删除后必须至少剩余一个身份；不以是否使用过限制删除。
- 删除具体身份与注销整个账号是不同动作；删除身份后旧帖子、评论继续保留，头像改为表示注销状态的统一头像，昵称改为编号，不继续展示原头像与昵称。编号具体格式待设计，不能按登录账号共用一个编号而暴露多个面具的关联。聊天框与记录清理按 MASK-DELETE-CHAT-01，不再套用公开内容保留规则。
- 删除身份立即释放名额；能否创建新身份还须满足 MASK-CREATE-01 的频率限制。新身份从零开始，不继承旧聊天或旧内容。
- 曾绑定已删除身份的旧帖子仍可阅读，但不能换新身份继续在这些帖子发言；删除不解除同账号每帖固定身份约束。
- 原始身份也可删除，但必须还有其他身份；删除后优先切换到最近使用过的剩余身份作为“我的”顶部展示，都未使用过则选创建较早的身份，不要求事先手动选择。
- 删除身份后点击时的提示遵循注销状态反馈方向，具体文案需区分单个身份删除和整账号注销，尚未定稿。


### MASK-DELETE-CHAT-01：删除身份清除该身份聊天框和记录

- 用户第六轮明确：“聊天记录只能通过用户自己持久化到本地，删除身份后理论上该身份产生的聊天框和记录都应该删除”。聊天历史由用户侧本地持久化，见[DM-STORAGE-01](messaging.md)。
- 删除身份后，本人 App 中该身份产生的聊天框和聊天记录全部清除，不提供已删除身份的成功聊天只读入口，也不让新身份继承。此规则替代原“删除身份后保留聊天并考虑本人归档”的方向。
- 删除身份不清除对方已有本地聊天记录；对方仍可查看原有记录，该身份按删除占位展示，不能继续向其发送。
- 本人为该身份各段会话填写的私人备注随身份一起清除，不留备注归档。用户独立备份或导出文件的能力与处理另行讨论，不承诺删除设备外独立保存的副本。
- 删除聊天与删除身份仍是不同动作：身份存在时，普通删除聊天保留备注；删除身份则清除本人对应聊天和备注。已授权提交的举报证据按举报规则独立处理，存留范围与期限继续待细化。

### MASK-DELETE-CONFIRM-01：删除身份前说明影响

- 确认界面显示待删除身份的头像和昵称，说明“旧内容仍保留，无法再用此身份发言”；同时说明本人该身份的聊天框、记录和私人备注将被清除，明确发布失败的帖子也从本人列表清除，对方已有本地记录保留；若尚在创建等待期，同时显示下次可创建身份的日期。
- 底部提供“取消／删除身份”；仍须遵守至少保留一个身份和创建间隔规则。

### MASK-TASK-01：身份删除后停止未成功任务的重试

- 原发送身份删除后，该身份尚未发送成功的帖子、评论或私信停止继续重试，提示“身份已删除”；不能自动换成其他身份补发。
- 评论／回复发送与身份删除几乎同时发生时，按服务端确认顺序判定：发送先成功，内容保留并按身份删除后的占位规则展示；删除先成功，未成功任务停止重试，确认未成功后按 MASK-TASK-CLEAR-01 清除本人侧记录及入口。客户端回执迟到不改变服务端已经确认的成功结果。
- 已成功公开的帖子、评论按 MASK-DELETE-01 保留；私信聊天框和记录按 MASK-DELETE-CHAT-01 清除。停止重试与清理记录分别处理。
- 尚未实际提交的普通帖子草稿仍按[发帖模块 POST-DRAFT-IDENTITY-01](post-composer.md)保留内容并重选身份；不能把已经提交过的任务改作普通草稿绕过原身份约束。
- 发送结果未知时须核对真实结果，不能直接当作失败或换身份重发；明确失败的评论与回复按 MASK-TASK-CLEAR-01 清除本人侧记录。第五轮并发场景针对评论／回复，其他失败任务的用户侧处理、具体并发实现仍待细化。

### MASK-TASK-CLEAR-01：身份删除后清除本人侧失败评论记录

- 删除发送身份后，本人侧直接清除该身份已明确失败的评论与回复记录及处理入口，不新增“已停止发送”的只读归档，也不提供继续复制或重试的入口。
- 用户明确区分用户侧清除与系统侧存留：系统侧仍保留对应记录；具体保留范围、保存期限及后续清理待定，不据此承诺永久留存。
- 系统中仍有记录不等于该失败内容已经公开或发送成功。已成功公开内容继续按 MASK-DELETE-01、MASK-ARCHIVE-01 保留，私信按 MASK-DELETE-CHAT-01 处理；未知结果继续核对，未提交的普通帖子草稿仍按既定规则保护。
- 本规则针对失败评论与回复；明确失败帖的本人侧清除按 MASK-FAILED-POST-CLEAR-01；私信由第六轮 MASK-DELETE-CHAT-01 单独确定删除身份后清除对应聊天框和记录，不再从失败评论规则推导。

### MASK-FAILED-POST-CLEAR-01：删除身份清除本人侧明确失败帖

- 删除身份后，一并清除本人列表中属于该身份、已明确发布失败的帖子；不提供从该入口找回、继续重试或换身份发送的操作，并在删除身份确认中说明。
- 尚未实际提交的普通帖子草稿继续保留，允许重选身份；成功公开的旧帖继续按 MASK-ARCHIVE-01 处理。发送结果未知先核对，不直接套用明确失败清除。
- 本项确认本人列表与操作入口的清除，不据此承诺系统记录永久保留或立即物理删除；相关存留和实现待细化。

### MASK-ARCHIVE-01：删除身份后旧帖从“我的”移除

- 删除身份后，该身份发表的旧帖不再出现在“我的／自己的帖子”列表，不保留该身份的旧帖归档入口。
- 这是本人列表展示的变化，不等同于删除公开帖子；旧帖继续按 MASK-DELETE-01 保留，并展示该身份的注销占位。
- 从通道等其他入口再次打开旧帖，本人仍可删除，但不能编辑，也不会将帖子重新放回“我的”；删除帖子按[内容管理 DELETE-POST-01](moderation.md)执行，不解除每帖固定身份限制。

### PRIVACY-02：按身份隔离，双方对称

- 用户已明确接受：同一对身份从不同帖子联系时，进入同一段私信；在其他帖子使用另一身份联系时，则属于另一对身份的独立会话。同一帖内不能借此换身份，遵循 MASK-02。具体会话规则由[私信模块](messaging.md)维护。
- 用户主动在不同帖子重复使用同一个身份时，对方可以识别、继续联系这同一副面具。新设计不再承诺“只要换帖子，就必然像换了一个人”。
- 不同身份之间保持隔离。平台不通过共同账号、关系标记、合并聊天、其他身份列表等方式提示它们属于同一个人；双方都遵守这一边界。
- 本人的身份切换列表仅本人可见；对外不标注“本体”“身份二”等能表明内部槽位或账号关系的信息。
- 不提供公开个人主页、历史帖子列表或按昵称检索某身份全部历史发言的入口。持续使用同一身份不赋予他人查看历史内容的权限。
- 邮箱及邮箱账户名称不自动作为公开身份名称；“本体账号名称”也不等于公开真实姓名或邮箱。
- 私信拉黑允许后台按账号执行接收限制，但前台不公开关联身份，详见[内容管理 BLOCK-DM-01](moderation.md)。
- 用户主动复用头像、昵称或自行透露信息仍可能被他人识别，设计不承诺绝对无法关联。

## 待确认

- **重名细节**：昵称二至十二个可见字符、中英日韩/数字/Unicode 标点、禁止空格和非法字符、大小写区分及上限反馈已定；输入法计数实现和相似昵称辅助辨认待设计。
- **身份生命周期**：至少一个、匿名占位、旧帖移出“我的”后可删不可编辑、自动切换与创建限制已确认；删除确认按 MASK-DELETE-CONFIRM-01，失败任务按 MASK-TASK-01。具体图稿与并发异常待细化。
- **首次身份选择**：首次公开发言默认原始身份、之后沿用最近公开发言身份；默认身份已删除时，多个剩余身份重选、只剩一个直接展示，按 MASK-DEFAULT-01。仅选择不绑定，实际发送即绑定且失败沿用；取消返回和并发绑定待细化。
- **公开标识**：楼主标识按[评论模块 COMMENT-AUTHOR-01](comments.md)执行；其他关系标记同样不得揭示不同身份属于同一账号。
- **设置界面**：首次昵称必填、头像可默认及完成后进入社区按 MASK-INITIAL-01 已定；字符范围已定，随机昵称按钮的位置和默认头像样式待设计；昵称二至十二字与剩余字数提示已确认。
- 昵称修改间隔的界面反馈、提交失败及同时修改昵称和头像的保存行为待设计；身份重建遵守 MASK-CREATE-01，不能因资料修改或删除而绕过限制。
- 普通审核员不可查看其他身份，所有管理端不可获知完整验证邮箱；规则与实现边界见[管理模块](moderation.md)及[账号模块](accounts.md)，不得另设后台特权恢复完整邮箱展示。

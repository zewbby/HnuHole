## 范围

独立的“消息”模块集中处理私信、点赞消息、评论与回复相关入口；[个人内容与设置](personal.md)负责本人头像名称、自己的帖子、收藏帖子及设置入口；[私信与会话](messaging.md)负责具体聊天及联系规则。

## 已确认规则


### MESSAGE-01：点赞、回复与私信归入消息

- 消息模块集中承载私信、点赞、评论与回复；“系统通知”用于举报反馈、违规处理结果及评论／回复发送失败的处理入口。
- “点赞”是收到的点赞提醒，评论与回复包含收到的互动和本人发言回访，按 MESSAGE-REPLIES-01 分区；“私信”进入对应会话。
- 消息首页上方的“点赞”“评论与回复”“系统通知”三个入口并排，图标在上、文字在下；点赞和评论回复显示各自未读数，系统通知有未读时显示小红点。下方为私信列表，身份范围按 MESSAGE-IDENTITY-01 和 MESSAGE-SYSTEM-01 执行。

### MESSAGE-SYSTEM-01：系统通知

- “系统通知”位于消息首页顶部，与点赞、评论与回复并列；有未读时显示小红点，用于举报反馈、违规处理结果及评论／回复发送失败。发送失败流程见 MESSAGE-COMMENT-FAIL-01。
- 违规处理通知提供申诉入口，规则由[内容管理 APPEAL-01](moderation.md)维护。
- 举报处理结果详情 v1 已获用户确认：单条通知详情展示举报对象、举报类别、处理结论及简短说明，不添加举报方申诉或重复举报按钮；结果字段与隐私边界按[REPORT-PRIVACY-01](moderation.md)执行。
- 帖子相关的举报反馈跟随对应身份；账号级处罚通知在任何身份下都能看到，切换身份不使这类通知消失。
- 系统通知按收到时间从新到旧排列；打开具体条目才算已读，已读后保持原位置，进入列表不批量标记。账号级通知已读全身份共用，切换身份不重新产生未读。
- 2026-09-20 用户明确系统通知不分类、不分栏，直接按发生的具体通知逐条展示为单一时间流；同类通知也分别占一条，不使用“发送失败／举报结果／违规通知”等分类入口或分组。每条直接表达具体事件，点击进入该条详情。旧列表 v1 的大图标和分类式标题呈现作废；业务事件类型仍用于确定处理流程，不作为前台分类导航。
- 系统通知时间流 v2 已获用户“可以，下一版”确认：时间、具体事件句子与简短处理提示逐条排列，不使用大图标或分类入口；未读点仅标识尚未打开的具体通知。
- 这是 App 内的通知分类，与操作系统推送区分；点赞、回复和私信仍按当前身份隔离。


### MESSAGE-COMMENT-FAIL-01：评论发送失败转入系统通知

- 2026-09-20 用户明确：评论或回复提交后明确发送失败时，弹出顶部消息提示，点击跳转到“系统通知”处理；不在评论与回复列表中展示失败项、失败标记或重试／删除入口。原“我发出的”失败状态稿和失败项混排问题作废。
- 系统通知中的失败任务沿用原发送身份归属；保留内容、图片、目标、重试／删除和身份失效清理规则，见[评论 COMMENT-FAIL-ENTRY-01](comments.md)。入口迁移不允许更换发送身份，不将失败内容当作已公开评论。
- “我发出的”只展示成功发表的记录，失败任务重试成功后才出现对应正常记录。结果未知仍先核对，不当成失败另发；顶部提示不直接重试。
- 此处“系统通知”指消息中心内的分类，顶部提示按 App 内提示设计；不据此新增操作系统推送。此次只迁移评论／回复的失败入口，发帖和私信失败流程不变。
- 点击顶部提示直接打开系统通知中的对应失败任务详情，显示原内容、回复目标及重试／删除；返回进入系统通知列表。若当前消息身份不同，按既有通知导航切到任务所属身份，不改变发送归属。
- 重试成功或用户主动删除任务后，移除该条失败通知；成功发表的评论在“我发出的”查看，删除表示放弃任务且不提供恢复入口。仅打开或阅读通知不移除任务，已读不等于已解决。用户于 2026-09-20 对上述两项均答复“推荐”。
- 系统通知发送失败详情 v1 已获用户确认：显示失败状态、时间、保留的发送内容与回复对象、来源帖，底部“删除”为次操作、“重试发送”为主操作；不提供切换发送身份。
- 顶部失败提示 v1 已获用户确认：失败图标、“发送失败”、说明“内容已保留，点击处理”和右箭头组成整块入口；不压暗背景、不在原页面列表插入失败项。提示覆盖顶部导航区域而不删除原导航，消失后恢复；显示时长及收起方式留到交互细化。

### MESSAGE-REPLIES-01：收到的与我发出的

- 进入消息中的评论与回复后，分为“收到的”和“我发出的”，默认显示“收到的”。
- “收到的”展示别人对本人帖子或评论的互动；“我发出的”提供自己发表过的评论与回复记录，供本人回访。
- “我发出的”仅展示当前身份成功发表的评论／回复，不显示发送失败任务、失败提醒或处理按钮，也不收录未提交的临时输入。失败处理移至 MESSAGE-COMMENT-FAIL-01 的系统通知，替代原失败项混排方案。
- 两个列表分别按时间从新到旧排列，每条展示相关昵称、评论内容与帖子标题；“我发出的”回复注明回复给谁。
- 两类列表仅展示当前身份内容，不增加“我的”回复页签；具体卡片排版待设计。
- 2026-09-20 用户明确：两个页签均属于当前身份，不在每条记录重复显示“收件：某昵称”或本人的收件身份小头像，页头也不显示“当前身份”。此修正替代此前逐条标注本人收件身份的要求，不改变身份归属及隔离规则。
- “收到的”每条在对方昵称旁显示对方的小头像；正文预览最多两行，超出省略，来源帖子标题一行。收到的 v2 图稿已获用户确认；头像／昵称的点击行为与整条提醒一致，按 MESSAGE-NAV-01 返回原帖，不设置独立私信入口，见[UI 评审](../../discussions/2026-09-20-replies-ui-review.md)。
- “我发出的”正常状态 v1 已确认：不重复展示本人头像昵称，以“回复 某昵称”或“评论了帖子”表达目标，时间靠右，正文最多两行、来源标题一行，不显示收到消息的未读红点。此图继续作为列表基准，失败任务在系统通知处理。

### MESSAGE-IDENTITY-01：消息全页按身份切换

- 用户在消息页切换身份时，私信、收到的点赞、收到的评论与回复、我发出的评论与回复一同切换，只显示当前身份对应的内容；替代此前点赞与回复汇总全部身份的方案。
- 点赞和回复入口的未读数随当前身份更新，其他身份的消息通过身份切换入口的未读提示保留可见性。此处管理收到的点赞提醒，不改变[帖子详情 LIKE-ACCOUNT-01](post-detail.md)中每账号每条内容最多一个赞的规则。
- 评论与回复只展示当前身份的记录，不逐条显示本人收件昵称或收件身份小头像；从前的逐条身份提示要求被 2026-09-20 用户修正替代。对方发言者的昵称与必要的回复关系继续显示，不混入其他身份的提醒。
- 从提醒进入内容继续回复时，使用收到该提醒的本人身份，即自己在该帖已确定的身份，遵循[身份模块 MASK-02](identity.md)。不提供改用其他预设身份的入口，也不因当前私信收件身份不同而更换。
- 消息分类与本人的身份切换列表仅本人可见，不向对方揭示账号下的其他身份。

### MESSAGE-MASK-01：切换消息身份

- 私信列表上方、点赞／评论与回复／系统通知三个入口下方提供身份切换入口，不显示“私信”标题。2026-09-20 用户认为原孤立小圆点不明显，明确要求改为显眼标识并附文字说明；旧“仅小圆点”约束撤回。
- 用户可切换至自己已设置的身份，作用范围为 MESSAGE-IDENTITY-01 规定的整个消息页；不将不同身份的内容混入当前列表。
- 切换入口须有可辨认的图标和文字，点击后从底部弹出身份列表，列表内继续显示各身份头像、昵称与选中状态。2026-09-20 用户确认 v2：整行可点击入口，包含切换图标、“切换身份”、说明“查看不同身份的消息”，右侧当前身份及下拉箭头。
- 沿用用户先前附件的底部身份列表：每行左侧头像、中间昵称及未读小红点，右侧选中圆标；当前选中身份使用本产品已有的冰蓝强调。点选后立即切换并收起面板，不增加确认步骤。
- 其他身份有未读消息时，身份切换入口显示小红点；展开列表后，有未读的身份也用小红点提示，无未读时红点消失。身份切换区域采用红点提示，不展示未读数量；私信会话行的未读数仍按 MESSAGE-ROW-01 展示。
- 交互参考用户提供截图，画面沿用本产品深色、银白文字和冰蓝强调的视觉体系；具体尺寸、间距与动效待设计。
- 身份数量、设置位置与公开隐私统一见[身份模块](identity.md)；会话归属由[私信模块 DM-PAIR-01](messaging.md)维护。
- 身份切换面板底部提供“管理身份”，进入设置中的身份管理页；新增、改名和删除统一在该页操作。
- 切换身份不意味着对应消息已被阅读；各身份的未读状态分别保留，按 MESSAGE-READ-01 仅清除实际打开的提醒或会话。

### MESSAGE-ROW-01：私信会话行

- 左侧显示对方头像与昵称，下方一行显示最近消息摘要；右侧显示时间和未读数。
- 最近消息为图片时，摘要显示“[图片]”。
- 本人当前消息身份在切换入口打开的身份列表中通过选中状态表示，不混入会话对方的昵称。
- 会话各行的头像、昵称、消息摘要统一对齐，时间和未读数靠右，使用很淡的分隔线区分会话。

### MESSAGE-MENU-01：长按会话菜单

- 长按私信列表中的某一会话行，在该会话附近弹出浮动菜单；采用用户附件的图标加文字、纵向排列与分隔线结构，颜色沿用本产品视觉。
- 菜单按顺序提供：设为免打扰、置顶、不显示、拉黑、删除；删除项用红色文字及图标强调。已开启的免打扰、置顶提供对应取消操作。

| 操作 | 行为 |
| --- | --- |
| 设为免打扰 | 关闭这一对身份会话的系统通知，消息仍接收并保留未读提示，不影响其他身份对的会话。 |
| 置顶 | 会话排在当前身份列表的置顶区域，未置顶部分按 MESSAGE-ORDER-01 排序。 |
| 不显示 | 确认后从本人会话列表移除，保留对应聊天记录；收到新消息或主动再次联系时，会话回到列表，原记录仍在。 |
| 拉黑 | 按[内容管理 BLOCK-DM-01](moderation.md)暂停双方发送私信，保留聊天记录。 |
| 删除 | 经 MESSAGE-ACTION-SHEET-01 确认后，移除本人这段会话并清除本人这边的聊天记录，保留这对身份的私人备注；对方记录和其他身份会话保留。不提供回收站或七天恢复。 |

- 会话行长按菜单与聊天内单条消息长按不同；单条文字消息操作由[私信模块 DM-MESSAGE-MENU-01](messaging.md)维护。

### MESSAGE-HIDDEN-01：隐藏会话不贡献未读提示

- 确认“不显示”后，该会话暂时不贡献未读角标或身份未读红点；聊天记录仍保留，不将隐藏操作当作阅读。
- 收到新消息时，会话重新出现并恢复提醒；通过搜索打开隐藏会话时，按 MESSAGE-SEARCH-01 恢复到列表，并按 MESSAGE-READ-01 处理已查看会话的未读。
- 因新消息重新出现时，将隐藏前尚未读的消息与新消息一起恢复计数。例如原有八条未读，隐藏后再收到一条，恢复时显示九条；隐藏仍不等同于阅读。

### MESSAGE-ACTION-SHEET-01：不显示、拉黑与删除的底部确认

- 点击长按菜单中的“不显示”“拉黑”或“删除”后，关闭浮动菜单，在当前消息页面上方弹出底部操作面板；页面背景保持原有黑色亮度，通过面板底色与页面的差异区分层次，不叠加压暗效果。面板顶部圆角，说明文字在上，操作项纵向排列，底部单独一行“取消”。
- 面板采用柔和、偏灰的浅白底色，搭配深灰文字，删除与确认拉黑继续用红色强调；白色亮度保持克制。具体颜色与分隔线在绘图时调整。背景的点击拦截行为与视觉亮度分开处理，面板打开时不误触后方会话。
- 点击确认操作后才执行对应动作；点击“取消”关闭面板并保留原会话状态。此流程替代此前尚未确认的居中删除确认框方案。

| 面板 | 说明内容 | 操作项，自上而下 |
| --- | --- | --- |
| 不显示 | 说明会话将从列表移除，记录保留，可通过当前身份的会话搜索找回。 | 不显示该聊天；取消 |
| 拉黑 | 说明拉黑后双方暂停发送私信，聊天记录保留，需明确解除后继续；限制范围按[内容管理 BLOCK-DM-01](moderation.md)。 | 确认拉黑（红色）；举报；取消 |
| 删除 | 说明将清除本人这段会话的聊天记录，删除后无法恢复，备注保留，对方记录不受影响。 | 删除并清空聊天记录（红色）；取消 |

- “不显示”后的新消息或主动联系恢复会话与原记录；这一规则不适用于已删除的记录，也不能绕过已生效的拉黑。已删除记录在重新联系、切换身份或搜索时均不恢复。
- 拉黑面板的“举报”进入[内容管理 REPORT-DM-FLOW-01](moderation.md)规定的“选择类别 → 填写详情与添加证据 → 授权提交”流程，不自动执行拉黑；私信证据授权覆盖所选首条至末条间全部可用记录，已知缺口按[REPORT-DM-GAP-01](moderation.md)在预览和材料中标注，不把有缺口记录称为完整。
- 已确认采用当前身份的会话搜索找回“不显示”的聊天；不采用附件中的七天恢复机制，不设置最近删除或回收站入口。

### MESSAGE-SEARCH-01：搜索当前身份的已有会话

- 消息页支持搜索当前身份已有的会话，包括设为“不显示”的会话，便于主动找回。
- 搜索范围遵循 MESSAGE-IDENTITY-01，不合并其他身份的会话，也不扩展为搜索陌生用户或公开身份历史。
- 支持按对方昵称、最初来源帖标题或本人私人备注查找当前身份会话，包括“不显示”的会话；最初来源与备注按[私信模块 DM-SOURCE-01 / DM-NOTE-01](messaging.md)确定。在当前身份会话范围内，也可按本机保存的聊天正文查找；不跨身份、不访问平台云端历史，已删除或未保存成功的内容不能恢复或命中。
- 搜到隐藏会话后，点开即恢复到当前身份的会话列表，无需先发消息；恢复不改变既定置顶与时间排序规则。
- 已清除的聊天记录不能通过搜索恢复；首页搜索入口已有确认图，具体匹配方式与结果排版待设计。

### MESSAGE-ORDER-01：私信按最新消息排序

- 每个身份的私信列表先展示置顶会话；置顶区域内部按最新消息时间从新到旧排列。未置顶区域也按最新消息时间从新到旧排列，收到或发出新消息时移至该区域顶部。
- 未读使用角标提示，读取行为仍遵循 MESSAGE-READ-01。
- 切换回某个身份时，恢复该身份私信列表此前的浏览位置；各身份分别保留位置。
- 用户向下浏览会话列表时，新消息不立即挪动当前画面中的会话行；顶部显示“有新消息”，点击后回到列表顶部并应用最新排序。置顶与普通会话分区规则继续适用。
- 时间相同、发送失败及跨身份浏览位置恢复时尚未处理的新消息提示待细化。

### MESSAGE-LIKE-01：按内容合并点赞提醒

- 同一条帖子或评论收到的点赞合并为一条提醒，显示新增点赞数量，不按每次点赞单独占一行。
- 首页“点赞”入口的数字表示有未查看点赞的内容条数；同一帖子新收到十个赞，入口计 1，列表对应提醒显示“新增 10 个赞”。查看该条提醒后只清除这一内容对应的未读。
- 点击合并提醒回到对应原内容。
- 取消点赞不发送通知或推送，不新建一条“取消赞”提醒。尚未查看的聚合提醒按仍有效的新赞重算：三个新赞取消两个后显示一个；全部取消时移除这条尚未查看的提醒及其未读。
- 已查看的历史点赞提醒在对方取消点赞后仍保留，表达为“曾赞过”，不新建取消点赞通知；当前帖子或评论的赞数按实际剩余点赞展示。历史提醒不能表述为对方现在仍在点赞；此项不新增点赞者名单或身份字段。
- 新增数量统计起点、提醒排序和身份信息展示待细化。

### MESSAGE-READ-01：按查看对象清除未读

- 打开消息首页不自动清空所有未读。
- 点进某条提醒或某个私信会话时，只清除对应提醒或会话的未读，其他未查看对象保持未读。
- 本规则管理用户自己的未读状态；对方不获得已读、在线或正在输入的状态，具体边界见[私信模块 DM-PRESENCE-01](messaging.md)。

### MESSAGE-DEVICE-RESTORE-01：换机恢复会话入口，缺少本地记录不提示

- 新手机登录原账号后，恢复现存身份的会话入口、对方昵称及私人备注，可以继续联系；已主动删除的会话入口不因换机自动恢复。
- 新设备没有旧聊天正文时，不作任何缺失提示，不显示“此前聊天记录保存在原设备”等说明；没有记录就不展示记录。恢复入口和备注不等于从云端下载历史正文。
- 登录后补收离线期间的新消息按[DM-STORAGE-01](messaging.md)执行；这与缺少此前已在原设备落地的历史记录是两种情况。首次联系限制、隐藏状态、排序及未读的换机衔接待细化，不因入口恢复重置已有联系限制。

### MESSAGE-READ-SYNC-01：本人未读状态与换设备衔接

- 同一时间仅一个移动设备登录使用，按[账号 AUTH-DEVICE-01](accounts.md)执行；原“其他已登录设备同时同步已读”场景不再适用。
- 只清除本人已经查看的那批消息，之后新到的消息仍保持未读；不向对方发送已读状态。
- 换设备后的未读状态衔接、离线冲突及同步异常待细化，须服从[本地历史 DM-STORAGE-01](messaging.md)，不因备注同步而默认可同步聊天正文。

### MESSAGE-NOTIFICATION-01：系统通知默认隐藏内容与身份

- 回复与私信的系统通知默认只提示“你收到一条回复”或“你有一条新私信”，不展示具体内容或身份信息。用户进入 App 后查看内容及对应身份；已设为免打扰的会话按 MESSAGE-MENU-01 停止系统通知。
- 设置中提供通知内容预览开关，用户可以主动开启预览；默认关闭。此规则针对系统通知，不改变 App 内已确认的消息展示。
- 开启私信通知预览后，显示发信者身份当前昵称和一行文字；图片显示“[图片]”，不额外显示本人的收信身份，不用私人会话备注替代发信者昵称。点击后仍按 MESSAGE-NAV-01 自动进入对应身份。
- 预览具体排版及回复通知开启预览后的字段待设计；默认关闭、免打扰和内容访问边界继续适用。

### MESSAGE-PUSH-01：系统推送事件范围

- 新私信、评论与回复、举报结果、处罚结果及申诉结果可以触发操作系统推送。
- 点赞只进入 App 内点赞提醒，不触发操作系统推送。
- 本规则继续服从默认隐藏内容预览、用户主动开启预览和单会话免打扰设置。

### MESSAGE-NAV-01：入口与跳转

- 导航树固定提供“消息”入口，具体位置由[入口与导航](navigation.md)维护。
- 点击回复提醒，进入对应帖子并定位具体回复，返回时回到消息列表。若整篇帖子已删除，则按[内容管理 DELETE-POST-01](moderation.md)显示删除状态，不继续展示原帖内容或打开可回复的评论区。
- “收到的”列表内对方头像／昵称也属于同一提醒点击区域，进入原帖对应评论，不直接进入私信。用户于 2026-09-20 对此答复“按推荐”；需要私信时，在原帖点击发言者头像／昵称，按[私信 CONTACT-01](messaging.md)执行。
- 若原帖仍在且可访问，但提醒指向的评论已删除（含随上级评论一同删除），则进入原帖评论区，顶部短提示“该评论已删除”；提醒中不保留该评论已删除的正文预览，不将其作为仍可回复的目标。整篇帖子删除仍按前一条规则执行。
- 首版不按主题或标签隐藏互动提醒及拦截跳转，主题屏蔽按[标签 TAG-BLOCK-DEFERRED-01](tags.md)留待后续版本。系统推送默认隐藏内容的规则继续独立适用。
- 私信会话进入聊天，首次身份选择和首次联系限制由[私信与会话](messaging.md)维护。
- 点击系统消息通知时，自动切换到收到该通知的身份并进入对应具体消息；返回后停留在该身份的消息页。自动切换不清空其他未读，仍按 MESSAGE-READ-01 只处理实际查看的提醒或会话。
- 从消息进入内容时遵守[账号访问](accounts.md)与[删除、下架等内容可见性](moderation.md)规则；所有身份展示遵守[身份模块](identity.md)的身份隔离边界。

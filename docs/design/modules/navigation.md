# 入口、导航与内容发现

更新：2026-10-08。当前规则只在本模块维护。

- 状态：全局与各通道历史分开、账号跨设备同步、进入搜索直接弹键盘并刷新置顶、结果仅展示帖子已确认；通道列表F1-01／02／03的v9三状态已由用户正式定稿，包含布局与本组配色：白色整体框架和局部偏暗偏灰蓝色，不代表全局主题；同步异常待细化。v6为此前通过的布局，v7林绿与v8整页暗蓝已废弃。此为设计规则更新，Flutter社区文字切片未实现，业务验收NOT_RUN。

## 范围

进入社区、选择通道、浏览列表、搜索和返回。登录规则见[账号](accounts.md)，标签规则见[标签](tags.md)。

## 已确认规则


### ENTRY-01：入口与导航树

- 未登录时展示树的入口外壳，但不显示任何通道节点或社区内容；未登录点击树洞进入登录／注册选择，不提供有功能意义的拖动。已有用户以私有用户名和密码登录；新用户先完成校邮验证码与账号注册。建立会话后在同一入口上下文中请求完整通道目录，初始露出五个节点，其余节点可探索到达并可拖动探索，再进入选中的通道。
- 普通启动 App 时先恢复本机安全存储中的会话令牌。恢复期间保持无节点树外壳并显示加载状态，不显示旧目录节点；恢复成功后直接进入导航树，不重复播放首次进入的过渡动画。从帖子、通道返回的既有位置恢复规则继续适用。分享链接登录后直达原帖按[账号模块 AUTH-SHARE-01](accounts.md)，消息通知仍按消息模块的定向跳转执行。
- 内部标题为两行：`S.A.Y`、`W.H.A.T`，保留圆点，采用艺术字体；具体字形、字号和动效未定。
- 登录后中部视觉是一棵可像球体一样拖动探索的树；首条切片实现高质量二维功能树，支持节点层次变化、点击反馈和位置恢复，不采用真实三维实现。未登录状态不渲染通道节点。
- 登录或新号注册并建立会话后，客户端通过 `GET /api/v1/channels` 请求完整七个通道；只有目录完整返回并通过校验时才渲染节点。加载中保留无节点树并显示加载状态，目录请求失败保留无节点树并提供重试，不显示部分节点或过期目录缓存。会话恢复收到 `401` 时清除令牌和节点并回到登录／注册入口；收到 `503` 或超时则保留令牌和本地状态，停留在无节点加载／重试状态，不误判为退出。新设备接替导致的 `401` 显示“账号已在其他设备登录”。
- 目录成功响应按稳定顺序返回七项：`vent`、`warning`、`recommendation`、`buddy`、`emotion`、`mutual_help`、`technology`；前五项为冷启动初始露出，后两项已加载但位于场景深处。接口使用 `200`、`401`、`503` 分别表达成功、会话无效和服务暂不可用；客户端不把节点坐标作为服务端业务数据。
- 分类节点被选中后亮起、向前靠近并进入通道；返回时恢复进入前的旋转位置。具体树形节点与动效另定。
- 底部提供文字搜索；固定提供“消息”和“我的”入口，分别通往[消息中心](messages.md)、[个人内容与设置](personal.md)。

### NAV-01 / NAV-02：独立通道

- 每个大分类是一个独立树洞通道。通道只显示所属分类的内容，换大分类须返回导航树重新选择。
- 不设置跨分类广场、全部帖子入口或通道内大分类切换栏。
- 导航树初始露出五个通道；有热度数据时优先展示热度最高的五个，新社区暂无热度数据时默认露出“吐槽、避雷、安利、搭子、情感”。其余首版通道通过转动探索，返回通道前的导航位置不被热门排序覆盖。
- 首版七个通道名称及每帖单通道归属按[分类模块 CATEGORY-01 / CATEGORY-02](tags.md)执行；通道热度由[热度与排行榜](popularity.md)维护。首条切片直接实现基础导航树，拆为两次开发任务：先实现服务端通道目录与高质量二维功能树，再接入通道内容主链。首条切片不接热度排序、搜索或标签筛选；节点最终视觉与动效仍待 UI 阶段细化。

### FEED-01：通道列表

- 采用图片／纯文字混排的双列瀑布流。图片帖展示图片封面，可用角标表达多图；纯文字帖通过标题排版形成卡片。卡片展示标题、发言身份头像／昵称、发布时间与点赞数量，不显示正文摘要；正文在[帖子详情](post-detail.md)中阅读。
- 顶部保留返回按钮、当前通道名称与右上角放大镜搜索入口；当前通道名单独显示，不增加通道内大分类切换栏。
- 提供最新排序，列表上方采用左侧“最新发布”、右侧“筛选”的紧凑工具栏；不设置孤立的单页签下划线或只有一个选项的排序下拉。底部筛选面板与已选标签操作继续按[标签模块 TAG-FILTER-02](tags.md)执行。
- 点击通道搜索后，在搜索区域下方展示当前通道的帖子热度排行榜，见 SEARCH-02 及[热度与排行榜 HEAT-03](popularity.md)。
- 新帖发布成功后进入当前通道“最新”列表顶部；若用户已滚动到其他位置，保持其浏览位置，不强制拉回顶部。帖子展示仍遵循当前标签筛选及内容访问规则。
- 2026-10-09用户重申点击确认发布后直接返回原通道主页面，不显示发布状态整页；发布中与失败在我的帖子卡片中处理。成功公开时当前前台页上部短暂显示小型浮层“发布成功！”；本次附件正式选中[暗蓝提示款](../../../UI产品图/通道-发布成功提示.png)，覆盖此前黑色候选。不强制跳往我的、不新增对话框确认步骤；未知结果不能提前提示成功，具体恢复与归属限制见POST-FLOW-01。
- 底栏固定提供“首页／中央加号／消息／我的”，列表滚动时保持可见。“首页”回到导航树并遵循既有位置恢复规则，不增加跨分类广场或全部帖子入口；消息与我的分别沿用对应模块。
- 中央“＋”为[发帖入口](post-composer.md)，点击始终新建当前通道帖子，不自动打开已有草稿；续写从“我的”进入，见 POST-NEW-ENTRY-01。按钮尺寸、安全区与内容避让在Flutter实现时校准。
- 通道列表F1-01／02／03的v9三状态布局与本组配色已正式定稿：白色整体框架、局部偏暗偏灰的原蓝色UI元素。确认范围为这三张通道图，不自动作为全局主题。v6为此前布局确认，v7整页林绿／炭黑与v8整页暗蓝已废弃，不沿用其背景或配色。图稿规则不代表图片上传、点赞、搜索、筛选或消息功能已实现，当次代码范围仍按文字发布／阅读任务与契约执行。

2026-09-16的单列、不显示通道名、右下角圆形加号和深色背景为历史方案，已由上述2026-10-08用户确认的通道布局与白色框架覆盖；其他授权、单通道归属及业务契约不因此改变。

### SEARCH-01：导航树全局文字搜索

- 首版按输入文字检索帖子标题、正文和标签，不使用模型理解意图、生成分类或推荐标签。
- 结果区直接展示匹配帖子，按所属通道分组，可直达不同通道的帖子；不增加关键词高亮或正文命中摘要。
- 全局搜索提供“相关度／最新”排序，默认相关度；帖子继续按通道分组，各组内部按用户所选方式排列。
- 相关度模式按每组最相关的匹配帖子决定通道组顺序；最新模式按每组最新的匹配帖子决定通道组顺序。切换排序时同时应用对应的组顺序与组内顺序，不按通道匹配帖子数量决定谁在前。
- 从帖子直接返回关键词搜索结果时保留搜索词与浏览位置；从热榜帖子返回榜单则自动刷新并回到顶部，见[HEAT-08](popularity.md)。每次点击搜索入口仍按 SEARCH-07 重新开始。
- 搜索遵守账号访问、删除和下架规则；搜索历史与通道历史分别保存，存储规则按 SEARCH-04 执行。

### SEARCH-02：通道搜索与热榜入口

- 每个大通道右上角提供放大镜搜索入口；点击进入搜索界面，顶部搜索框直接获得焦点并弹出键盘，下方展示搜索历史与当前通道热榜。
- 热榜规则统一由[热度与排行榜](popularity.md)维护；不沿用之前“最新 / 热榜”并列切换的候选入口。
- 通道搜索只匹配当前通道帖子的标题、正文、标签；导航树的全局搜索继续按 SEARCH-01 覆盖全部通道。结果直接展示对应帖子，不增加关键词高亮或正文命中片段。
- 未输入时，搜索框下方展示 SEARCH-04 的搜索历史，历史下方展示热榜；提交关键词后，两者替换为搜索结果；清空关键词后恢复历史和热榜。
- 从搜索返回通道时保留原通道列表浏览位置；从帖子直接返回搜索结果时继续按 SEARCH-01 保留搜索词与浏览位置。再次点击搜索入口时按 SEARCH-07 刷新并从顶部开始。

### SEARCH-03：通道搜索结果排序

- 通道搜索结果默认按与关键词的相关度排列，并提供“按最新”排序供用户切换。
- 相关度相同时，较新的帖子优先；全局通道组的最相关匹配帖同分时，也优先其中较新的匹配帖所属组。相同相关度且相同时间的稳定顺序、相关度算法与控件待实现设计。全局分组按 SEARCH-01 执行。

### SEARCH-04：搜索历史的展示与复用

- 导航树全局搜索与各通道搜索都保存可再次查看、使用的历史，各自记录、各自展示。例如树上搜索“考研”、搭子通道搜索“自习”，两处历史分别显示对应词，不自动混入另一处。
- 历史跟随登录账号保存，仅本人可见，三个身份共用；换手机登录同一账号后同步历史。跨设备同步不改变各搜索范围之间的分隔。正式注销账号后清除该账号搜索历史，同邮箱重新注册的新账号从空历史开始。
- 搜索框下方放搜索历史，默认显示两行，超出部分通过“展开”查看；下方继续展示当前通道热榜。提交搜索后两者被搜索结果替换，清空关键词后恢复历史和热榜。
- 每个通道分别记录自己的搜索词，按最近搜索时间排列；同一词再次搜索时置顶，不产生重复项。
- 只记录已提交的搜索；点击历史词直接在当前通道执行搜索。
- 每处最多保留最近二十个不同搜索词，超出后移除最旧的一条；重复搜索仍按最近时间置顶。
- 从帖子返回仍沿用 SEARCH-02 保留本次搜索词与浏览位置，不因新增历史而重置当前搜索。

### SEARCH-05：搜索历史删除

- 每条搜索历史右上角显示叉号，点击叉号直接删除该条记录；不采用长按删除。
- 点击叉号只触发删除，不触发该搜索词的搜索操作。
- 历史区域右侧提供“清空”；再次确认后清除当前通道的全部搜索历史。

### SEARCH-06：无结果时主动扩大搜索

- 通道内无匹配结果时显示“暂无相关帖子”，提供“搜索全部通道”按钮。
- 用户点击后携带当前关键词进入导航树的全局搜索；不自动扩大通道搜索范围。
- 全局搜索继续遵守已有的登录访问与内容可见性规则。

### SEARCH-07：每次点击搜索重新开始

- 每次点击搜索入口都更新搜索初始页面，从列表顶部开始，直接弹出键盘，不恢复上次停留的热榜位置或名次快照。
- 通道搜索重新获取当前通道热榜，历史记录继续按 SEARCH-04 保留；刷新页面不等于清空历史。
- 该规则描述点击搜索入口的动作，不改变正在浏览热榜时顺序稳定的规则。


## 待确认

- 有效登录再次打开直接进入导航树已确认；首条切片的二维拖动、节点可达、点击反馈和本次登录期间返回位置恢复已确认，App 重启/重新登录回到固定初始布局，树冠与节点造型、旋转范围的最终视觉细节待设计。
- 首屏分类与搜索结果的具体布局、失败反馈及树形联动；搜索直接弹键盘、全局独立历史及账号同步已确认。首条切片暂不实现搜索，历史同步冲突、删除同步、展开后的收起控件及空历史布局待细化。
- 通道页面底栏“首页／中央加号／消息／我的”、顶部当前通道名与搜索、“最新发布＋筛选”及v9本组三状态配色已正式定稿；导航树消息和“我的”入口的具体视觉仍待细化。实际尺寸、安全区、内容避让和平台渲染在实现时校准，静态定稿不代证这些平台检查通过。
- 全局与通道搜索均默认相关度并可切换最新，全局保留通道分组；组顺序按 SEARCH-01 的最相关／最新匹配帖子决定，同相关度较新优先按 SEARCH-03 已定；相关度算法及最终同时间稳定顺序待设计。拖动惯性和标签朝向仍为候选，热度由[热度模块](popularity.md)维护。

## 已确认规则


### DETAIL-02：默认阅读与展开评论

| 状态 | 已确认结构 |
| --- | --- |
| 默认阅读 | 从通道帖子卡片进入详情，以标题、正文及帖子图片为主；评论列表初始收起。标题在左，楼主头像与昵称位于标题右侧。 |
| 阅读操作 | 左下角为紧凑的“评论＋数量”；右侧提供帖子心形点赞及数量、五角星收藏。默认画面不设置大尺寸回复按钮或评论输入区。 |
| 展开评论 | 点击左下角评论入口，正文约占可用内容高度的三分之二，底部评论区约占三分之一；操作栏位于正文与评论之间。 |
| 独立滚动 | 正文和评论分别滚动；操作任一区域不带动另一区域，正文继续可操作，不使用遮罩禁用正文。 |
| 收起与恢复 | 再次点击“评论＋数量”收起评论区；重新展开恢复默认约 2/3 正文、1/3 评论的比例，载入最新评论，正文和评论仍分别恢复此前阅读位置。新内容展示按[评论 COMMENT-NEW-01](comments.md)，内容变化时的定位衔接待细化。 |

### DETAIL-SPLIT-RESIZE-01：允许拖动分界增大评论区

- 用户可拖动正文与评论区的分界，增大评论可读空间，同时保留一部分正文；两个区域继续独立滚动。
- 收起评论再展开时恢复默认正文约三分之二、评论约三分之一的比例；阅读位置按 DETAIL-02 保留，比例恢复不等于回到内容顶部。
- 可拖动范围、不同屏幕适配及手势冲突细节随页面设计，不在本轮新增具体尺寸。

### DETAIL-META-01：时间与细标签

- 标题下方用较小字号展示发布时间与帖子细标签，再往下呈现正文。
- 楼主头像与昵称仍位于标题右侧，保持已确认的作者区结构。
- “已编辑”位于发布时间旁，点击可看最后修改时间；普通读者不开放历史版本，规则见[内容管理 EDIT-POST-01](moderation.md)。时间格式、间距与无标签排版待细化，现有 PNG 尚未同步新增内容。

### DETAIL-COUNT-01：评论总数

- “评论＋数量”统计当前帖子中的主评论与楼中楼回复总数。例如十条主评论和二十条回复显示“评论 30”。
- 删除主评论时减去该条及所属楼中楼的全部数量；删除楼中楼回复只减一条，对它的其他回复保持并继续计数。实际被删内容不留原位占位，范围按[管理 DELETE-COMMENT-01](moderation.md)执行。

### LIKE-01：帖子点赞与收藏

- 评论未展开时也能点赞和收藏帖子，点赞数量可见。
- 点赞使用心形图标，正式稿展示未点赞与已点赞状态；收藏使用五角星图标。
- 点赞、收藏与其他点击区域分别响应；点赞不能顺带触发回复或私信。
- 不增加可串联用户跨帖身份的点赞者列表。评论点赞规则由[评论与回复](comments.md)维护。

### LIKE-ACCOUNT-01：同一账号对同一内容最多一个赞

- 点赞以登录账号为单位：每个账号对同一条帖子、主评论或楼中楼回复最多保留一个赞，再次点击取消已有的赞。
- 不同内容分别记录点赞；不是整篇帖子及其所有评论合计只能点一次。
- 可以给自己的帖子、主评论或楼中楼点一个赞，再次点击可取消；换自己的其他身份不能重复点赞。自己的浏览不计数，见[热度模块](popularity.md)。
- 三个身份不能为同一条内容分别投票。切换消息收件身份或在其他帖子使用不同身份，不产生新的点赞资格，也不改变该内容已有的点赞状态。
- 点赞无需先选择身份，不设置点赞身份切换入口，也不单凭点赞确定该帖发言身份；发言身份遵循[身份模块 MASK-02](identity.md)。
- 不提供公开点赞者列表，不展示同一账号下其他身份或关联关系。

### LIKE-FEEDBACK-01：点赞即时反馈，明确失败后回退

- 点击点赞先更新心形与数量；请求明确失败后恢复操作前状态及对应数量，短提示“点赞失败，请重试”，由用户再次点击，不把失败显示为成功。
- 取消点赞同理：点击先反馈取消，明确失败后恢复原已赞状态和数量，提示取消失败并允许再次点击。帖子、主评论与楼中楼使用同一规则。
- 服务端仍按账号每条内容最多一个赞执行；请求未知不能当作明确失败，连续点击及结果未知的具体同步处理待细化。

### FAVORITE-FEEDBACK-01：收藏即时反馈，明确失败后回退

- 点击收藏先更新五角星状态；请求明确失败后恢复原收藏状态，提示失败并允许用户重试。取消收藏同理，不能将明确失败的操作显示为成功。
- “我的”收藏列表按实际保存成功的收藏维护，不能因详情页的临时状态保留失败的新增或移除。结果未知时显示处理中并暂停重复点击，核对成功或失败后落实最终状态；同步实现和提示视觉待细化。

### DETAIL-MEDIA-01：帖子图片查看

- 图片统一接在帖子正文后，使用固定形状与统一尺寸的缩略图容器；多图按三列排列，保持发布时的图片顺序，单图使用同一种缩略格。本轮F1-19正式图为紧凑方形预览，覆盖原单图较大的方向。
- 横图、竖图、正方形、超长／超宽图及不同像素分辨率均等比缩放后填满并裁切到相同预览框，不拉伸、不按原图宽高比改变容器大小。相同展示位置的格子同宽同高、间距与圆角一致；容器随可用宽度布局，不要求不同设备使用相同物理像素。加载、失败或重试占位同样保留原尺寸，避免跳动。
- 缩略图裁切不改写原图。点开后按原始宽高比完整适配大图，允许留白、不强行裁切；使用完整图片资源，不放大已裁切缩略图替代原图。多图时可左右切换当前帖子中的图片。
- 大图支持双指缩放和双击放大；图片恢复原尺寸时可下滑关闭。缩放中的移动不直接当作关闭。
- 关闭大图后回到此前的浏览位置；正文和评论区原有的独立滚动位置不因看图被重置。大图查看页提供用户主动“保存到相册”入口；不会因收到或浏览图片自动写入系统相册。帖子、评论、回复及私信图片查看均沿用这一主动保存边界。
- 帖子图片数量与发布前排序由[发帖模块 MEDIA-01](post-composer.md)维护；评论单图查看见[评论模块](comments.md)。

### DETAIL-01：联系入口的画面边界

- 点击帖子或评论上他人实际使用的身份昵称直接私信，不放“继续聊”联系卡片、独立私信图标或发消息前置的个人资料页。
- 首版取消关注与互关；持续联系通过[私信与会话](messaging.md)完成，不设置关注入口。
- 帖子右上角菜单提供“分享”，点击打开手机系统分享面板；仅携带产品名称和帖子链接，不携带帖子标题、正文、作者身份或配图。接收者须登录后查看，访问规则见[账号模块](accounts.md)；删除入口状态按[内容管理 DELETE-POST-01](moderation.md)。
- 外部链接预览同样不得返回帖子标题或内容；系统面板外的菜单样式待设计。
- 帖子右上角菜单提供举报入口，提交流程由[内容管理 REPORT-01](moderation.md)维护。

- 点击已注销账号的头像或昵称，顶部显示“账户已注销”短提示，不弹框，也不发起私信；已有帖子评论继续保留并允许其他用户互动，按[账号模块 ACCOUNT-CLOSE-01](accounts.md)执行。身份删除后的头像昵称替换按[身份模块 MASK-DELETE-01](identity.md)执行。

- 正式稿手机画板为 402 × 874。基准可用内容高度为 738，其中正文 492、评论 246；顶部状态栏与导航、底部安全区不计入比例。其他屏幕适配未定。
- 回复输入采用 DETAIL-03 的近全屏输入状态，不沿用浏览状态的三分之二／三分之一比例。主动收起未发送输入后恢复分屏及两区原浏览位置；具体输入、草稿与发送流程统一见[评论与回复](comments.md)。
- 正文、昵称、时间和计数均为占位示例；图外比例、动作说明不是 App 文案。定稿不代表静态图已实现或验证真实手势。

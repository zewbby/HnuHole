## 设计与规则

- 依据[新建帖子](../modules/post-composer.md) POST-FLOW-01、MEDIA-01、POST-DRAFT-01及当次前端计划。页面属于内容编辑第一步；右上“下一步”进入发布确认，标签与身份不提前放在编辑页。标题与正文填写顺序自由，不增加顺序选择、预览、直接发布或额外确认。
- 白色写作面、黑色标题和正文，暗灰蓝“下一步”，系统中文无衬线目标。沿用通道组后，本页已有独立看图确认；仍不推定最终全局主题。
- 顶部“写帖子”与当前通道“搭子”，标题在上、正文在下。稳定的“标题／正文”标签保留，便于输入后仍能识别字段；ui-ux-pro-max的`form labels --domain ux`命中关联标签指导，仅采纳这一通用语义，不照搬Web的for属性实现。
- 样例标题“周末一起去图书馆”为8个汉字；正文为两段日常中文。内容为设计占位，远未接近3000字，未显示无意义的正文限额提示。
- 图片区接在正文后，当前0/9，只显示一个三列单元宽的添加入口；图片最多九张、三列缩略图／移除／拖动按完整产品规则设计。图片实现尚不在当次文字切片代码范围，不能因入口出图登记为已实现。
- 底部“草稿已保存”表示所选正常态中已获得成功保存结果。保存中／明确失败不能复用这一状态；失败仍留编辑页，后续另画。没有独立草稿保存按钮或正常退出确认。
- 编辑流程独立于浏览列表，因此本页不放首页／消息／我的底栏；返回沿用自动保存或保存失败留页规则。

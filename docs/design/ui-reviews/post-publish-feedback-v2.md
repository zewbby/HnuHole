## 用户任务与规则

依据[发帖POST-FLOW-01／PENDING-01／FAIL-01](../modules/post-composer.md)、[个人内容PERSONAL-LAYOUT-01／CONTENT-01／DRAFT-01](../modules/personal.md)、[导航FEED-01](../modules/navigation.md)。已读取HANDOFF、计划与相关模块，实际查看正式通道、本人混排与失败重试编辑参考，以及用户最新1080×2400小红书截图。参考只借用帖子封面／信息区与小黑色成功浮层，不复制钱包、粉丝、账号编号、公开个人主页或全页蓝底。

- 点击确认发布立即回原通道主页面，后台继续发送。不显示发布状态整页，不强制跳往我的；恢复浏览位置，不抢占已滚动的列表。发送前持久上下文异常的恢复边界依实施计划，不能丢失输入。
- 正在发布只在我的对应原尺寸卡片的信息区显示转圈＋发布中；前台主页面仍正常浏览。未公开任务无公开作者区及点赞；用户可主动查看只读提交内容、核对或请求取消，结果未知与取消核对的语义仍保留，但不再各自作为自动进入的整页。
- 成功公开才短暂显示“发布成功！”小黑色浮层；本地已保存或服务端仅受理不代表成功。浮层不阻断操作、不要求确认、不重复播报旧恢复结果，不向新账号或无关页面泄露旧任务反馈。时间拟定约3秒，实际可访问性播报及前台寿命在实现阶段校准。
- 明确失败后保存为原列表内的失败重试草稿，草稿标签旁亮红叹号，信息区小字发布未成功；点击恢复内容编辑并重试，没有独立失败栏目或草稿箱。原身份与通道仍固定；结果未知不能提前转成可另发的普通草稿。保留原失败尝试及提交关系，实际本机保存未成功时不能显示刚刚保存。
- 编辑页沿用原文本／图片编辑结构、固定身份与通道、底部确认重试；顶部仅小字说明上次未成功且内容保留，没有大错误卡或结果页。普通未提交草稿的身份重选权限不套用到失败重试草稿。
- 原身份已删除时仍停止重试并清理明确失败入口，遵循身份模块；本组示例身份有效，不覆盖该独立状态。

## 设计卡与技能应用

实际应用项目[hnuhole-ui-craft](../../../.agents/skills/hnuhole-ui-craft/SKILL.md)、frontend-design层级／留白和Impeccable Operate参考，并用内置imagegen编辑位图。没有运行Impeccable完整工具链。ui-ux-pro-max实际查询：

```powershell
python -X utf8 .agents/skills/ui-ux-pro-max/scripts/search.py 'toast notification asynchronous feedback' --domain ux
```

采用Toast Notifications的短暂反馈原则；Haptic Feedback和AI Feedback Loop两条与本次需求无关，未引入振动或AI反馈入口。用户要上方小弹框，按其参考处理为短暂浮层，不是需要取消／确认的阻断对话框；宋体弹框正文规则不自动扩大到toast、列表或按钮。

目标色：框架白#FFFFFF、主字#141414、动作暗灰蓝#263B4E、次字#556273、表面#EEF0F3、状态红#F04438；成功浮层黑色#111111为局部反馈表面，不是全局暗色主题。保持用户要求的视觉分量，通过黑字、明确边界和有限阴影表达。

本人帖子改为两列等宽网格：同排封面及信息区等高、上下边对齐、统一照片裁切比例；纯文字完整封面，正式帖作者／时间／赞数落在统一信息区，未公开项保持相同卡片高度。两排照片与文字卡封面边界已统一；较短内容不缩短卡片。通道feed原批准布局不自动跟随此次网格改版。最终几何由真实Flutter组件实现；PNG轻微生成偏差不当作精确测量。

已查看所有当前输出。初版第二排文字封面比图片高，集中修正后以成功网格为统一参考，仅改第一张卡片的状态；最终正常／成功／发布中／失败四张的卡片行与封面边界一致，没有为状态插入整页面板。发布中原稿重复转圈已去重；失败叹号清楚，未公开项无点赞。中文无明显截断，宋体删除弹窗原正式图未变。

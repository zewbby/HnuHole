## 2. 要求评审者挑战的核心结论

以下是**待核对的设计结论**，不能先写成审计通过项：

1. C 与客户端诚实且旧号凭据未泄漏时，恶意 V 可自签新密钥／新槽位造假资格或拒绝服务，但 OTP、资格、bootstrap 私钥、退役／释放收据均不授予旧账号控制权。
2. V 若把合法用户的同一 `slot_id` 改绑攻击者公钥，C 必须先重算固定散列等式并拒绝；只要求“票据含公钥＋PoP”不足以阻止掌握签名钥的 V 换绑。
3. 严格验签、一次性真实 C 挑战、不可改开户意图、准入桶及长期槽位终态须共同成立。密码学验签成功不能覆盖过期、已消费、错误用途或错误账号状态。
4. 只取得 V 库仍得到邮箱原文；只取得 C 库仍得到内容及密码验证值。V＋C 串通或双库泄漏可用 `slot_id` 直接 JOIN 邮箱与账号，注销前历史日志／WAL／备份可能继续连接历史账号。
5. 独立主体与诚实客户端是实际前提。C 若控制恶意客户端更新，可让客户端上传邮箱；两个数据库、不同服务名或不同云账户本身不能证明对 C 匿名。
6. 恢复码／Passkey 被盗可夺号；密码、恢复码和全部 Passkey 都丢失后不能邮箱救回，也不能在旧槽位仍占用时凭 OTP 另开号。通知在全部设备丢失时无法保证到达。

### 成熟原语与实现差异

评审以 [RFC 8032](https://www.rfc-editor.org/rfc/rfc8032.html)、[FIPS 180-4](https://csrc.nist.gov/pubs/fips/180-4/upd1/final)、[RFC 9106](https://www.rfc-editor.org/rfc/rfc9106.html)及 [WebAuthn](https://www.w3.org/TR/webauthn-3/) 为参考。使用成熟原语不自动证明本项目的组合协议安全；本项目不是 Privacy Pass 盲券实例，不宣称绝对匿名或任何 NIST 认证等级。

| 检查点 | 要求的实际证据 |
| --- | --- |
| Ed25519 接受集合 | 依注册协议第 2.1 节，对选定库逐条运行规范／非规范 `A/R/S`、单位元 A/R、小阶、混合阶及错误签名向量；A/R 都须非单位元且处于主素数阶子群。记录构建和配置差异，没有完整准入能力时不能只换一个函数名放行 |
| 槽位与签名编码 | 逐字节核对域、零字节、u32 大端、长度、版本和完整票据；测试截断、附加字节、用途替换、未来桶、错误环境／撤销钥 |
| 随机数与秘密 | 核验实际 CSPRNG、128 位恢复码、32 字节能力、数据库外 HMAC／加密钥及安全存储；公开测试 seed 不进入生产 |
| 密码与幂等 | Argon2id 参数及 KDF 并发上限实测；无快速无钥密码／恢复码请求散列；NFC 和输入界限一致 |
| Passkey | 核验真实 origin／RP ID、UV、可发现凭据、挑战消费、COSE ES256 与签名计数／备份语义；同步用户名不含私有登录用户名 |
| 传输与部署 | 内部路由验证真实对端证书及固定签名；OpenAPI `security: []` 和扩展不能当作已部署的 mTLS 中间件 |

## 3. G1–G6 证据清单

“已有”仅指仓库中的内部规格或静态输入。没有运行报告的验收方案不计为通过证据。

| 门槛 | 当前已有材料 | 仍缺失、须提交的证据 | 当前结论 |
| --- | --- | --- | --- |
| G1 协议和数据 | 固定消息规格、V/C OpenAPI、迁移设计及本轮静态向量 | 独立重算／复验、所选生产库接受集合、实际 SQL 的唯一／复合 FK／局部 CHECK、生成器兼容性 | 待独立评审；未证明实现 |
| G2 并发与故障 | T03–T10／T12、锁顺序、outbox 和未知结果规则 | 第 4 节交错的服务／SQL／客户端运行记录，丢包／崩溃／HSM 中断与灾备演练 | 未运行 |
| G3 在线攻击 | 每码十错、设备三错、邮箱滚动预算和密码基线 | 真实限流参数、负载与误伤、跨设备／flow 猜码、撞库／喷洒、时延及用户名探测测量 | 未校准 |
| G4 隐私和留存 | 字段分工、独立请求 ID、有界留存评审基线及备份边界 | 两组织证据、第 5 节权限材料、实际请求／日志／WAL／备份抽样、清理演练及真实客户端包 | 未验证 |
| G5 用户可理解性 | 强制保存确认恢复码、可选 Passkey、全丢与同步隐私提示规格 | 普通用户走查：忘用户名、换机、丢码、缓冲期重设、全部凭据遗失；恢复通知能力说明 | 未做用户测试 |
| G6 独立结论 | 本包、版本登记和签署模板 | 独立评审者签署范围、发现、复测、剩余风险与放行结论 | 未委托／未签署 |

G4 的具体单位和保留起点以迁移设计第 5 节为准：普通日志／WAL 基线七天、加密备份十四天，OTP 短期状态最多二十四小时，最近替代设备三十天。长期槽位终态和 EXPIRED 锚点不套 TTL；没有清理与恢复实测时不得把这些基线作为已兑现的隐私承诺。

评审状态只取“未评审／待补证据／发现待修／待复测／范围内通过／风险经指定责任人接受”。不得用百分比把缺失证据折算为安全程度，也不得把 G1 静态通过写成 G2–G6 通过。

## 4. 边界失败与交错验收表

每个运行案例附锁／提交顺序、故障位置、实际时间、返回状态和脱敏权威状态快照。检查结果必须能证明“不该发生的副作用没有提交”；只记录 HTTP 错误码不足以验收。静态负向向量不能代替表中的事务和客户端测试。

| ID | 刻意制造的输入／交错 | 接受标准及必须拒绝的行为 |
| --- | --- | --- |
| A01 | 恶意 V 自签新槽位，与替换合法用户同槽位公钥分别提交 | 前者是已接受的假资格边界；后者散列绑定拒绝。均不能进入已有账号重设路径 |
| A02 | 弱公钥／非规范签名、附加字节、旧版本、错用途、撤销钥／环境钥 | 所选实现逐项拒绝；不能“可解码”即接受，也不能退役／释放冒充注册 |
| A03 | 当前／上一／未来桶；意图先有效、等锁后过期；时钟倒退 | 创建和最终提交各取锁后重查；短时未来票仅原票重试；回退冻结验票，过期不开户 |
| A04 | 同邮箱多设备／flow 重发；旧码、真错及 SMTP 回包丢失 | 最新码全局生效，预算不因换 flow／重发归零；未知投递不证明 NOT_SENT，不自动重复发信 |
| A05 | V quota／OTP 已提交，HSM 卡住直至票据过期 | 保留同槽位待签事实；不新开配额、不移动原准入桶；到期须新 OTP 换签 |
| A06 | ABSENT 槽位同时开户／退役；开户成功回包丢失 | 恰一终态；重复证明不重发令牌，ACTIVE 不退役、RETIRED 不开户 |
| A07 | 退役请求前崩溃、C 已提交后回包丢失、新 OTP 过期 | V 待办先持久；不续旧票、不自行放配额；收据确认后新签仍须有效 OTP |
| A07a | RETIRED 拉取先完成／推送先完成、重复并行、V 已提交但 ACK 丢失／C 未提交 | V 恰一次清旧配额；C 本地持久记录同槽位／用途 ACK 后才清投递材料。迟到拉取的 202／拒绝不回退原结果或恢复旧配额，续办只用原确认绑定且不清新槽位 |
| A07b | 收据轮换重签、旧钥撤销、旧 ACK／signer 迟到、清理后查询及恢复旧 outbox | 重复也先验当前信任，按槽位／用途幂等；ACK 标记单调、清理起点不延期，已清任务不复活。状态页可基于终态重签，HSM 不可用只 503；灾备不回退 ACK 或重算已结束留存 |
| A08 | RELEASED 先处理、SLOT_NOT_RETIRABLE 后到；再重放旧收据 | 不恢复旧占用、不释放后来的新槽位；用途冲突不 ACK、不猜测修复 |
| A09 | 同键不同负载、同键跨操作、LIVE 收缩 EXPIRED 与迟到 POST | 原位锚点无删除空窗；拒重执行，不再次发 OTP 或重放恢复码／令牌，永久锚点容量受控 |
| A10 | 旧恢复证明初验后轮换；先建意图 A、后建 B，再提交 A | 账号锁内拒旧版本／旧凭据／旧代次；B 废弃 A，最多一份当前恢复码 |
| A11 | 重设提交与结果查询、意图过期、迟到提交同时争锁 | 只得一个 COMMITTED／NOT_COMMITTED；尚无记录或早到 404 不当作未提交，查询不静默登录取消注销 |
| A12 | 管理意图建成后密码重设／换机／撤会话；旧意图增删凭据 | 最终核对当前会话、版本和固定目标；旧意图拒绝，重设撤全部旧 Passkey／会话 |
| A13 | 同令牌续期与定向退出／新登录并发，旧撤销待办迟到 | 仅同一仍有效会话续期；旧秘密不撤新会话；不能按本地旧 expiresAt 删除未知撤销待办 |
| A14 | 客户端在退出标记、导出撤销秘密、删 Bearer 间分别崩溃 | 重启先完成旧令牌转换／撤销；旧 Bearer 不复活，也不误清新会话；未确认撤销显示待确认 |
| A15 | 注销 POST 丢回包、GET 先到 404、相同 ID 重试 | 保留预存秘密和原 ID；只有一个申请／截止，不换 ID 重建、不静默登录 |
| A16 | 请求在七天前开始但到期后才拿锁；worker 延迟；新封禁竞速 | 到期后拒登录取消、恢复及写入；仅真实 CLOSED 提交后签释放，V 未持久处理收据前不放配额；ACK 回包丢失不回滚 V 事实 |

| A18 | 旧 V/C 备份、旧信任配置／会话、最新凭据材料或终态证据缺失 | 全部认证与受保护读写冻结；不复活旧码／钥／槽位；证据不完整持续冻结，不能邮箱兜底 |
| A19 | 共用请求 ID、trace／SDK、运维导出，检查备份与清理后恢复 | C 无邮箱，V 无旧号凭据／恢复事件；发现跨方关联或超期副本即记录边界失效，不能只验主表 |

## 7. 下一步最小现实工作

本包完成后不再为补百分比继续扩展文档。用这一版本推进三项可产生新证据的工作：

1. 项目负责人确定真实 V/C 运营候选方与独立评审者，填写范围和权限事实，将现有材料交给评审者；当前未进行外部发送或委托。先审散列绑定、严格库接受集合、恢复控制权和分权前提，存在阻断发现时先修规格。
2. 在项目授权进入实施后，第一片验证选**隔离环境中的实际 SQL 约束＋注册／退役终态竞争＋提交后签名 outbox**，使用公开测试材料。提交 A02／A03／A05–A09 的真实运行证据，证明最核心的配额与拒重放边界；再扩展恢复、会话、注销和客户端崩溃测试。
3. 同时用可交互原型做 G5 用户走查并核实 G4 实际控制关系。对全部凭据遗失后同邮箱被锁的理解与接受不能从“重输恢复码成功”推断。

本轮静态材料使评审与第一片隔离验证可以开始准备；生产认证业务实现、实际迁移执行及上线仍须满足各自门槛。公开测试秘密不是生产秘密，静态向量的正确值不是事务、移动端或部署安全结论。

# 评论与回复：独立核心与接线契约

2026-10-18，任务 B07，分支 `codex/feat/comments-replies`。已正常整合 main `986477b`（包含 PR #13）。

本阶段交付纯 Go 领域规则、Dart 客户端状态核心及严格 OpenAPI 设计；**尚未提供生产 HTTP 路由、SQL 持久实现或帖子页面接线**。下面的服务端事务与端点是后续实现必须满足的契约，不能把模型测试计为真实 SQL、HTTP、设备或完整 B07 通过。

## 归属和不可变边界

- 临时编辑器仅活在当前帖页面。收起保留；真正离帖清空文字、图片和目标，不落入帖子草稿或“我发出的”。进入身份管理前保留当前输入，选择身份不绑定。
- 客户端点击发送时先生成随机规范 UUID `taskId` 与独立随机命令键 `commandId`，把完整意图写入当前环境、当前账号的私有 journal，成功后才请求服务端。journal 只保存已点击发送的任务，禁止保存未提交输入。生产 journal 必须沿业务 vault 的原生加密、账号隔离和关闭清理边界装配；内存测试适配器不证明此能力。
- CREATE 最终 C 事务检查账号、会话状态/代次/期限、处罚、身份归属、帖子及具体目标有效性；同时写入命令回执、任务和 `(account,post)` 唯一身份绑定。拒绝或仅选择身份不写绑定。受理后异步失败仍保留绑定。楼主使用发帖身份；删评论/取消赞不释放绑定。
- 任务固定 `taskId/postId/identityId/rootCommentId/targetCommentId`，目标是具体内容 ID。主评论的 root/target 均为 null；回复二者均非 null，服务端核对目标属于该帖该楼。楼中楼只缩进一层。
- 公共作者投影仅含该次公开身份的展示引用、昵称和头像/占位；不含内部账号、内部 identityId、其他面具或私有任务。`isPostAuthor` 由实际公开身份判断，不能用昵称或同账号代替。
- 重试仅 FAILED 且版本相符时接受，保留原身份及原目标，版本加一；可改文字或一张图。原目标已删时不能修改旧任务改投。确认放弃完成后，用户可显式把保留内容放入当前帖临时编辑器，选择新对象并产生新任务；未知时禁止转换。

## 命令、核对和恢复

命令键沿既有帖子协议的 16 随机字节、22 字符无填充 base64url 规则，评论使用独立用途域和回执命名空间。CREATE/RETRY/ABANDON/DELETE/SET_LIKE 每个新意图各用新键；同键、同账号、同资源、同操作、同规范内容只返回原回执；同键不同意图为 `COMMAND_CONFLICT`。不把帖子命令的摘要域直接套到评论。

受理回执和任务当前状态分开：回执 `ACCEPTED` 是原尝试受理事实，不能被客户端当成最新任务状态。任务只有 `ACCEPTED/PUBLISHED/FAILED/ABANDONED` 四种服务端状态。本地 `SENDING/UNKNOWN` 不得写成服务端 FAILED。

连接中断、超时、401、503、App 退出均不能证明未受理。按原 commandId 查询；`UNKNOWN_NOT_OBSERVED` 仍是未知，禁止换新任务发送、改身份、改目标或放弃。查询到受理回执后读取同一 taskId 的最新状态。重复查询和安全的原意图精确回放仍使用原键；客户端核心不自动重发未知请求。未知命令的显式封口使用原 operation/digest、相同账号键锁，在与迟到请求串行的事务内记永久 `NOT_ACCEPTED`，丢响应继续核对该键；不能仅因一次查询为空就解锁新提交。

RETRY/ABANDON 也必须先写 journal（新 commandId、expectedAttemptVersion、原绑定、原内容/新内容），丢响应后核对该命令及任务，不能把本地旧 FAILED 当成当前权威状态。App 重开只恢复已提交 journal 并核对；无法确认账号/环境归属时不自动请求或发送。切账号推进代次，每个 await 后检查代次，拒绝迟到回写。身份删除立即清本人侧失败材料/通知入口并停止发送；已受理未知任务在服务端最终事务按原归属终止，不换其他身份。

明确未受理必须独立于未知和任务 FAILED：适配器仅在核对原命令键的权威 `REJECTED/NOT_ACCEPTED` 回执后报告拒绝。CREATE 拒绝不伪造服务端任务；保留已提交意图，显式恢复到当前同帖临时编辑器前先成功删除该 journal 项，再由用户重新发送。RETRY/ABANDON 拒绝后读取原任务的当前权威状态，再决定允许动作；旧的本地 FAILED 不能自行解锁。401/503/超时仍属于未知，不能当成确定未受理。

### 独立命令字节帧 v1

帧为 `UTF8("HNUHOLE/COMMENT-COMMAND/V1") || 0x00 || uint8(operation) || fields`，SHA-256 小写 hex 为 requestDigest。命令键不进入 payload 帧，回执存储仍必须按账号和独立评论命名空间隔离。服务端存储用途隔离 HMAC 及永久密钥承诺、命令串行锁、封口执行均属于 SQL 接线阶段；纯 codec 不提供这些保证。

| operation | fields（按顺序） |
| --- | --- |
| 1 CREATE | task UUID、post UUID、identity UUID、root UUID/零、target UUID/零、body、image |
| 2 RETRY | task UUID、uint64BE expectedAttemptVersion、body、image |
| 3 ABANDON | task UUID、uint64BE expectedAttemptVersion |
| 4 DELETE | comment UUID |
| 5 SET_LIKE | comment UUID、uint8 liked（0 或 1） |

UUID 使用原始 16 字节，必填 UUID 非零且输入为规范小写；root/target 仅可同时为空，空值编码各 16 个零字节。body 使用 `uint32BE(UTF8字节长度) || 原始UTF8字节`，不 trim、不 NFC、不更换换行；拒绝无效 Unicode scalar 和超过帧预算的输入。版本范围为 1..2147483647。RETRY 不接收新身份、帖子或目标。

image 先放 uint8 presence（0 或 1）。有图时放 `media UUID16 || text(sha256小写hex64) || text(mimeType) || uint32BE(byteLength) || uint32BE(width) || uint32BE(height)`，text 同 body 的字节长度帧。无图也必须保留 presence=0；评论帧不复用帖子摘要域。单图清单复用现有结构预算，实际原字节验证另行执行。framing 与业务校验分开，以便对结构合法但内容不满足发布规则的请求记录稳定拒绝回执。

## 列表、排序和定位

一次阅读快照固定评论 ID 顺序：主评论取前十条按赞降序、发布时间升序，再以规范 UUID 字节升序稳定兜底；其余按时间、ID 升序且不重复。每楼前五同规则，其余由用户手动展开后按时间、ID 加载，每页默认 50（末页返回全部剩余），普通滚动不自动展开隐藏回复。

分页令牌必须绑定当前账号、帖子、楼、快照与位置，用服务端不透明且完整性保护的游标，不能把 offset 当作重新执行实时排名的依据。读取后点赞只改数字，不移动已显示条目；收起整评论区重开或重新进帖才生成新快照。他人新评论不插入或提示。本人真实成功内容纳入当前快照后展开所在楼并滚到评论区顶部、高亮，上方正文位置保持；不能把当前列表整体重排。

定位使用具体 commentId，必要时服务端返回其楼和包含位置，客户端展开并高亮；目标不可访问时统一 `COMMENT_NOT_FOUND`，顶部短提示“评论已经删除”，不返回原文、不阻塞、不限制重复提示。缓存遇到明确删除/权限失败立即移除；重新展开加载失败保留仍允许展示的旧内容及位置，首次失败不能显示成空列表。

本人删除主评论无确认，原子删除整楼及图片/互动计数；删除回复只删除该条，保留其他回复的具体目标关系及目标作者展示文字，不保留原文占位。禁言允许本人删除。删帖关闭整个讨论；注销/删身份/处罚/图片迟到提交和删除必须通过同一最终 C 授权与资源锁顺序串行。

## 一张原图

`image` 是 null 或一项既有 `postmedia.Selection`，不接收数组；文字和图片至少一种。复用 JPEG/PNG/GIF/WebP 原格式验证、10 MiB/像素/动画预算及原图组件，不复用帖子九图归属表。正文当前以现有帖子 3000 字素作为技术预算；这不是新增已确认产品上限，最终接线需保留该项标注。

选图/读取/上传失败只标记该图并保留文字与实际目标，可移除或重选；已接受任务只在明确 FAILED 后改内容重试。图片尝试绑定 task/version/media，短期上传能力只允许该尝试原字节，最终写入再次检查 Gate/账号/身份/目标/终态。只在完整验证后与评论公开原子提交。

公开读取每次要求当前 C 会话和最终 Gate，媒体归属 commentId，租约最长 60 秒且不超过会话期限。禁止公开 URL、跨评论切图或长期私有字节缓存。删帖/删评论/关闭账号/切账号/权限失败立即撤销并逐 provider 清理，原格式保存沿现有查看器策略。具体媒体端点接线在 0016 阶段补齐，不以模型中的 Selection 校验代替真实解码/上传/读取。

## 给统一系统通知的私有适配

本任务提供 `taskId`、`ownerIdentityId`、目标引用（post/root/target）、当前状态、尝试版本、failureCode、允许动作和材料可用性。通知侧只在原发送身份展示 FAILED，详情通过任务拥有者接口取保留内容；账号级通知不能混入其他面具任务。

| 权威事实 | 通知入口 | 允许动作 |
| --- | --- | --- |
| ACCEPTED 或本地 UNKNOWN | 不作为明确失败 | 核对原任务/命令 |
| FAILED 且身份/目标/权限允许 | 原身份“发送失败” | RETRY、ABANDON |
| FAILED 但目标失效或权限受限 | 保留失败详情，解释原因 | ABANDON；恢复权限后重新校验 |
| PUBLISHED | 移除失败通知 | 正常公开内容定位 |
| ABANDONED | 移除失败通知，清本人保留材料 | 无恢复入口 |
| 原身份删除 | 清本人失败记录/入口；系统依法留存另管 | 不允许重试或换身份 |

阅读/标已读不解决任务，失败项删除表示放弃任务，不是删公开评论。重试进行中不得再提供并发重试/放弃。任务最终成功或放弃后幂等移除通知；失败状态/动作由任务实时权限判定，通知不能自行推导成功或复活任务。

任务2拥有消息系统通知列表/详情/已读/路由；本任务不新增第二套通知中心。最终远端核对发现任务2已提交[通知契约 60e5df4](https://github.com/zewbby/HnuHole/blob/60e5df46545180c1c7017b6aee3b417af471ccbe/docs/design/report-notification-contract.md)，已完整读取并对齐下列映射；尚无已合入的 0015 或真实通知 provider 接线。没有合并整条治理分支或复制其未提交代码。

| 本任务的私有事实 | 对接任务2的通知包装 |
| --- | --- |
| `ownerIdentityId` | `identityId`，固定 `scope=IDENTITY`；不能混入账号级或其他身份列表 |
| `taskId` | `route={name:COMMENT_FAILURE,resourceId:taskId}`，白名单资源路由，不传任意 URL |
| 本机 journal 的明确失败投影 | `source=LOCAL_TASK`；这是通知来源，不是伪造服务端是否受理的证据 |
| 权威 FAILED、原目标与动作权限 | 详情与 RETRY/ABANDON 调用评论任务 provider，通知不复制正文或发送状态机 |
| PUBLISHED／ABANDONED／已删除原身份 | 按实际结果撤去本人失败入口；未知仅保留核对元数据，不投递失败 |
| 阅读／标已读 | 不修改任务、不放弃内容；由实际 provider／通知持久适配记录单条 read |

当前投影尚不包含完整通知包装的 `id/eventId/kind/state/title/body/createdAt/readAt/route`，不冒充完整 provider。接线时按 `(taskId,attemptVersion)` 识别失败事件并建立稳定事件／接收记录映射，精确 ID 格式和 LOCAL_TASK/SERVER 同一事件去重须与任务2实际实现核对；不能每次列表重新生成 ID 或时间。`body` 只放通知摘要，原评论文字和图片仍从评论拥有者详情取，不存第二份。失败时间和本机单条 read 需持久适配，不借标已读清任务；通知 `kind/state` 的精确枚举仍待任务2实际规范固定，不能直接把全部任务状态作为通知状态。

当前核心 `failures` 只投递权威 FAILED；CREATE 的 `REJECTED/NOT_ACCEPTED` 没有服务端任务，继续使用本地已提交意图及同帖显式恢复流程，不伪造 FAILED 来补通知入口。后续本机未受理失败详情路由需以真实 provider 接线单独覆盖。治理证据的 2 MiB／每批 8 MiB 预算不覆盖评论单图既有 10 MiB。上述包装／已读／路由及实际顶部失败入口均为未实现项，`COMMENT-FAIL-ENTRY-01` 与完整 B07 继续未验。

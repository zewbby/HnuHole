## 已核实的基线事实

- `services/api/internal/authprivacy/community_comments_read.go`：固定五分钟到期；每账号最多 128 份快照；超过 10,000 个 ID 拒绝整个列表；删除或隐藏项跳过，游标按原名单扫描位置推进。
- `apps/mobile/lib/src/comments/comment_views.dart`：本人发布任务进入 `published` 后触发定位；现有逻辑允许补入本人的新发表内容，但可能先遍历旧游标寻找目标，插入也不保证列表首位。文档“旧名单不插入新评论”需要明确本人发送的展示例外。
- `GLOSSARY.md` 已区分账号与公开身份；额度归属社区账号，不随公开身份切换。
- 主评论页读取后，客户端逐条读取有回复的主评论的回复预览；每份预览会创建回复快照。在每页 50 条均有回复的场景，主评论快照 1 份加前三页回复快照 150 份，合计可达 151 份，超过原账号额度。
- `ce140d57` 的 `services/api/go.mod`、`infra/docker-compose.yml` 和配置模板没有 Redis 接入，也没有可供本需求直接采用的 Redis 内存预算或固定 P95 压测数据集。原网络限流为实例内 map，公共 Redis 接入属于未来交付依赖。

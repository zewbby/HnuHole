本期将评论分页使用的临时有序 ID 名单从 PostgreSQL 迁到 Redis，并改善连续阅读和本人发表后的展示体验。正文、图片、点赞、身份资料和权限仍以现有业务存储与授权流程为准。

本版合并原 V1.0 及本次 12 项讨论问题的确认结果。需求审查基线为 `ce140d57`；实施前核对最新目标分支及评论区并行交付，不回退已经完成的提交即显示、回复按需预览和排序功能。本文用于后续实施与验收，当前尚未开始实现。

## 目标与范围

迁移主评论及楼中楼回复分页快照的创建、读取、归属验证、过期回收和账号配额统计。完成跨 API 实例读取、客户端恢复、容量保护、观测、发布切换及回退。

本期不迁移评论正文、图片、点赞或账号权限；不更改正常排序算法，不合并评论 SQL 批量优化，不建设全站缓存、热榜或 Redis Cluster，也不增加超过 10,000 条的分段快照方案。

普通分页每页保持 1–50 条；回复预览保持 5 条及现有展开协议。

## 分页名单和临时置顶

首次读取先完成登录及可见性校验，按所选正常排序规则生成有序名单。Redis 保存成功、本次授权及数据库事务成功后，才能返回有效快照与游标。保存失败不能返回伪装成功的游标。

后续翻页保持原名单的成员和顺序，读取数据库中的当前内容、点赞状态和公开身份资料。新增评论和点赞变化不修改已有名单；主动刷新取得新名单。客户端不能在原游标下重新排序、用新名单套用旧偏移，或将两份名单直接拼接。

本人新发表内容采用当前页面的临时置顶展示，不改写原分页名单：

- 主评论在当前主评论列表第一位，连续发表时最新一条在前，并滚动到该条。
- 回复在所属根评论的回复列表第一位，自动展开并滚动到新回复；根评论在主列表的位置保持不变。
- 继续翻页按评论 ID 去重，本人新内容不能出现两次。临时置顶只影响本人的当前页面，主动刷新或重新进入帖子后恢复正常排序。
- 保留评论区并行分支已经实现的提交即显示行为；待确认内容不冒充服务端已发表事实。确认发表成功后，以服务端内容衔接并去重；明确失败和结果未知继续按原发布任务协议处理，保留内容与处理入口。
- 已删除、隐藏或无权读取的本人评论同样受可见性约束，临时置顶不能绕过授权。账号或会话变化时沿用现有展示隔离规则。

## 有效期和资源边界

主评论及楼中楼快照统一在创建后 30 分钟到期。创建时记录可信到期时间并设置 Redis TTL，读取时再次校验；翻页不续期。快照和账号配额索引均须自动回收，不保留永久临时键。

每份快照最多保存 10,000 个评论 ID，另设单份序列化字节上限。超过上限拒绝创建并提示“当前评论列表规模超限”，不混用操作太频繁的错误。主评论超限只影响主评论读取；某层回复超限只影响该层，帖子正文和其他楼层照常显示。

每账号有效快照额度改为可配置值，归属社区账号，切换公开身份不能重置。模块容量充足时，同一账号连续阅读至少 10 页、每页 50 条且每条均带回复的主评论，不得因账号快照额度被拦。回复预览保持按需读取，不要求一次预建全部楼层快照。

跨实例并发创建不能突破配置额度；创建、配额占用和清理必须保持一致。失败或重试不能长期重复占额，过期索引不能无限增长。不得通过删除其他仍有效的快照绕过额度。

快照模块必须有独立总预算，不挤占限流预留空间。预算满时拒绝新建，不自动退回 PostgreSQL 大量创建快照。交付时提交默认账号额度、单份字节上限、模块预算、限流预留和实际容量测试；这些数值由实施测量确定。

## 可见性和删除后的翻页

每页重新检查帖子、根评论及目标评论的当前可见性与权限。不可见项跳过，允许返回少于请求条数；游标按实际扫描的原名单位置推进，不能因跳过项目而重复返回内容。

如果一个分页段全部不可见，则沿原名单继续查找下一个分页段，一次加载最多扫描三个分页段。找到可见内容后允许返回短页，返回条数不超过原请求上限；回复预览也保持最多 5 条。仍为空且还有后续内容时停止加载，保留“继续加载”入口；扫描到末尾才显示没有更多。

## 失效和故障恢复

| 情况 | 接口与页面行为 |
| --- | --- |
| 已过期、明确不存在或游标不合法 | 沿用 HTTP 400 / `CURSOR_INVALID`。停止追加并提示刷新，保留当前页面和未发送输入；用户刷新成功后使用新名单首页替换，不能套用旧偏移或拼接两份名单。 |
| 单层回复快照失效 | 只刷新该层回复，保留主评论、其他楼层和未发送输入。主评论快照失效时才刷新整个主评论列表。 |
| Redis 超时、断连或写入失败 | 返回 HTTP 503 和可区分的稳定错误码，不误报为游标失效。超时或断连先做一次短重试，仍失败就停止等待，在失败加载处显示手动重试入口；保留已显示内容和阅读位置，不自动刷新列表。 |
| 账号快照额度超限 | 沿用 HTTP 429 / `RATE_LIMITED`，返回合理等待时间，保留已显示内容及输入，不删除其他有效快照。 |
| 单份过大 | 使用独立容量错误，提示当前列表规模超限，不无限重试；错误只影响对应列表。 |
| 模块预算满或容量拒写 | 使用可区分的容量错误，提示稍后重试，不进行循环自动重试或自动存储切换。 |
| 帖子、根评论不可见或账号失去权限 | 沿用现有不可见或无权限行为，不因快照存在而放行，也不泄露隐藏内容。 |

一次短重试是同一次加载的统一预算，不能在客户端和服务端各自叠加成多层重试。新建快照重试也要保持配额一致性。明确失效、权限拒绝、额度超限和明确容量不足不套用临时故障的自动重试。

## 安全和最小化保存

快照绑定社区账号、帖子、根评论及快照类型，保留现有签名游标和偏移检查。跨账号、帖子或楼层串用，以及篡改和越界游标统一拒绝，不泄露快照归属。兼容所支持的排序模式，不能把原名单解释为另一种排序结果。

Redis 只保存归属校验标识、有序评论 ID、到期时间及必要版本信息。不保存学校邮箱、登录令牌、评论正文、“我是否点赞”或额外身份关联。

## 公共接入和并行交付

“共享限流和动作级防刷”任务统一负责公共 Redis 依赖、连接、配置、Compose、密钥配置及初始化装配。本任务负责评论快照存储、配额、资源预算、客户端行为和对应验收；公共基础接入完成后进行集成验收。

快照使用独立命名空间，例如 `{环境}:comment:snapshot:v1:`，两模块分别设置调用超时与资源预算。不得修改限流规则、清理限流键或执行 `FLUSHDB` / `FLUSHALL`。

共用实例必须沿用公共内存与淘汰策略并为限流预留资源，不能擅自启用会淘汰限流状态的策略。无法满足资源隔离要求时，再通过公共接入方案拆实例，不能把 key 前缀当作完整资源隔离。

## 发布和回退

先全量部署兼容读取 PostgreSQL 和 Redis 快照的版本，再统一开启 Redis 新建。最后一个 PostgreSQL 快照写入实例停止后，至少保留 30 分钟旧快照读取，并确认过渡快照已到期，再停止正常访问旧快照表。旧快照按自身到期时间校验，不为迁移擅自续期。

本期保留旧表与 PostgreSQL 存储实现供明确发布开关回退，无需双写每一份快照。回退后无法承接的游标明确要求刷新，不能重新生成名单套用原偏移。本期不做故障时的运行时静默存储切换。

## 验收和交付

| 项目 | 通过条件 |
| --- | --- |
| 分页稳定 | 点赞和新增评论不修改旧名单；刷新取得新名单；正常顺序不重不漏。本人评论和回复临时置顶、滚动定位、后续翻页去重及刷新恢复正常排序通过。 |
| 删除与隐藏 | 不可见项不返回，游标正确推进；全隐藏分页段最多扫描三段，空短页不误报到底，也不无限加载。 |
| 有效期 | 30 分钟后失效，翻页不续期；回复预览、展开、空列表、末页和大小边界符合协议。 |
| 客户端恢复 | 主评论与单层回复按各自范围刷新；保留输入和未受影响内容；超时断连仅一次短重试，手动重试不重置列表；新旧名单不拼接。 |
| 授权与隔离 | 跨账号、帖子、楼层、伪造及越界游标被拒绝；权限撤销、帖子或根评论隐藏后，旧快照不能放行。 |
| 跨实例和账号额度 | 两个 API 实例读取同一快照；并发创建不超配置额度；失败不长期占额；模块容量充足时，单账号完成 10 页各 50 条且每条均带回复的阅读场景，不因账号额度被拦。 |
| 容量与共享限流 | 单份 ID 和字节上限、模块总预算及限流预留均有效；压力不清除、重置或挤占限流状态；超限错误可区分。 |
| 故障和发布 | 断连、超时、状态丢失及容量拒写提示正确；至少 30 分钟兼容读取及明确开关回退通过；无静默重建、自动存储切换或重试风暴。 |
| 存储迁出 | 正常切换过渡结束后，快照读写、账号配额统计和过期清理不再访问旧快照表。 |
| 性能 | 同一数据集、同一并发及可比较条件下，评论接口 P95 相对对照回退不超过 5%；单独报告快照创建和读取耗时，不预设整个接口必须提升的百分比。 |

性能与容量交付记录必须写明被测版本、部署及资源配置、数据规模、并发量、操作序列、预热与采样方法、耗时结果及错误率，包含首次读取、主评论翻页、回复预览与展开等相关路径。不以少量成功请求或功能回归测试代替容量与 P95 验收。

交付包含实际配置参数、接口错误约定、相关测试、前后对照、发布步骤和回退说明。工程参数在实现时测量并提交，不作为继续扩大产品需求讨论的理由。

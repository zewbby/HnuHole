# 独立快照实例和保守预留

现有限流候选仅有单主体大小和全实例 maxmemory，没有可证明的双模块总字节分配。评论快照默认使用独立社区 Redis 进程，继续复用公共接入与部署负责人，以避免快照压力挤占限流；只有公共方案补齐硬预算和验证证据后，才可显式共享实例。

快照用有界模块名录预留账号额度与字节，再写不可变名单；SQL 明确提交后才确认发布。写入未知保留预留，补偿先删数据再核销。选择单名录保守提交，放弃依赖多个计数器写入失败自动回滚的方案；代价是新建名录重写需要受限并通过真实性能门槛，普通翻页不扫描名录。persistent control 是固定大小的配置与高水位，不是永久临时名单索引。

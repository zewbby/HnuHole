# 私信第三阶段：治理、通知与正式装配

任务 DM-P3-GOVERNANCE，分支 `feat/direct-message-governance`，2026-10-23。依赖 P2 PR #51，未合并、未发布。

## 业务边界

- 拉黑按账号关系阻止双方通过任意面具建立或继续发送；已经受理的投递继续完成，ACK 不代表已读。
- 黑名单只列用户明确选中的身份对。统一操作回执不披露不同面具是否属于同一账号。解除只移除对应选择；其他明确选择仍生效时统一显示联系不可用。
- 举报独立于拉黑。先选择原因，再确认连续区间及固定快照；用户必须明确授权提交。快照不随后续撤回或本机删除静默改变。
- 普通聊天历史仍仅存本机。服务端保留受理元数据及新文字的 HMAC 校验摘要，不因举报功能恢复已 ACK 的普通正文档案。私信证据使用现有受限治理存储和管理员权限。

## 证据与重试

区间最多 200 个连续序号。缺失项必须显式标注；不知道类型的缺口为 UNKNOWN，由服务端校对归属及元数据。旧文字缺少真实性摘要时不可冒充已验证证据；全部不可验证的区间不予提交。服务端核验消息 ID、序号、会话、文字摘要或图片摘要，并标注真实撤回状态。管理端使用结构化方向、序号和内容字段，正文不能伪造发言方。

聊天图片快照最多 24 MiB；已有图片超过预算时要求缩短区间，不将其伪装为缺失。说明和补充图沿用既有 200 字、6 图及图片校验规则；所有解码材料合计不超过 32 MiB，HTTP JSON 上限 48 MiB。待办材料加密存储容量提高到 50 MiB，以容纳编码后的固定快照。

提交保留原 UUID 和原材料。未知结果先查询原任务；查询未提交会封住旧请求，重试必须使用服务端返回的 retryToken，避免放弃后迟到请求重新生效。举报回执、系统通知、禁言／封禁及申诉沿用现有治理流程，私信不提供帖子下架动作。

## 生命周期与通知

权威身份目录删除会清理对应本地会话、消息、草稿、备注和无引用图片；普通退出保留账号本地资料，正式注销封闭存储入口并清理，迟到任务不得复活数据。证据选择及预览在授权失效时立即隐藏，图像解码缓存随预览释放。

Android 本地通知仅对已经可靠落地的新消息触发，免打扰和已删除会话不提醒。默认只显示“你有一条新私信”；用户主动开启后才显示公开发件昵称和预览，不使用私人备注。通知失败不回滚落地或 ACK。点击只携带应用私有随机 nonce，登录后重新校验环境、账号、身份和会话，不因点击直接标记已读。首次绑定及账号切换清除旧通知，含未登录冷启。原生权限由设置页面明确申请。

正式 Flutter 入口接入 DmRuntime；服务端 `directMessages` 仍默认关闭，显式启用需要迁移 0024、治理及私有媒体校验配置。没有部署或打开生产开关。

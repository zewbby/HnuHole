# 恢复码与七天注销：隔离实现和验证

日期：2026-09-30。分支：`codex/auth-privacy-handoff`。基线：`19924b002a5ed789e6078f1d1b0c4b72b356b765`。本轮继续 C 隔离服务端实现，沿用已收口的恢复、数据／API、数据库和 Authorization Safety Gate 契约；未接生产路由或 Goose 迁移。

## 交付范围

| 边界 | 实现 |
| --- | --- |
| 恢复码证明 | 当前恢复码在 C 内定位旧号，忘记用户名也可恢复。初验所见凭据版本和旧码摘要须在账号锁内重新核对；创建唯一十分钟意图，原子废弃前一意图并推进重设代次。首次响应才展示新恢复码及已证明的私有用户名；旧码在最终重设前保留。 |
| 最终密码重设 | 新密码由原有有界 Argon2id／NFC／弱密码策略在锁外准备；最终事务复核原凭据版本、活动意图 ID／代次、授权代次、新码确认和最终可信时间。更换密码与恢复码、删除全部已存备用凭据、撤销旧会话、递增凭据／会话代次、消费意图及最小受限安全事件原子提交。重设不自动登录、不解除处罚、不取消注销。 |
| 无秘密结果核对 | 原键同请求提交及重试均 `204`，不重发恢复码或令牌。`ResetResult`＋`Reset-Intent-ID` 只核对 `PENDING/COMMITTED/NOT_COMMITTED`；早到或结果过期不能当作未提交证明。结果保留至少七天，随后原位收缩为永久、无身份的 `EXPIRED` 锚点。 |
| 注销申请与取消 | 当前有效 Bearer 加新鲜密码复验，在同事务进入 `PENDING_CLOSE`、撤全部会话、推进会话／申请代次并持久建立最终可信时间＋七天的截止。只有截止前成功主动登录取消；恢复、状态读取和续期均不取消。旧 Bearer 不因同申请重试重新获得权限。 |
| 到期关闭 | 最终账号锁内时间达到截止后立即失去登录／恢复权限；后台尚未关闭时状态为 `FINALIZING`。有界 worker 原子关闭账号、清用户名／密码／恢复途径及活动指针、撤会话、终止旧号限制、把槽位置 `CLOSED` 并清账号连接、写唯一 `RELEASED` outbox。 |
| 受限状态与释放 | `ClosureStatus` 只读本次申请的最小状态，只有 `PENDING/FINALIZING` 返回截止；终态不返回账号、用户名或处罚。释放收据仅从已提交终态签发，经现有 mTLS 对端持久 ACK；重复 ACK 不改留存起点。ACK 后投递材料已清时可只读重签，不复活 outbox。 |
| 封禁联动 | 受信内部 `ApplyAccountBan` 在账号、限制、申请及会话锁下核对限制版本；生效时立即撤销会话，解除或到期不会复活旧 Bearer。新封禁只在注销截止前取消申请，迟到封禁不能撤销已经到期的关闭。未新增公开审核接口。 |
| 留存 | 废弃／消费／过期立即清新恢复摘要；最小结果和意图元数据有界保留，受限恢复事件七天清理。取消状态三十天清理；释放状态从首次 C 持久 ACK 起三十天清理。未释放状态继续保留，但其请求 HMAC 独立在八天窗口后收缩；状态删除后永久 closureId 域摘要拒绝重建原七天申请。 |

所有新增授权、状态读取、重试与本轮清理经 Gate。锁外计算保留原证明版本与授权代次；账号、限制、申请／意图、凭据、会话和结果按固定顺序串行化。没有把邮箱、恢复事件或用户名发送给 V。

新增实验迁移 `0004_recovery_reset.sql`、`0005_account_closure.sql`；恢复码三条公共端点、注销两条公共端点均按现有 C OpenAPI 实现。已有注册与登录／会话端点保持兼容，并补上注销截止前主动登录取消。

## 验证证据

最终验证命令、运行环境、实际执行案例和文件摘要记录在 [`recovery-closure-verification.json`](../../services/api/authlab/recovery-closure-verification.json)。真实 SQL／HTTPS 证据来自 `sh authlab/run-isolated.sh` 创建的私有临时集群和两个非超级用户数据库；脚本执行全模块 race 与 vet。单独不带数据库 DSN 的 Go 命令不能代替 SQL 验证。

最终代码下，`sh authlab/run-isolated.sh`、单独的 `go test -race -count=1 -p 1 ./...` 与 `go vet ./...` 均退出 0。运行环境为 Go 1.27.1 darwin/arm64、PostgreSQL 18.6；新增 27 个数据库测试、9 个 HTTP 契约测试，现有真实 HTTPS／PostgreSQL 测试扩展到完整恢复和注销释放链路。实验通过不代表生产或独立安全验收通过。

测试覆盖旧码／旧会话失效、替代意图、同键与异负载重试、结果核对和永久墓碑、并发重设、锁内版本复核、密码计算途中冻结、授权恢复后的旧意图拒绝、注销截止与登录取消、恢复不取消注销、封禁即时撤销、到期关闭的释放链路及留存。真实锁等待与事务故障还验证：密码／登录不能跨截止或冻结提交；跨账号交叉申请 ID 不锁住彼此申请；恢复摘要冲突和最终关闭 outbox 失败完整回滚；V 已释放但 C ACK 被冻结或最后状态写入失败时，C 三项 ACK 事实一起不提交，原收据可恢复后重试。端到端测试从真实校邮资格与开户继续完成恢复、主动登录、申请注销、登录取消、再次申请、可信时间跨截止、正式关闭、签名和 mTLS 配额释放。

## 后续边界

本轮完成恢复码闭环，尚未实现可选 WebAuthn Passkey 的绑定、恢复和管理，也未实现已登录用户的新鲜密码复验换码。实验 `passkeys` 表只为全量撤销验证提供最小存储，不能作为 WebAuthn 验证实现或生产迁移。受限安全事件已入库，设备通知投递和移动端恢复／注销待办仍待接入。

公开内容注销占位、未公开任务停止、本机聊天／搜索等数据清理尚无对应业务实现；账号终态只是这些后续投影的权威依据。本轮处罚命令只实现隔离授权联动，审核后台、处罚接口与权限配置仍待接入。

下一切片应补齐恢复凭据管理：恢复码轮换与可选 Passkey，然后完成移动端安全存储／持久结果核对／登出待办，并接入生产路由、通道授权及正式迁移。共享限流、密码名单／KDF 容量校准、独立授时与库外锚点、可信灾备、备份留存、真实 V/C 分权和独立人类审计仍是生产验收门槛。
